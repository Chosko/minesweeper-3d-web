# Task 7 — Fidelity tests for the reference ruleset

Target: claude+human

## Goal
Pin the reference ruleset of feature `cell-graph-rules-engine` by fidelity
tests: each rule Minesweeper Online could plausibly play two ways is observed
once on the live site with its default options, the observation is recorded
beside the test, and a Node test asserts the engine reproduces it. This
closes the feature document's open question on the observations.

## Acceptance criteria
- `tests/fidelity/minesweeper-online.md` records one dated observation per
  rule: what the first click guarantees (a safe cell, or always an opening);
  whether a left click on a revealed, satisfied number chords, and which
  inputs chord at all; what a chord does when its flags are wrong; what the
  board shows on a loss (unflagged mines, wrong flags, the exploded mine);
  what counts as a click for efficiency and whether wasted clicks count;
  whether a revealed cell can be flagged.
- `tests/engine-fidelity.test.mjs` has one test per observation, citing it,
  asserting the reference profile reproduces it (the first-click guarantee
  through the engine's rejection of a board that breaks it).
- Any rule the engine plays differently from its observation is corrected in
  rules version 1 (task 5's decision), and the full suite passes.
- `.claude/domain/features/cell-graph-rules-engine.md` records the
  observations as settled in place of its open question, citing the
  observation file. Nothing else in the document changes.

## Decisions
- One observation file serves every later fidelity test (board generation's
  first-click guarantee, Classic 2D's input and board-size rules), so the
  observations are made once. Settled here: the feature document's open
  question on the fidelity observations.
  `.claude/domain/features/cell-graph-rules-engine.md` is normally
  `/architect`'s; this task updates it for exactly this and for nothing else.

## Manual interventions

⚠ REQUIRES MANUAL INTERVENTION — pause implementation at these points and
walk the user through them on the live Minesweeper Online site; wait for
their confirmation and verify the outcome before continuing:

1. Before any fidelity test is written: the user opens Minesweeper Online
   with its default options and, for each of the six rules listed in the
   acceptance criteria, performs the described play and reports what the
   site did. Claude writes each report, dated, into
   `tests/fidelity/minesweeper-online.md`. Verify the file holds one entry
   per rule, each stating a single observed behaviour.
2. After the tests run: if any test fails because the engine differs from
   an observation, show the user the rule and the observed behaviour before
   correcting the engine. Verify the corrected engine passes the full suite.
