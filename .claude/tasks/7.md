# Task 7 — Fidelity tests for the reference ruleset

Target: claude

## Goal
Pin the reference ruleset of feature `cell-graph-rules-engine` by fidelity
tests: each rule Minesweeper Online could plausibly play two ways is read
from its dated entry in `tests/fidelity/minesweeper-online.md`, the
committed record of the site's behaviour with its default options, and a
Node test asserts the engine reproduces it.

## Acceptance criteria
- `tests/engine-fidelity.test.mjs` has one test per engine rule the file
  records, each citing its entry by heading: the first-click guarantee (safe,
  not always an opening — asserted through the engine's rejection of a
  supplied board that puts a mine on the first-click cell, and its
  acceptance of one that puts mines beside it); which inputs chord, as far
  as the engine's actions reach; a chord with a matching flag count and a
  wrong flag (the mine opens and the game is lost); a chord with a differing
  flag count (nothing opens, a wasted chord is counted); the board after a
  loss (exploded mine, unflagged mines revealed, wrong flags crossed out,
  correct flags kept flagged, every other closed cell closed); what counts
  as a click for efficiency, wasted clicks included; and that a revealed
  cell cannot be flagged.
- The tests use `tests/fidelity/minesweeper-online.md` as it stands and add
  nothing to it, unless a test finds a contradiction in it.
- A rule the engine plays differently from the file is corrected in the
  engine against the file, in rules version 1 (task 5's decision), and the
  full suite passes.

## Decisions
- One observation file serves every fidelity test (board generation's
  first-click guarantee, Classic 2D's input and board-size rules); its
  entries were settled from the site's client code, help pages and live
  play, so no step of this task needs a person. The file is the oracle: a
  fidelity-test failure is resolved by correcting the engine, never by
  re-observing the site.
