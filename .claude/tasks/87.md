# Task 87 — Windows packaging and the SteamPipe private build

Target: claude+human

## Goal
Ship feature `steam-desktop-host`'s build path: a packaging step producing an
unpacked Windows x64 build — Electron, the game files, and slots for the
binding's native module and the Steam API library — and a SteamPipe build
script that uploads it to the app's Windows depot and sets it live on a
private branch, so the game installs and runs from Steam.

## Acceptance criteria
- One command in `desktop/` produces an unpacked Windows x64 build that
  contains the game files and starts to the main menu.
- The SteamPipe app and depot build scripts upload that directory to the
  Windows depot and set it live on a private branch; app and depot ids come
  from a config file, never hard-coded in scripts; credentials are never
  written to the repository.
- A `steam_appid.txt` is used only for development runs and is excluded
  from the packaged build.
- The build installs from Steam on the private branch and plays offline.

## Manual interventions

⚠ REQUIRES MANUAL INTERVENTION — pause implementation at these points and
walk the user through them in the Steamworks partner site, the Steam client
and a Windows machine; wait for their confirmation and verify the outcome
before continuing:

1. Before the SteamPipe scripts are filled in: the user gives the app id,
   the Windows depot id and the private branch name from the Steamworks
   partner site (creating the branch if needed). Verify the ids are in the
   config file.
2. After the packaging command works: the user runs the SteamPipe upload
   with their builder account (Steam Guard prompt included) and sets the
   build live on the private branch. Verify the upload log reports success
   and the build id.
3. After the upload: the user installs the private branch from the Steam
   client on Windows, launches it, and plays a game with the network off.
   Verify from their report and the crash log that the game reached the
   main menu and played.
