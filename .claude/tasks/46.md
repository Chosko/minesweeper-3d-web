# Task 46 — Results flow and results view

Target: claude

## Goal
Build feature `results-screen`: on the game shell's game-finished hand-off,
record the summary with personal records, then fill and show the results
screen — outcome, board label, time, 3BV (and 3BV solved on a loss), 3BV/s,
efficiency, the three best comparisons on a win — with *Play again*,
*Records* and *Back to menu*.

## Acceptance criteria
- The results flow attaches to the shell's game-finished hook, calls
  `record(summary)` before the screen shows, and routes to the results
  screen with the summary and comparison.
- The view fills the kit's results composition: outcome header, board
  label, time to the hundredth of a second, 3BV (3BV solved on a loss),
  3BV/s to two decimals, efficiency as a whole percentage; a stat that is
  not available shows a dash.
- On a win, each of the three bests shows the standing best and the
  difference, and marks a new best.
- *Play again* has default focus and asks the shell to start the same board
  choice; *Records* routes to the records route with this game's board key;
  *Back to menu* returns to the main menu.
- When recording fails the screen still shows the game's own stats without a
  comparison and says the result could not be saved; when records are not
  being saved this session the player is told once.
- In Classic 2D the finished board stays visible behind the screen.
- Mouse, keyboard and controller operate every action.
- Node tests cover formatting and the flow with fakes; a Playwright check
  wins a fixed Beginner board and checks the screen, then *Play again*.
