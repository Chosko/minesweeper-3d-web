# Task 84 — Electron main process: window, game protocol, window state and crash log

Target: claude

## Goal
Start feature `steam-desktop-host`: the Electron main process that creates
the one game window and loads the same game files the web preview serves,
over a custom application protocol so ES modules and the generation worker
load as they do on the web. The window is the desktop window the feature
document describes: frameless and transparent, drawn entirely by the game
in its title bar's style, windowed by default, dragged by its title bar,
sized by its content and never by the player, with Fullscreen / Windowed
and Minimise. The main process holds the single-instance lock, remembers the
window's position and fullscreen state, writes uncaught errors from both
processes to a local crash log, and runs the closing sequence every quit
path will share. Exact looks come from the canvas
https://claude.ai/artifact/LeP32jxNxEnHLUtRwJ3FNC — J-Components *Window
title bar* and J-C2D-xl.

## Acceptance criteria
- `desktop/` holds the host: its own `package.json` (Electron as a dev
  dependency, a `start` script) and the main-process modules; the web build
  at the repo root stays dependency-free and unchanged.
- The window loads `index.html` from a custom protocol scoped to the packaged
  game files; ES modules and the generation worker load; a request outside
  the game files is refused.
- The page runs with context isolation on, Node integration off and the
  sandbox on.
- A second launch focuses the running window and exits.
- The window has no system title bar or frame and is transparent, so the
  page's rounded window shows on the desktop; it moves by the drag region
  the page marks on its title bar; the player cannot resize it.
- The main process exposes the window actions the bridge calls (task 85):
  set the content size — the window resizes to it, staying where it is —,
  toggle fullscreen — full-screen on the game's backdrop, neither draggable
  nor resizable, and back to the floating window as it was —, and minimise
  to the taskbar; it reports each fullscreen change.
- Window position and fullscreen state are restored from a small file in
  the user-data directory, outside any save directory; a missing or
  unreadable file falls back to a windowed window, centred.
- Uncaught errors from the main process and the page go to a rotating local
  crash log in the user-data directory; nothing is uploaded.
- Closing the window runs one closing sequence (flush request hook, bounded
  timeout, shutdown hook, exit) that later tasks fill; with no hooks it
  simply exits.
- Node tests drive window-state, crash-log rotation, protocol path
  resolution and the closing sequence with injected Electron stand-ins; a
  manual `npm start` in `desktop/` opens the playable game.

## Decisions
- **Re-planned for the frameless desktop window** (design changelog
  2026-10-23, "Window title bar, window behaviour and game logo"): the
  window's size is no longer remembered — it follows the page's content —
  and the window has no system frame.
- The host lives in `desktop/` with its own `package.json`, so the web
  preview keeps having no dependencies and `node --test` at the root keeps
  working without installing Electron. Main-process logic is written over
  injected Electron APIs so its tests run on the Node built-in runner.
- Settled here: the location of the desktop code, which
  `.claude/domain/features/steam-desktop-host.md` leaves unstated.
