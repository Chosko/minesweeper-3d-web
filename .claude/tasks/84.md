# Task 84 — Electron main process: window, game protocol, window state and crash log

Target: claude

## Goal
Start feature `steam-desktop-host`: the Electron main process that creates
the one game window and loads the same game files the web preview serves,
over a custom application protocol so ES modules and the generation worker
load as they do on the web. It holds the single-instance lock, remembers the
window's size, position and fullscreen state, writes uncaught errors from
both processes to a local crash log, and runs the closing sequence every
quit path will share.

## Acceptance criteria
- `desktop/` holds the host: its own `package.json` (Electron as a dev
  dependency, a `start` script) and the main-process modules; the web build
  at the repo root stays dependency-free and unchanged.
- The window loads `index.html` from a custom protocol scoped to the packaged
  game files; ES modules and the generation worker load; a request outside
  the game files is refused.
- The page runs with context isolation on, Node integration off and the
  sandbox on.
- A second launch focuses the running window and exits.
- Window size, position and fullscreen state are restored from a small file
  in the user-data directory, outside any save directory; a missing or
  unreadable file falls back to a default window.
- Uncaught errors from the main process and the page go to a rotating local
  crash log in the user-data directory; nothing is uploaded.
- Closing the window runs one closing sequence (flush request hook, bounded
  timeout, shutdown hook, exit) that later tasks fill; with no hooks it
  simply exits.
- Node tests drive window-state, crash-log rotation, protocol path
  resolution and the closing sequence with injected Electron stand-ins; a
  manual `npm start` in `desktop/` opens the playable game.

## Decisions
- The host lives in `desktop/` with its own `package.json`, so the web
  preview keeps having no dependencies and `node --test` at the root keeps
  working without installing Electron. Main-process logic is written over
  injected Electron APIs so its tests run on the Node built-in runner.
- Settled here: the location of the desktop code, which
  `.claude/domain/features/steam-desktop-host.md` leaves unstated.
