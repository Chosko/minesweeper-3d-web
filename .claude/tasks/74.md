# Task 74 — Library view in the Records screen

Target: claude

## Goal
Add the library view of feature `replay-library` to the Records screen: the
chosen board's kept replays with their stats and pin state, *Watch* and
*Pin* / *Unpin*, and *Watch* on the bests and recent games whose replay is
kept.

## Acceptance criteria
- For the board the Records screen shows, a list of its kept replays with
  date, outcome, time, 3BV/s, efficiency and pin state, newest first, with a
  filter that shows pinned ones first; an empty state when there are none.
- Each replay's time is shown to the tenth of a second, truncated
  (47.38 s shows as `47.3 s`), through the results screen's time formatter
  (task 46) rather than a second copy; a Node test checks a row's time.
- *Pin* / *Unpin* toggles the hand pin and the list updates through the
  library's change notification.
- The bests panel and the recent-games list show *Watch* on entries whose
  replay is kept.
- *Watch* routes to the replay viewer with the replay id and the Records
  screen to return to; the action is shown only once the replay route is
  registered.
- When replays are not being saved this session, the screen says so once.
- Mouse, keyboard and controller operate every action; Node tests cover the
  list model and the pin toggle with a fake library.

## Decisions
- *Watch* appears only when the shell has a replay route, so this view can
  land before `replay-playback`'s viewer and gains its action when that
  screen is registered.
- The list's time format is `results-screen`'s, per `replay-library.md`
  § Architecture (Library view). Task 46, in the earlier milestone, lands
  before this task through its precondition 48, so the shared formatter
  needs no precondition of its own here.
