# Task 15 — Browser storage implementation and start-up selection

Target: claude

## Goal
Add the web build's implementation of feature `platform-storage`: a backend
keeping each document in browser storage under one namespaced key, with the
failure handling that keeps the game playing when storage is unavailable,
full or corrupt, and the start-up selection that makes it the active
implementation without callers knowing which is active.

## Acceptance criteria
- The browser backend stores each document under one namespaced key,
  serialised as text with its version; it never reads or deletes the legacy
  `ms3d.*` keys.
- Storage that cannot be read behaves as empty; a write that fails (quota,
  blocked storage) is reported as a failed save; `available()` reports
  whether anything will persist this session.
- A corrupt document's raw text is kept aside under a separate key, not
  overwritten, until the owner saves a new document.
- The platform module selects the browser implementation once at start-up
  and exposes the storage interface; no caller imports a backend directly.
- Node tests drive the backend through a fake `Storage` object (including a
  throwing and a full one); a Playwright check confirms a document survives
  a page reload.
