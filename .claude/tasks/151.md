# Task 151 — Daily board, board codes and challenge links

Target: claude

## Goal
Give the returning player a reason to come back each day, and let any board
be shared. This is row W-33 of `docs/UX_REVIEW.md` § Approved scope and work
plan (Area: Generation, shell, Records; Size: Medium; Phase 5, after W-13).
It closes I-03 and I-04 of that document under decision 15 ("Daily board and
codes on the web now? Yes, with a marked start cell — I-03, I-04 proceed").

- **I-03, Board of the day with a shareable code** (Medium; returning
  player, friends comparing). Nothing calls the player back on a given day,
  and bests move rarely. The generator is deterministic from board, start
  cell, seed and generator version, so a static site can offer one 2D and one
  3D board per day. The one design gap was that the board must mark its start
  cell. Approved sketch: a "Daily" menu entry with today's Expert no-guess
  and today's cube, a highlighted start cell, one counted attempt per day, a
  Daily board in Records with a days-in-a-row streak, a board code
  (E-20261011-7F3A style) and a link that opens the same board, pre-generated
  when the menu opens.
- **I-04, Board codes and challenge links for any game** (Small, after I-03;
  enthusiasts sharing a board or a best to beat). Every summary already
  stores the seed and generator version. Approved sketch: show the code on
  results, Records and the replay viewer with Copy; accept it in the custom
  form ("Play this board"); a challenge fixes and marks the start cell like
  the daily.

Task 138 (row W-13) introduced the marked start cell (the centre cell of each
side), pre-generation for it and the recorded seed. It kept the first click
free everywhere. This task is the one place the start cell is forced: on the
daily board and on a challenge. Task 128 (row W-27) left the board code on
the results screen to this task. The task serves the returning player,
friends comparing a day's board, and enthusiasts sharing a board or a best
to beat.

## Acceptance criteria
- **Board code format** (I-03, I-04). One DOM-free module encodes and parses
  codes (`encodeBoardCode`, `parseBoardCode`). A code rebuilds its board
  exactly from board, seed, start cell and generator version. The grammar is
  uppercase on output and case-insensitive on input, with surrounding
  whitespace ignored:
  - **Board token.**
    - `B`, `I`, `E` for the three 2D standard boards, recognised by exact
      dimensions and mines as `standardBoard` does.
    - `<w>X<h>M<mines>` for any other 2D square board, e.g. `20X12M50`.
    - `<x>X<y>X<z>M<mines>` for every 3D board, cube presets included, e.g.
      `8X8X8M40`.
    - A trailing `N` when the board is no-guess: `EN`, `8X8X8M40N`.
  - **Daily code** `<board>-<YYYYMMDD>-<check>`, e.g. `EN-20261011-1F3A`.
    The seed is `dailySeed(date, board token)` and the start cell is the
    board's marked start cell, as task 138 defines it.
  - **Game code** `<board>-<seed>-<start>-<check>`, e.g.
    `EN-9C41D07A-247-1F3A`. The seed is 8 hex digits, zero-padded. The start
    is the start cell's index in decimal, in the graph's own coordinate
    order.
  - **Check** `<generatorVersion in decimal><3 hex digits>`. The 3 hex digits
    are the low 12 bits of the 32-bit FNV-1a hash of the code's canonical
    text with the version appended: `<board>-<payload>[-<start>]-<version>`.
    A typo is caught before anything is generated.
  - **Daily seed.** `dailySeed(date, token)` is the 32-bit FNV-1a hash of
    `daily-<YYYYMMDD>-<token>`.
  - The grammar, the hash and the daily seed are frozen. A later change is a
    new code shape and never a reinterpretation of an existing code.
  - `parseBoardCode` returns `{ ok: true, board, seed, startCell,
    generatorVersion, daily? }` or `{ ok: false, reason }`, never throws, and
    refuses each of these with its reason:
    - malformed text or a failed check (a typo);
    - a board outside the mode's custom limits, including task 124's at least
      one mine when it has landed;
    - a 3D no-guess board the 3D board choice refuses (over 8,000 cells, a
      side of 2);
    - a start cell outside the board.
  - Round trips are pinned for every board kind, both forms and seeds 0 and
    2^32 − 1.
- **Unknown generator version.** A code whose version is not this build's
  `GENERATOR_VERSION` is refused, and nothing is generated, so a code never
  opens a board other than the one it names:
  - newer: "This board code comes from a newer version of the game. Reload
    the page to update.";
  - older: "This board code was made by an older board generator and can no
    longer be rebuilt."

  A code shown for a game always carries that game's recorded
  `generatorVersion`.
- **Daily boards** (I-03; decision 15):
  - Each day has two boards: 2D Expert no-guess (`EN`) and the cube
    8 × 8 × 8 · 40 no-guess (`8X8X8M40N`).
  - "Today" is the player's local calendar date.
  - Each board is generated with `generate({ graph, mineCount, firstClick:
    <marked start cell>, noGuess: true, seed: dailySeed(date, token) })`.
  - A test pins the mines of one fixed date's two boards, so a change to the
    generator or the seed shows up as a failing test.
- **Daily entry and screen** (I-03):
  - `MENU_ENTRIES` gains `daily`, between `3d` and `records` (the order of
    product-design § Main menu). It opens a Daily screen on the router with
    two rows, "Expert" and "Cube".
  - Each row shows today's date, the row's state ("Not played", "Won 48.2 s"
    or "Lost"), the current and longest days in a row, today's code with
    Copy and Copy link, and Play. A played row also offers Watch replay when
    the library kept the replay.
  - Play is offered only while today's counted attempt is unused.
  - The cube row is disabled with task 132's reason when 3D is unavailable.
  - The screen is built from the component kit, takes its focus and Back from
    the router, and works by mouse, keyboard and controller.
- **Pre-generated when the menu opens** (I-03):
  - When the main menu shows, today's daily boards whose counted attempt is
    unused are requested in the background through each mode's warm client
    (task 138's one client per mode). The menu never waits for them.
  - A finished daily board is kept in memory under its code. It is
    deterministic, so it equals a fresh generation.
  - A daily played before its board arrives waits on the generating card
    under task 138's rules.
- **Forced, marked start cell** (I-03, I-04; decision 15). This applies to a
  daily and to a challenge, and nowhere else:
  - The game opens closed, with the start cell marked as in task 138: the 2D
    mark, the 3D tinted cube. In 2D the keyboard and controller cursor starts
    on it.
  - The first reveal must be on the marked cell. A reveal anywhere else
    changes nothing and is not recorded. It shows a hint, "Start on the marked
    cell", and the mark pulses (2D view, 3D tint).
  - Flags before the first reveal behave as each mode already treats them.
  - The board is the one generated for that start cell, used as task 138
    uses a pre-generated board, so the timer starts at the first click.
  - Free play keeps task 138's free first click unchanged.
- **One counted attempt per day** (I-03):
  - Today's counted attempt for a row is the first daily game of that date to
    reach its first click. A daily left before its first click uses nothing.
  - Once started, the game is recorded as every game is: left, restarted or
    closed, it counts as a loss.
  - It is recorded on that day's Daily board only, not on Expert no-guess or
    the cube board.
  - A daily started before midnight finishes as its own date's attempt.
  - Once the attempt is used, the row shows the result and code. The same
    board stays playable only through its code, as a challenge (below).
- **Daily board in Records** (I-03):
  - Each mode has one Daily board: the daily board's identity with a daily
    flag, keyed `daily:<board key>`, for example
    `daily:classic-2d:square:30x16:99:no-guess`. `parseBoardKey` reads it
    back, and `boardLabel` gives "Daily · Expert · no-guess" or
    "Daily · 8 × 8 × 8 · 40 mines · no-guess".
  - Each Records picker lists it after the mode's named boards and before
    custom boards.
  - Its figures are the three bests, games, wins and win rate, with the
    streak as days in a row (current and longest) in place of the win streak:
    - the streak counts consecutive dates that have a counted attempt, won or
      lost;
    - the current streak stays alive until a date ends without one.
  - The days-in-a-row streak derives from the history, so rebuilding the
    records from the history alone gives the same figures.
  - A records format version step makes an older build refuse the new
    documents instead of misreading them. Existing keys and figures are
    unchanged.
  - Daily games count in the mode's overall figures like any game of that
    mode.
- **Board code on results, Records and the replay viewer** (I-04; the code
  task 128 left to this task):
  - Shown with Copy and Copy link wherever the game has a seed (a fixed 3D
    board with no seed shows none):
    - the results screen, for won and lost games;
    - every Records row that names one game: the recent games list, the
      library view's rows, and the top-10 rows when task 149 has landed;
    - the replay viewer.
  - The summary record gains `startCell`, the first click's cell. A daily
    game's summary also gains its `daily` date, and a challenge's its
    `challenge` flag.
  - The compact history entry keeps `seed`, `generatorVersion`, `startCell`,
    `daily` and `challenge`. The replay listing carries the code. An entry
    or a replay from before this task shows no code.
  - A daily game shows its daily form on results and in Records.
  - The replay viewer builds the game form from the header's board, seed and
    generator version and the first reveal in the action stream. This needs
    no replay format change.
  - Copy writes the code. Copy link writes
    `<origin><path>#board=<code>`. When the clipboard is refused, the code
    text is selected and a toast says to press Ctrl+C.
  - Both buttons are reachable by keyboard and controller, and the contrast
    test covers them in both themes.
- **"Play this board" in the custom forms** (I-04):
  - Classic 2D's and 3D's board choice screens each gain a code field and a
    "Play this board" button.
  - A valid code of the form's own mode starts it as a challenge. A code of
    the other mode is refused with a hint that names the right mode. A
    refused code shows `parseBoardCode`'s reason live, as the custom fields'
    live validation does, and the button stays disabled.
  - Today's daily code opens the Daily screen instead, so the counted
    attempt rules hold.
  - A challenge or a daily never changes the last board choice memory.
- **Challenge links** (I-03, I-04):
  - At start-up, once settings and records have loaded, `#board=<code>` in
    the URL opens the main menu and then starts that challenge, so Back
    leads to the menu. Today's daily code opens the Daily screen instead.
  - A `hashchange` to `#board=` is honoured the same way while no game is
    started. During a started game it is ignored with a toast.
  - A refused code shows the main menu with a toast giving its reason.
  - The hash is then removed with `history.replaceState`. This adds no
    history entry and keeps task 122's rule that the shell's own navigation
    never changes the URL.
  - No `404.html` change is needed: `/#board=…` is served by `/`.
- **Challenge records** (I-04): a challenge — a game started from a board
  code or a `#board=` link — is recorded on its board identity and kept in
  the history and in games played, but is not eligible for bests and is not
  counted in the win rate or the streaks, standard or completed-games (task
  130's, where it has landed).
  - It is not ranked either, since both lists rank bests: the ranking
    behind the results screen's "#n of N on this board" (task 128's, or
    task 149's one ranking function where it has landed) and task 149's
    Top 10 leave challenge games out, in N as well. A challenge's own rank
    figure shows a dash, as any unavailable figure does. A challenge
    counts only in the history and in games played.
  - This holds for the board's figures and the mode's overall figures. The
    history entry's `challenge` flag lets a rebuild from the history alone
    give the same figures.
  - The results screen labels a challenge "Challenge · not eligible for
    bests", in the style of the "Paused · not eligible" wording of
    `docs/UX_REVIEW.md` P-48.
  - The daily board keeps its own board, streak and counting, as defined
    above.
  - Play again after a challenge or a daily starts a fresh free-play board of
    the same size, mines and no-guess setting, never the same seed.
  - A challenge whose no-guess generation fails (a hand-made code past the
    attempt budget) says so and offers Back only. It never substitutes
    another board.

  Settled here:
  - the code grammar, check, daily seed and unknown-version rule;
  - local date for "today";
  - the cube daily board;
  - the counted-attempt boundary;

  These documents are normally `/architect`'s. This task updates them for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- **The cube daily is 8 × 8 × 8 · 40 no-guess.** That is Cube Intermediate as
  it stands. P-20 keeps that board "as is" in every measured candidate for
  W-17, and W-17 has no task yet, so it does not depend on W-17's outcome.
  The re-tuned Beginner (6 × 6 × 6, its mine count measured between 16 and
  20 by task 152) is not in the preset table yet, and its tuning is W-17's
  to settle. The daily and every 3D code name the board
  by its dimensions, never by preset name, so a later preset re-tune changes
  neither today's board nor any code.
- **Letter tokens only for the 2D standard boards.** Their sizes are fixed by
  the reference. Every other board is spelled out, so a code never changes
  meaning when a preset changes.
- **Two code shapes.** The daily shape keeps the date readable in the code,
  in I-03's E-20261011-7F3A style; the daily boards are no-guess, so it reads
  `EN-…`. The game shape carries the seed and the free first click a game
  was played from. Both carry the generator version explicitly, because
  `GENERATOR_VERSION` covers everything a board depends on except the start
  cell, which the code carries itself.
- **Unknown versions are refused, never approximated.** The build keeps only
  its own generator. A code read under another version would open a
  different board under the same code, which defeats sharing. The refusal
  says whether to reload (newer) or that the code is spent (older).
- **"Today" is the local calendar date.** "The same for every player, worked
  out from the date" (product-design § Daily board) holds per date. The code
  carries the date, so friends in other time zones can still share a day's
  board. A local day also matches the days-in-a-row streak the player sees.
- **The counted attempt starts at the first click.** That is the moment the
  records' game-in-progress marker starts a game today. A daily opened and
  left before it costs nothing, and a started one follows the existing
  "counts as a loss" rule.
- **Days in a row counts days played, won or lost.** I-03's purpose is
  calling the player back each day, and Expert no-guess losses are common. A
  won-days streak would break on the board's difficulty rather than the
  player's absence. Wins and win rate still show beside it.
- **The daily is counted on the Daily board only.** It is played under a
  forced start and once a day, a condition the plain board's games do not
  share. That mirrors "no-guess boards as separate records".
- **A challenge is kept but not eligible (director decision, 2026-10-12;
  `docs/UX_REVIEW.md` I-04).** `personal-records` keeps "the player's local
  record of every game", so a challenge stays in the history and in games
  played; the director rules it out of bests, the win rate and the streaks,
  standard and completed-games. Its results label follows P-48's
  "Paused · not eligible" form. Play again after one deals a fresh seed, so
  no button repeats a known board.
- **A challenge is not ranked (director decision, 2026-10-12;
  `docs/UX_REVIEW.md` I-04):** the results screen's "#n of N on this board"
  and task 149's Top 10 are best-type lists, so "not eligible for bests"
  leaves challenges out of both.
- **A code of the other mode is refused with a hint** rather than switching
  modes from inside a board choice screen. A link opens either mode.
- **Feature attribution:** none. Every feature that owns a touched document
  is `[DONE]`, and no `[PLANNED]` feature covers the daily board or codes.
- **Boundaries.** Out of scope:
  - Steam daily leaderboards and ranks (product-design § Daily board;
    `steam-leaderboards`);
  - the cube preset re-tune and first-box presets (W-17);
  - the generation pipeline itself (task 138), the free first click it
    keeps, and its Play-again pre-generation;
  - replay import and download (task 150);
  - campaign levels.
