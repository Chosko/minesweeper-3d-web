# Task 107 — Leaderboards tab in Records and Quit in the main menu

Target: claude+human

## Goal
Implement feature `leaderboards-menu-entry`: make the Records screen's
Leaderboards tab — built with its coming-soon panel by task 170 — lead to the
leaderboards of the board Records shows, in both builds; and make the main
menu's Quit entry, which task 165 shows locked on the web, work in the
desktop build by asking the host to run its closing sequence.

## Acceptance criteria
- **Leaderboards tab.** In the web and the desktop build the tab replaces
  its coming-soon panel with the leaderboards of the board Records shows, in
  the form the owner settles (see Manual interventions); Back from the
  leaderboards returns to Records with the tab selected. The tab is always
  shown, whatever Steam's state; Steam unavailable or offline is reported in
  the leaderboards, never by hiding the tab. No main-menu entry for
  Leaderboards.
- **Quit.** The menu's final entry is enabled only when the desktop-host
  capability flag is on (whether or not Steam started) and stays locked
  otherwise, as task 165 draws it, with no styling of its own and no rule
  added to any theme stylesheet. Quit sends the bridge's quit request and
  disables itself while it is in flight, so a second activation sends
  nothing; a rejected request re-enables it. The page does no flushing of
  its own on Quit and asks no confirmation.
- Both are in focus order for mouse, keyboard and controller; Esc and the
  back button on the main menu never quit.
- Node tests cover Quit both ways (locked on the web, enabled on the
  desktop), the quit flag and rejection with a fake bridge; Playwright
  checks the Records tab's leaderboards round trip on the web build.

## Decisions
- **Owner decision** (DESIGN-CHANGES §2.2): Leaderboards leaves the main
  menu and becomes Records' fourth tab; this replaces the Leaderboards menu
  entry this task first carried.
- **Quit on the web stays locked** — the owner's answer.
