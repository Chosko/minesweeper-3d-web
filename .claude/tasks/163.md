# Task 163 — Layout kit components: backdrop, screen frame, mode entry, board option, stat tile and the rest

Target: claude

## Goal
Add the components the shared layout of feature `shared-screen-layout` is
built from to the component kit, so every screen can be recomposed from
catalogued parts: every component the canvas's J-Components artboard draws
that the kit lacks — among them the page backdrop, the screen frame (head
with back action, title and screen action; scrolling body; foot as a status
line or a bottom bar with a summary and actions; a window-chrome decoration
slot), the mode entry (icon, label, per-entry accent, Last played chip,
selected and disabled states), the board option (name, size line, mine
density, Last played chip beside the name, chosen and selected states), the
section label, the key hint, the stat tile (label, figure, detail line,
optional badge), the chip (state, rank, *Coming soon*), the list row of
recent games and the scene panel. Each joins the kit catalogue, gets its
structure in the base stylesheet and its look in *Joyful tiles* from
J-Components, and shows in the gallery.

## Acceptance criteria
- **Catalogue.** Each new component is declared in `js/ui/kit-catalogue.js`
  with its parts (optional ones marked), the states of its interactive parts
  and its decoration slots (the screen frame's window-chrome slot at
  least), and documented as a markup pattern in the head comment of
  `css/components.css` (element, role, accessible name). Every component
  J-Components draws is in the catalogue after this task (existing or new).
- **State model.** Mode entries and board options follow the kit's state
  model (`screen-components.md` § Scope and non-goals), as task 158 does for
  buttons: raised by default, level with the surface when hovered or
  focused, sunk when pressed, flat when disabled — no outline or halo. The
  selected mode entry is also taller than the others, with a bigger icon and
  label. A board option's chosen state is its fill and check, distinct from
  selected, so "focused but not chosen" and "chosen" read apart.
- **Mode entry.** Icon and label, the entry's accent from J-Tokens, the
  Last played chip; a disabled entry shows its reason line and a lock and
  opens nothing. No locked state for a mode entry: modes not built yet are
  ordinary entries.
- **Board option.** Name, size line, mine density and the Last played chip
  beside the name — no 3BV and no best part; an option may omit the size
  line and density (*Insert Board Code* carries a one-line description
  instead).
- **Base structure.** `css/components.css` gives each its layout only: the
  frame on the backdrop at a size bounded by the window, sizable to its
  content, its head and foot staying in view while its body scrolls
  vertically; decoration slots hidden by default; no visual value.
- **Joyful tiles look.** `themes/joyful-tiles/theme.css` styles every new
  part and state as J-Components draws it; *Joyful tiles* still passes the
  conformance suite.
- **Accessibility.** Every interactive part is a native button or input
  reachable by keyboard and controller navigation, with an accessible name
  and a visible focus style (the selected state on mode entries and board
  options); the key hint follows the active input device through the
  bindings source, as every help surface does.
- **Gallery.** `dev/components.html` shows every new component in every
  state and with its decoration slot, under any registered theme.
- **Tests.** `tests/components.test.mjs` covers the new markup patterns
  (structure, roles, names, the disabled mode entry, a chosen and a focused
  board option told apart, the frame body scrolling with head and foot in
  view at a short window), and the conformance suite covers the new
  catalogue entries for every theme.
- No screen uses the new components yet; existing screens are unchanged.

## Decisions
- **Settled design detail** (`.claude/domain/features/shared-screen-layout.md`
  § Scope, *New kit components*; § Architecture, *Kit additions*): the exact
  component, part and slot names, chosen here and fixed as the contract. The
  feature document is not edited here; task 173 records what holds at ship
  time.
- **The canvas is the source** (owner, DESIGN-CHANGES §1): J-Tokens and
  J-Components are the source of the theme's tokens and the Joyful kit CSS;
  the components are built as drawn there, not from the earlier S3D
  artboards.
- **No locked mode entry** (owner decision, DESIGN-CHANGES §2.1, reversing
  the locked state this task first carried): Hexagon, Triangle and Surface
  are enabled entries; only the disabled state, with a reason, remains.
- **Open item — focus visibility** (DESIGN-CHANGES §8, raised with the
  owner): the flush selected state is the only focus cue; build it as drawn
  and add no ring. An answer that changes the cue arrives as an amendment.
