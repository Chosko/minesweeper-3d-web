# Task 163 — Layout kit components: backdrop, screen frame, mode entry, board option, stat tile and the rest

Target: claude

## Goal
Add the components the shared layout of feature `shared-screen-layout` is
built from to the component kit, so every screen can be recomposed from
catalogued parts: the page backdrop, the screen frame (head with back action,
title and screen action; scrolling body; foot status line; a window-chrome
decoration slot), the mode entry (icon, label, detail line, per-mode accent),
the board option (name, size line, best time, selected state), the section
label, the key hint, the stat tile (label, figure, detail line), the list row
of recent games, and the scene panel (a framed region the 3D scene draws
into). Each joins the kit catalogue, gets its structure in the base stylesheet
and its look in *Joyful tiles*, and shows in the gallery.

## Acceptance criteria
- **Catalogue.** Each component above is declared in `js/ui/kit-catalogue.js`
  with its parts (optional ones marked), the states of its interactive parts,
  and its decoration slots (the screen frame's window-chrome slot at least),
  and documented as a markup pattern in the head comment of
  `css/components.css` (element, role, accessible name).
- **Base structure.** `css/components.css` gives each its layout only: the
  frame centred on the backdrop at a size bounded by the window, its head and
  foot staying in view while its body scrolls vertically; decoration slots
  hidden by default; no visual value.
- **Joyful tiles look.** `themes/joyful-tiles/theme.css` styles every new part
  and state from the S3D-Menu and S3D-Setup artboards (dotted-paper backdrop,
  framed window, mode entries with their accents, board options, stat tiles,
  key hints, list rows); *Joyful tiles* still passes the conformance suite.
- **Accessibility.** Every interactive part is a native button or input
  reachable by keyboard and controller navigation, with an accessible name and
  a visible focus style; the key hint follows the active input device through
  the bindings source, as every help surface does.
- **Gallery.** `dev/components.html` shows every new component in every state
  and with its decoration slot, under any registered theme.
- **Tests.** `tests/components.test.mjs` covers the new markup patterns
  (structure, roles, names, the frame body scrolling with head and foot in
  view at a short window), and the conformance suite covers the new catalogue
  entries for every theme.
- No screen uses the new components yet; existing screens are unchanged.
