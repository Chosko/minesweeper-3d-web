# Task 17 — Component kit: styles, markup patterns and focus contract

Target: claude

## Goal
Build the component kit of feature `screen-components`: one stylesheet of
component classes styled only from design tokens — primary and secondary
buttons, vertical menu list, card and panel surfaces, toggle, slider,
segmented choice and numeric stat readout — each with its documented markup
pattern, every interactive state, a visible focus ring, and the small
behaviour helpers the slider and segmented choice need.

## Acceptance criteria
- `css/components.css` styles every component above from tokens only; no
  component carries theme-specific rules, so both themes follow from the
  token values.
- Every interactive component has default, hover, pressed, focused (visible
  focus ring for keyboard and controller) and disabled states.
- Each component's markup pattern — element, class, ARIA role, accessible
  name — is documented at the head of the stylesheet as the catalogue
  screens build against.
- Small helpers (slider value display, segmented choice selection) live in a
  DOM module with Node-testable logic separated from DOM access.
- Every interactive component is reachable by keyboard and declares its
  default focus target the way the shell's controller navigation expects
  (`padNav` in `js/main.js`).
- A component gallery page renders every component in every state; a
  Playwright check screenshots it in both themes and asserts text contrast
  meets the tokens' contract.
