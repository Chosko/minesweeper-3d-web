# Task 254 — Hexagon graph provider and the `hex` generation description

Target: claude

## Goal
Part of feature `hexagon-grid`: add the hexagon cell-graph provider beside
the square-grid provider, and the `hex` description that board generation,
the generation worker and the marked start cell accept. A board of W × H is
W columns of H flat-top hexagons, odd columns half a tile lower, and a
tile's neighbours are the tiles that share a side. The rules engine plays on
it unchanged.

## Acceptance criteria
- The provider takes width and height and returns the immutable cell graph
  with the square provider's index (column + width × row) and column-row
  helpers. Every neighbour list is in ascending index order. Interior,
  edge and corner neighbourhoods of even and odd columns are pinned by tests.
  An impossible size throws a `RangeError`.
- The generator, placer, logic-only solver and no-guess loop run over a
  `{ kind: 'hex', width, height }` description with the same attempt budget
  and no generator version change. The same request, seed and version give
  the same board in the worker and in Node.
- The marked start cell of a `hex` description is the centre column and row,
  as on the square grid.
- The reference profile's reveal, flag, chord, safe first click, 3BV and
  click counting are tested on a small hexagon board.
- The no-guess generation time on Expert (30 × 16, 123 mines) is measured
  and reported. If it misses the attempt budget's timing, the report says so
  as a follow-up for `board-generation`; this task does not change the
  budget.

## Decisions
- Settles the feature document's open question on Expert no-guess timing by
  measuring it; a budget change is not this task's.
