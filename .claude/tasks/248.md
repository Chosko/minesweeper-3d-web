# Task 248 — Flat grid geometry contract and the square geometry

Target: claude

## Goal
Feature `flat-grid-geometry` collects the Classic 2D stack's square-grid
assumptions behind one DOM-free geometry interface, so Hexagon and Triangle
share Classic 2D's board, inputs, sampler and viewer. This task adds the
contract and its first implementation, the square geometry, which reproduces
Classic 2D's layout, hit-testing, cursor moves and tile shape exactly. No
consumer is moved onto it yet; tasks 249-252 do that.

## Acceptance criteria
- A geometry built from a grid kind, width and height answers: the board's
  extent at a tile size and gap; each cell's centre, outline (with its
  orientation) and glyph box; the cell at a board point, or none outside the
  board, with a point in a gap going to the cell whose slot holds it; the
  cursor's neighbour up, down, left and right, or none at the edge; the
  minimum tile size and the tile size at each board scale.
- The square geometry's answers equal today's pitch arithmetic
  (`boardLayout`, `cellAtLayout`, the cursor's column and row steps) and its
  floor and cap are the shipped `MIN_TILE_SIZE` and `TILE_CAP`, read from
  where they live rather than copied.
- An unknown grid kind throws a `RangeError` when the geometry is built.
- The module is DOM-free and tested with Node's runner (fast tier),
  including a property test that every point inside the board's outline maps
  to exactly one cell.

## Decisions
- **The geometries live in a new folder `js/geometry/`** (`index.js` with
  the kind lookup, `square.js`), beside `js/engine/`: the replay viewer and
  the records layer rebuild a geometry from a board identity, so it is not
  Classic 2D's private module. The hexagon and triangle geometries
  (tasks 255, 259) join the same folder.
- Board units on the square geometry are pitches, so recorded replays stay
  valid.
