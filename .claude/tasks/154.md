# Task 154 — Fast and slow test tiers and a cheaper browser suite

Target: claude

## Goal
Make the test suite a quick regression tool. A full
`.claude/external/run-full-tests.sh` run takes about 9 minutes (549 s wall,
1077 s summed at concurrency 2) on the 4-core cloud box with no GPU. The 59
tests named "…in a browser…" take 98.8 % of that time; the other 1479 tests
take about 13 s. 77 % of the time (834 s summed) goes to 18 browser files
about Classic 2D, the shell, Records, Settings and the component kit that load
`index.html` with WebGL live and so pay for the decorative 3D menu backdrop:
`shouldRender()` in `js/main.js` returns true on every frame while
`onBackdrop()` holds (menu, board-choice, coming-soon, records,
classic-2d-choice, settings), orbiting a 343-cube demo board at about 10 fps
under SwiftShader. Every Playwright wait polls on `requestAnimationFrame`, so
each wait is 10–20× slower on those screens. A probe on the idle box, same
page and 1100 × 900 viewport:

| | WebGL live | WebGL 2 refused by init script |
|---|---|---|
| menu rAF rate | 10.4 fps | 59.1 fps |
| two-rAF wait | 331 ms | 21 ms |
| element screenshot `#menu .ui-card` | 5281 ms | 382 ms |
| `browser.close()` | 3787 ms | 177 ms |

This task splits the suite into a fast and a slow tier by test name, stops
the backdrop costing time in the 2D and screen browser tests, makes the
component kit's artefact screenshots opt-in, maps changed files to the tests
that cover them, and puts a per-test timeout on the full run. Every part of
this scope was approved by the owner.

## Acceptance criteria
- **Two tiers by test name, no file moves.**
  `.claude/external/run-fast-tests.sh` runs
  `node --test --test-skip-pattern="in a browser" "tests/**/*.test.mjs"`;
  `.claude/external/run-browser-tests.sh` runs the same glob with
  `--test-name-pattern="in a browser"`, at `--test-concurrency=2` like the
  full run. Both `cd` to the repo root as the existing scripts do and pass
  extra arguments through to `node --test`.
- `.claude/external/run-full-tests.sh` still runs the whole suite, with
  `--test-timeout=180000` added to its `node --test --test-concurrency=2
  "tests/**/*.test.mjs"`.
- **The backdrop no longer costs time in the 18 2D and screen browser
  files:** `components`, `classic2d-mode`, `shell-pause`, `settings-page`,
  `shell-menu`, `shell-help`, `shell-returning`, `results-watch`,
  `shell-history`, `records-history`, `shell-router`, `settings-appliers`,
  `replay-viewer`, `results`, `classic2d-fidelity`, `records-screen`,
  `records-replays`, `tile-skin` (each `tests/<name>.test.mjs`). The
  implementer picks, per test, whichever of the two mechanisms degrades no
  test's intent:
  - the existing WebGL-2-refusing init script — the
    `HTMLCanvasElement.prototype.getContext` override that returns `null` for
    `'webgl2'`, already used in `tests/shell-menu.test.mjs` (around line 411),
    `tests/shell-returning.test.mjs` (around line 448) and
    `tests/replay-viewer.test.mjs` (around line 747) — where 3D is irrelevant
    to the test; or
  - a test hook in `js/main.js` (for example a query parameter or an `__ms`
    switch) that stops the backdrop re-rendering after its first frame, where
    the test needs WebGL 2 present (a test that opens the 3D board choice or
    starts a 3D game, or asserts on the 3D menu entry being available).
  A test whose subject is the WebGL-2 path itself keeps it. The game's
  behaviour without the hook switched on is unchanged.
- The 13 genuinely 3D gameplay files keep rendering as they do now:
  `camera-spawn`, `mode3d-board-choice`, `mode3d-end`, `mode3d-session`,
  `records-screen-3d`, `render-3d-feedback`, `render-3d-flag-flash`,
  `replay-viewer-3d`, `shell-mode-3d`, `shell-mode-host`, `shell-pause-esc`,
  `shell-lock-fallback`, `shell-first-use`.
- **Artefact screenshots are opt-in.** In `tests/components.test.mjs`, the
  element screenshots that `check()` saves into a temporary directory, and
  the other artefact screenshots in that file (around lines 916, 964–965 and
  1014 at the time of writing), are taken only when an environment variable
  is set (for example `MS_SHOTS=1`); with it set, the existing
  `length > 1000` check still runs on each. The contrast assertions, which
  read computed styles through `measureContrast`, run either way.
- **Affected tests by import.** `.claude/external/run-affected-tests.sh`
  maps changed files to the test files that import them, directly or
  transitively, by walking each test file's static import closure over
  `js/`:
  - a change under `js/classic2d/` selects the `classic2d-*` tests and every
    other test whose closure reaches it, and not `render-3d-*`,
    `camera-spawn` or the `mode3d-*` tests that do not reach it;
  - a change to `js/main.js`, `index.html`, any file under `css/` or
    `js/render.js` selects every browser test (every test file holding a
    test named "…in a browser…") in addition to its importers;
  - a changed test file selects itself;
  - explicit test-file arguments run exactly those files, as today.
  A unit test or a scripted check pins the mapping on at least the
  `js/classic2d/` and `js/main.js` cases.
- **Measured durations**, recorded in the task's closing report and in
  `.claude/context/testing.md`: the fast tier under 30 s on the 4-core cloud
  box; the full suite materially under its current 9 minutes, with the
  before and after wall times stated.
- Every existing test still passes, in the full run and in the two tiers
  together.
- `README.md` § Tests documents the fast, browser and full runs and the
  screenshot variable; `.claude/context/testing.md` describes all four
  runner scripts, the tier convention (a browser test is named "…in a
  browser…") and the backdrop mechanism the tests use.

## Decisions
- **Script names** `run-fast-tests.sh` and `run-browser-tests.sh`, beside the
  existing `run-full-tests.sh` and `run-affected-tests.sh`, so all runners
  sit in one place under `.claude/external/`.
- **What `run-affected-tests.sh` takes as changed files:** an argument that
  is a test file under `tests/` runs as given; any other path argument is a
  changed source file to map; with no arguments, the changed files are those
  `git` reports against `HEAD` (staged, unstaged and untracked). This keeps
  explicit test-file calls working and replaces the no-argument usage error.
- **The investigation's report lives outside the repo**, so its measured
  figures and the classification of the 18 and 13 files are carried in this
  body; the implementer re-measures rather than trusting them.
