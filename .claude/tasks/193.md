# Task 193 — Records: best tiles and tables keep their figures on one line

Target: claude

## Goal
Make the Records screen's figures fit where they are shown. The UX review
drift audit (`docs/UX_REVIEW_DRIFT.md`, "Five most important findings" #2,
§ 1 row P-68 "defective", and § Defects outside the numbered items,
"Records tables wrap figures and stack actions") found:

1. **Best tiles too narrow (P-68).** At 1280, 1440 and 1920 px each of the
   three best tiles is 130–135 px wide. The best time "4.853 s" wraps its
   "s" onto a second line, and "96.0%" / "100.0%" spill past the tile's
   right border (the audit saw it at every width from 1024 to 1920 px).
2. **Tables wrap figures and stack actions.** At 1280 and 1920 px the
   Records tables wrap times ("4.853 / s") and board codes, and a replay
   row's Watch / Download / Unpin / Delete stack into a column about 200 px
   tall.

P-68's approved solution in `docs/UX_REVIEW.md` is "three stat tiles with
the figure large and its date and Watch small beneath, spacing from the
design tokens"; a figure that wraps or overflows its tile defeats it.

Steps to reproduce (from the audit): win any Classic 2D board (a few games,
so the replay list and recent games have rows) → Records at 1920 × 1080 (and
at 1280 × 800) → the Best time tile shows "4.853" over "s", the efficiency
tile's "100.0%" crosses the tile border; Recent games and the replay table
wrap the time and board code, and each replay row's four buttons stack
vertically.

## Acceptance criteria
- At 1024 × 768, 1280 × 800, 1440 × 900 and 1920 × 1080, in both themes and
  both modes (2D and 3D Records), each best tile's value — the longest
  realistic figures included: a time of "999.999 s", 3BV/s "99.99",
  efficiency "100.0%", and a dash — stays on one line, and its text box lies
  inside the tile's border box. The label, date and Watch stay inside the
  tile too.
- On a phone (390 × 844), where the tiles wrap as the kit already allows,
  the same holds.
- In the Recent games, Top 10 and replay tables at 1024 to 1920 px, every
  time and every board code stays on one line, and a replay row's actions
  (Watch, Download, Pin / Unpin, Delete) lay out in one row. At phone width
  the tables keep their existing stacked-card layout (the `max-width` block
  in css/style.css), with the actions in a row that may wrap only there.
- The fix is either more width for the tile row or a value that shrinks
  (`white-space: nowrap` with a clamped font size), the implementer's
  choice, using design tokens; the two-column layout (P-69) stays.
- Every Watch, Download, Pin and Delete stays a D-pad stop in the order
  task 144 pinned (tests/shell-pad-walk.test.mjs passes).
- **Tests first**: a browser test (tests/records-screen.test.mjs, or
  tests/components.test.mjs for the tile itself) seeds Records with long
  figures and asserts, at 1280 and 1920 px, each tile value is one line
  high and its bounding box is inside the tile's, each time and code cell
  is one line high, and a replay row's action buttons share one top
  coordinate. It fails on the current build.

## Decisions
- **One task for both findings**: the same screen, the same CSS block
  (css/style.css's Records rules and the kit's `ui-stat--tile`) and the same
  kind of fix — figures held to one line — checked by one browser test.
- **Actions as a row, not a menu.** The audit offers "a row or a menu"; a
  row keeps each button a D-pad stop, which P-41's approved solution ("make
  each table row's Watch a stop") and task 144 require, and changes no
  interaction.
- Settled without conflict: `.claude/domain/features/records-screen.md`
  § Architecture, "Records view" describes the tiles (label, figure large,
  date beneath) and does not fix their widths; the document does not
  change.
