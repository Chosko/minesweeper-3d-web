# Task 92 — Steam document storage, Steam blob store and the quit flush

Target: claude

## Goal
Add the page side of feature `steam-cloud-saves`: the Steam implementation
of `platform-storage`'s document interface (one text file per document) and
of `replay-library`'s replay store (one binary file per blob, a store per
name), both over the bridge's file operations, selected by the platform
layer when the bridge is present, with pending saves joining the quit
flush.

## Acceptance criteria
- Steam document storage implements exactly `platform-storage`'s register,
  load, save and availability, asynchronously; loading, upgrades and
  refusal of a newer version stay `platform-storage`'s; a file that will not
  parse is set aside and reported missing.
- Steam blob store implements exactly `replay-library`'s put, get, delete
  and list, plus opening a store by name; the replay library opens its own
  store unchanged.
- The platform layer's Steam slots for storage and the replay store are
  filled with these implementations; availability is true whenever the
  save directory is writable, whether or not Steam is running.
- Every save in flight registers with the flush hook from task 86, so the
  host's flush request waits for it.
- A failed write reports through `platform-storage`'s and
  `replay-library`'s own failure contracts, and the game keeps playing.
- Node tests run both implementations against a fake bridge over the file
  service from task 91, reusing the interface suites of the browser and
  in-memory implementations.
