# Task 89 — Steam adapter implementation on the chosen binding

Target: claude+human

## Goal
Build the Steam implementation of feature `steam-desktop-host`'s capability
adapter on the binding task 88 chose: the callback pump on a timer, start-up
through the Steam client, presence and logged-on state, identity, overlay
activation, and the fallback to the unavailable adapter when Steam cannot
start, so the game plays fully with local saves.

## Acceptance criteria
- The adapter's Steam implementation covers every capability the binding
  supports; one it lacks reports unavailable without changing any caller.
- The packaged build asks Steam to relaunch it through the client when
  started outside it; a development run uses the local app id file.
- When Steam does not initialise, the host selects the unavailable adapter
  and the game plays fully.
- Logged-on changes reach the page as Steam state events; overlay
  activation reaches the page as the overlay event; Steam is shut down in
  the closing sequence after the page's flush.
- Calls that need the Steam network reject with `offline` while it is down.
- Node tests run the adapter against a fake binding module; the manual
  checkpoint covers the real client.
