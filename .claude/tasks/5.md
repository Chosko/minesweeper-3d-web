# Task 5 — Rules engine: game state, actions and the first-click hand-off

Target: claude

## Goal
Build the rules core of feature `cell-graph-rules-engine`: game state over a
cell graph, creation under a rule profile and rules version, the phases
(awaiting first click, playing, won, lost), the first-click hand-off to board
generation, the reveal / toggle-flag / chord actions with iterative flood
fill, the cell-state queries the tile skin paints, and the ordered action
stream — playing the reference (Minesweeper Online, default options) profile.

## Acceptance criteria
- Create from a graph, a rule profile with an optional rules version (current
  by default) and a mine count → *awaiting first click*; or from a graph, a
  profile and version and a full mine set → *playing*. An unknown rules
  version is refused; a mine count outside what the board and the
  first-click guarantee allow, or a mine index out of range or repeated,
  throws a `RangeError` and never yields a half-built game.
- The first reveal in *awaiting first click* returns a "board needed at cell
  c" request and changes nothing; supplying a board then applies the reveal.
  A supplied board that breaks the first-click guarantee is rejected.
- Reveal, toggle flag and chord each take a cell index and return the cells
  changed and whether the game ended. Flood fill is iterative (no recursion
  limit on a large custom board). An action outside *playing* changes and
  counts nothing.
- Queries: each cell's visual state (closed, flagged, revealed with its
  number, mine, exploded mine, wrong flag); mines left (mines minus flags,
  may be negative); phase.
- State lives in flat typed arrays over the cell index; actions on an Expert
  board allocate nothing per cell.
- The ordered stream of applied actions with their cell indices is kept in
  memory for the game; the same board and actions always give the same game.
- Rule profiles are a table keyed by profile and version; the reference
  profile ships as version 1.
- Node tests cover every contract above on hand-built square boards.

## Decisions
- Where the reference could behave two ways (left click on a satisfied
  number, chord with wrong flags, flagging a revealed cell, the loss view),
  this task implements the most common Minesweeper Online behaviour and
  marks each such rule in the profile; task 7 pins each against a recorded
  observation. Rules version 1 is not frozen until task 7 lands, because no
  version has shipped yet: a mismatch task 7 finds is corrected in version 1
  itself, not as a version 2.
