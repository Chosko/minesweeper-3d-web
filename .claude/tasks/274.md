# Task 274 — Replay format version with `hex` and `tri`, and the 2D recorder over them

Target: claude

## Goal
Part of feature `flat-grid-records-replays`: every Hexagon and Triangle
game is recorded as a replay. The replay format version steps up: the
header's graph kind gains `hex` and `tri`, each with the 2D sample arity, so
an older build refuses such a replay as newer instead of failing to read
it. The 2D recorder runs over the new graphs.

## Acceptance criteria
- `REPLAY_FORMAT_VERSION` steps up once. The header's graph kinds include
  `hex` and `tri`, each with width and height and `SAMPLE_ARITY` 2. The
  graph description in the header rebuilds the graph and geometry.
- Every earlier version still decodes through its own decoder and an upgrade
  step; the recorded fixtures under `tests/fixtures/replays/` decode and
  verify unchanged. A replay of an unknown kind, or from a newer version, is
  refused with the newer version's reason.
- The recorder records actions, pauses, the cursor stream and pointer
  samples in the geometry's board units at Classic 2D's sampling interval
  for both modes, and the board code goes into the listing.
- A finished Hexagon or Triangle game hands its replay to the replay library
  like a Classic 2D one, and the results screen offers Watch replay.
