# Task 109 — Steam rank panel on the results screen

Target: claude+human

## Goal
Implement feature `results-steam-rank` in the framed results screen of the
shared layout: a non-interactive rank panel in the Steam build, for a won
game on a catalogue board, showing the global rank with its move and the
friends rank after an improving win, the standing "your best" ranks
otherwise, and offline wording when Steam does not answer in about 5
seconds; and the *Leaderboard* action that opens the leaderboard screen on
the game's board — both composed from catalogued kit components only.

## Acceptance criteria
- The panel sits in the results screen's framed body below the figure tiles
  (task 169's one-column layout) only when the leaderboards capability is present, the game was
  won and its board has a leaderboard; otherwise the screen keeps its
  shared-layout composition. It never takes focus or moves the default
  focus off *Play again*; text changes are announced politely.
- The panel is a section label over two stat tiles, global and friends,
  each with the rank as its figure and the move or "your best" as its
  detail line, composed from its supplied artboard with no styling of its
  own beyond placement and no rule added to any theme stylesheet; contrast
  checks pass under *Joyful tiles*.
- A resolver started by the results flow follows the summary's submission
  state: submitted → global rank with its move (#120 → #87, or "new entry")
  and friends rank from own standing; not eligible, already beaten or
  rejected by verification → own standing as "your best"; pending → keeps
  waiting.
- "ranking…" shows for up to about 5 seconds, then "Will be ranked when you
  are back online" for a pending win or "Rank unavailable offline"
  otherwise; a later answer still fills the panel while the screen is
  open. Leaving the screen stops the resolver and drops its subscription.
- A rejected query ends in the offline wording; the rest of the results
  screen is never blocked or delayed. Works the same for Classic 2D and 3D
  results.
- A *Leaderboard* action, with its key hint, follows *Records* among the
  results screen's actions when the leaderboards capability is present and
  the game's board has a leaderboard, after a won or a lost game; it never
  takes the default focus off *Play again*. It asks the shell to open the
  leaderboard screen with the shown summary's board identity; Back returns
  to the results screen, where the flow starts the panel again for the
  shown summary.
- No horizontal scroll at 1024 px wide; the results screen's element ids,
  default focus and controller navigation targets survive.
- `.claude/domain/features/results-steam-rank.md` drops the artboard from
  its open questions once supplied. Nothing else in it changes.
- Node tests drive the resolver through every state and the timeout with a
  fake leaderboards module and a fake clock, and check when the action is
  shown and the board identity it routes with; Playwright checks the web
  build shows no panel and no *Leaderboard* action.

## Decisions
- **Shared layout (2026-10-13):** the panel and the action sit in the
  framed results screen task 169 composes (`results-steam-rank.md`
  § Architecture), so this task waits on task 169. A component the artboard
  seems to need beyond the catalogue is not added here: compose from the
  catalogued ones and name the gap under *Follow-ups*.
- Settled here: the artboard open question
  (`.claude/domain/features/results-steam-rank.md` § Open questions), dropped
  once the artboard is supplied. The document is normally `/architect`'s;
  this task updates it for exactly this and for nothing else.
- **Waits on its artboard**, per `shared-screen-layout.md` § Architecture,
  *Design status per screen*: the results screen's artboard supplied for
  task 169 does not draw the panel or the action.
