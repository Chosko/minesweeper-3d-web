# Task 66 — Recorder and sealer

Target: claude

## Goal
Build the recorder and sealer of feature `replay-recording`: one recorder
per game session that keeps actions and movement samples on the game clock
in growable typed buffers, caps the movement stream, and at a win, loss or
abandon seals the replay with check values from the engine's final state.

## Acceptance criteria
- `startRecording(header fields known at board open)`; the mine set, seed
  and generator version are added when the board arrives.
- `action(kind, cell, time)` records every action handed to the engine while
  the game accepts actions, including ones that change nothing; actions
  before the timer starts carry time 0 and keep their order.
- `sample(values, time)` stores a sample only when it differs from the
  previous one; recording allocates nothing per event.
- The movement stream stops growing at the cap; the rest of the game is
  recorded as actions only and the header marks where movement ended.
  Actions are never dropped.
- `seal(summary, engine final state)` computes the check values, stamps the
  summary's id and returns the blob and its listing fields (id, board key,
  mode, outcome, time, 3BV/s, efficiency, end date, size); sealing twice
  returns the same replay.
- A recorder failure never interrupts play: the replay is dropped and the
  failure reported once.
- Node tests cover feeding, de-duplication, the cap, sealing and failure.
