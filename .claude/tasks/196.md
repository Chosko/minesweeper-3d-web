# Task 196 — Browser tests: root-cause and fix the flakes seen under full-suite load

Target: claude

## Goal
Several browser tests fail now and then when the whole suite runs
(`.claude/external/run-full-tests.sh`, concurrency 2, software-rendered
Chromium) and pass when run alone; each was seen during runbook
ux-review-tasks-implementation. A flaky test costs every later run a re-run
and hides real regressions. Each flake is root-caused and fixed so the test
passes reliably under load, using the suite's existing means — the timing
helpers in `tests/helpers/` (`patience()`, `timed()`, `MS_TIME_SLACK`),
waits that poll for a state instead of fixed windows or hard-coded
timeouts, and fixed boards where randomness is the cause. No test is
retried, skipped, quarantined or weakened to make it pass.

## Acceptance criteria
- Each of these is root-caused and fixed, with the cause named in the
  task's closing report:
  - `tests/shell-pad-walk.test.mjs` — the D-pad walk of the 2D and 3D board
    choices, and the Records walk;
  - `tests/shell-mode-3d.test.mjs` — "the 3D generating card shows by its
    delay…": its random no-guess first click can win outright (the test
    then never reaches the loss and Play again it expects), and the daily
    pre-generation may share the stubbed 3D worker at start-up and take
    the stub's first, fast board slot;
  - `tests/classic2d-touch.test.mjs` — the Classic 2D phone touch run
    (Expert played by touch);
  - the 2D replay-viewer browser test in `tests/replay-viewer.test.mjs` that
    failed under load, and `tests/shell-menu.test.mjs`'s "without WebGL 2"
    browser test — each investigated; where a cause is found it is fixed,
    and where none reproduces, its waits are brought onto `patience()` and
    state polling and that is said in the report.
- Fixes stay inside the tests and their helpers unless the cause is a real
  product race; a product race found this way is fixed in the product with
  its own test, never hidden by the test.
- No retry loop around a test or an assertion, no `skip`/`todo`, no raised
  `--test-timeout` and no lowered concurrency as the fix. A hard-coded wait
  timeout in a touched test becomes `patience(ms)`; a fixed sleep stays
  only where it proves something does not happen.
- Where randomness causes the flake, the test uses a fixed board (fixed
  mine positions or seed) that reaches the state the test needs.
- Evidence: the touched test files pass in several consecutive full-suite
  runs (`.claude/external/run-full-tests.sh`), and each alone under a raised
  load (for example `MS_TIME_SLACK=1` beside a parallel browser-tier run);
  the run counts go in the closing report.
- `.claude/context/testing-conventions.md` records any new convention the
  fixes establish (for example "a browser test that needs a loss plays a
  fixed board"); nothing else in the context layer changes unless a fix
  makes a passage stale.

## Decisions
- **One task for every flake**: they share the cause class (timing and
  randomness under load) and the means of fixing it, so investigating them
  together is cheaper than five tasks; the bare `node --test` scope is a
  separate task.
- **Investigated, not only patched**: the two seen-once flakes are included
  but may end with "no cause reproduced; waits made load-proof" rather
  than a named cause, since one sighting may not reproduce.
