# Task 97 — Steam submitter, best cache, reader and replay fetcher

Target: claude+human

## Goal
Connect feature `steam-leaderboards` to Steam through the desktop host's
bridge: the submitter that shares the replay, uploads the score with
details and attaches the file; the player's best cache; the reader for
global, friends and around-me entries and own standing; and the replay
fetcher that checks a downloaded replay against its entry before handing
it to `replay-playback`.

## Acceptance criteria
- Submitter: writes the replay to Steam remote storage under the file name
  rule task 88 recorded, shares it, uploads score and details keeping the
  best, and attaches the file when Steam reports an improvement; a score
  Steam already beat is dropped; `offline` or `failed` leaves the entry for
  the next flush; `not-found` drops it and logs once. Submitted state
  carries the global rank before and after.
- Best cache: the player's score per leaderboard, read once logged on and
  updated after each upload; feeds eligibility.
- `entries(board, scope, range)` returns entries (rank, player id and name,
  score, details, replay handle) and the total count for global, friends
  and around-me; `standing(board)` returns score and global and friends
  rank, or none.
- `replayFor(entry)` downloads, decodes with `replay-recording`'s decoder,
  checks the header's board and the check-value time against the entry, and
  returns the replay or a reason: no replay attached, download failed,
  unreadable, or does not match.
- With the leaderboards capability off, queries reject with that reason and
  submissions wait in the outbox.
- Node tests run all of it against a fake bridge.
