# Task 112 — Classic 2D and 3D input read their actions through the bindings

Target: claude

## Goal
Make every mode's input of feature `input-rebinding` ask the bindings
resolver which action a key, mouse button or controller button means,
instead of testing fixed codes, so a rebinding takes effect from the next
input — with every rule, gesture and default feel unchanged.

## Acceptance criteria
- 3D: the move keys, the held view modes and the controller's buttons are
  translated through the resolver before the controls union reads them;
  physical mouse buttons and the controller triggers are translated to the
  logical buttons `MouseActions` works on, so chord-on-release semantics are
  untouched.
- Classic 2D: the pointer state machine receives logical buttons from the
  resolver, and a mouse button bound directly to chord feeds the same chord
  action; the cell cursor's reveal, flag, chord and move inputs come from
  the resolver.
- Reserved inputs keep their shell and shortcut meanings in both modes.
- An input held when its binding changes is dropped, not fired.
- With no overrides, behaviour is identical to before: the Classic 2D
  fidelity tests (task 37), the 3D input tests and the existing Playwright
  checks pass unchanged.
- Node tests cover a swapped mouse (reveal on the right button, flag on the
  left, chord still on both), a rebound move key and a rebound controller
  button in each mode; a Playwright check plays a fixed Classic 2D board to
  a win with rebound keyboard keys.
