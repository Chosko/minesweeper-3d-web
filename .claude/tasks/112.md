# Task 112 — Classic 2D and 3D input read their actions through the bindings

Target: claude

## Goal
Make every mode's input of feature `input-rebinding` ask the bindings
resolver which action a key, mouse button or controller button means,
instead of testing fixed codes, so a rebinding takes effect from the next
input — with every rule, gesture and default feel unchanged.

## Acceptance criteria
- 3D: the move keys, the held view modes and the controller's buttons are
  translated through the resolver before the controls union reads them;
  physical mouse buttons and the controller triggers are translated to the
  logical buttons `MouseActions` works on, so chord-on-release semantics are
  untouched.
- The flat modes: Classic 2D's pointer state machine receives logical
  buttons from the resolver, and a mouse button bound directly to chord
  feeds the same chord action; the cell cursor's reveal, flag, chord and
  move inputs come from the resolver. Hexagon and Triangle play on the same
  input layer and read the same flat-mode bindings.
- Reserved inputs keep their shell and shortcut meanings in both modes and
  are handled ahead of the bindings, never translated through them: Esc and
  Back, F2 (restart in play and on the pause card), R on the results screen
  (play again), the 3D camera return, help, sound, fullscreen and the 3D
  spacing buttons.
- The Start + Y chord stays away from the bindings: Y pressed while Start is
  held restarts (`restartInput('pad', …)`) in play and on the pause card and
  is not translated through the resolver, whatever action Y is bound to; Y
  pressed on its own produces its bound action (by default the 3D Ctrl view
  mode's hold, and Classic 2D's chord).
- An input held when its binding changes is dropped, not fired.
- With no overrides, behaviour is identical to before: the Classic 2D
  fidelity tests (task 37), the 3D input tests and the existing Playwright
  checks pass unchanged.
- Node tests cover a swapped mouse (reveal on the right button, flag on the
  left, chord still on both), a rebound move key and a rebound controller
  button in each mode, Start + Y restarting with Y bound to another action
  while Y alone still fires that action, and F2 and R keeping their restart
  and play-again meaning with no binding reaching them; a Playwright check
  plays a fixed Classic 2D board to a win with rebound keyboard keys, and a
  key rebound for the flat modes reveals on a Hexagon board too.

## Decisions
- Settled here, against `.claude/domain/features/input-rebinding.md`
  § Interfaces and contracts → Reserved inputs: Y alone stays rebindable,
  so the resolver cannot refuse the Start + Y chord; the input layers keep
  it by testing the chord (and F2, and R on the results screen) before any
  resolver lookup, as `main.js` already orders `restartKey` and the pad's
  restart test ahead of play input.
