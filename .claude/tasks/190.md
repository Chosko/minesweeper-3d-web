# Task 190 — Classic 2D overlay bar fits a phone: Pause and Reveal / Flag on screen

Target: claude

## Goal
Make every control of the Classic 2D overlay bar reachable on a phone. The
UX review drift audit (`docs/UX_REVIEW_DRIFT.md`, "Five most important
findings" #1, § 1 row P-37 "defective", § 2 decision 11 "defective") found
that at 390 px the 2D overlay bar is about 545 px wide (`.hud-bar`,
css/style.css), so the Reveal / Flag switch `#hud-tap` (right edge 469 px)
and Pause `#hud-pause` (489–570 px) sit beyond the right edge of the screen.
A touch player cannot pause, and cannot flag except by long-press. The
mouse-only *Swap clicks* toggle `#hud-swap` also shows on touch, where it
does nothing useful and takes width the bar does not have. Decision 11 of
`docs/UX_REVIEW.md` ("Touch a target? Yes") and P-37's approved solution
("a 44 px Reveal / Flag switch sits in the overlay bar") require both
controls to be usable; this task delivers that on phone widths. Mouse,
keyboard and controller layouts on desktop stay as they are.

Steps to reproduce (from the audit): Playwright or DevTools with 390 × 844
touch emulation (`hasTouch`, `isMobile`) → main menu → Classic 2D → any
size → the bar runs off the right edge, ending in a sliver;
`page.tap('#hud-pause')` fails with "outside of the viewport".

## Acceptance criteria
- On a 390 × 844 and a 360 × 740 touch phone (portrait), in a Classic 2D
  game on every standard board and a custom board, every visible control
  and readout of the 2D overlay bar — time, mines, clicks, board size,
  Reveal / Flag switch, Pause — has its bounding box fully inside the
  viewport, and `#hud-pause` and `#hud-tap` take a tap (a tap on Pause
  opens the pause card; a tap on the switch flips "Tap: Reveal" /
  "Tap: Flag").
- At those widths the bar wraps or shrinks (for example the readouts
  stacked on one row and the switch and Pause on another, or tighter
  padding) rather than overflowing. The Reveal / Flag switch keeps its 44 px
  hit area (P-45's coarse-pointer size).
- *Swap clicks* (`#hud-swap`) is hidden on a coarse-only device — a
  coarse primary pointer and no fine pointer, the same test as `main.js`'s
  `COARSE_ONLY`. A device with a fine pointer (desktop, or a touchscreen
  laptop driven by a mouse) still shows it in Classic 2D, unchanged.
- The board's framed panel still sits below the bar with no overlap at
  phone widths: the panel geometry (`panelFrame2D`, `placePanel2D`) uses the
  bar's actual height when it wraps to more than one row.
- At 1024 × 768 and wider with a mouse, the 2D overlay bar, the framed
  panel and the 3D overlay bar render as before (same controls, same
  layout); the 3D bar at 390 px keeps Pause on-screen as it does today.
- **Tests first**: `tests/classic2d-touch.test.mjs`'s phone run gains a
  viewport-containment assertion — the bounding box of every visible child
  of the 2D overlay bar lies inside the viewport at 390 × 844 and
  360 × 740 — plus a real tap on `#hud-pause` and `#hud-tap`, and an
  assertion that `#hud-swap` is not visible there. A mouse run at
  1280 × 800 asserts `#hud-swap` visible in Classic 2D. The test fails on
  the current build and passes after the change.
- `.claude/domain/features/classic-2d-square-play.md` (§ Scope, the
  *Swap clicks* bullet) and `.claude/domain/features/screen-components.md`
  (§ Architecture, "Overlay bar") state the agreed design change — *Swap
  clicks* shows only where a fine pointer exists, and the 2D overlay bar
  wraps to fit a phone's width — in every passage that stated the old one,
  and settle the wrap. Nothing else in those documents changes.

## Decisions
- **Design change agreed (user decision, 2026-10-15)**, by prior
  instruction: the user approved turning the audit's findings into tasks,
  and the audit's "what to do" for P-37 prescribes exactly this fix ("Let
  the 2D bar wrap or shrink at phone widths (stack the readouts, hide *Swap
  clicks* on coarse-only pointers)").
  - `classic-2d-square-play.md` § Scope says the *Swap clicks* toggle
    "shows only while the game is unpaused"; it also hides on a coarse-only
    device, since it trades mouse buttons and a coarse-only device has no
    mouse.
  - Settled here, without conflict: `screen-components.md` § Architecture,
    "Overlay bar" does not state the bar's layout at narrow widths; it wraps
    to fit.
  These documents are normally `/architect`'s; this task updates them for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- **"Coarse-only" is `COARSE_ONLY`'s test** (`(pointer: coarse)` and not
  `(pointer: fine)`), not plain `(pointer: coarse)`, so a hybrid device with
  a mouse keeps the toggle — the same rule task 142 used for the 3D notice.
- **How the bar fits is the implementer's call** (wrap, stack or tighten),
  judged by the containment test; no control is removed other than *Swap
  clicks* on coarse-only devices.
- **Decision 11 closes with this task**: the audit's decision-11 row says
  "Fix P-37's bar overflow", nothing more.
