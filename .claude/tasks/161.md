# Task 161 — Theme conformance tests and the component gallery per theme

Target: claude

## Goal
Make "a theme is done" a mechanical fact, for feature `theme-system`: a
conformance suite, run in the ordinary test suite for every registered theme,
that fails the suite when any theme breaks the contract; and a development
gallery that renders every component in every state and decoration slot under
any registered theme, which the theme skill screenshots against the artboards.

## Acceptance criteria
- **Conformance suite** `tests/theme-conformance.test.mjs` iterates the
  registry and, per theme, checks:
  - every file the registry names exists, and every `@font-face` source in
    the stylesheet is one of the theme's own files; no theme file holds a
    remote URL (`http:`, `https:`, `//`);
  - every rule of the stylesheet is scoped to the theme's id;
  - every required token is declared (the required set is declared once,
    beside the kit catalogue, and is what the base stylesheet and the
    screens read);
  - every part and state of every catalogued component has a rule, and every
    interactive part has a visible focus style;
  - every decoration slot the theme fills is a catalogued slot;
  - the DOM contrast checks: body text on each surface token at least 4.5:1,
    large text and essential glyphs at least 3:1;
  - in a browser, the gallery renders under the theme with no missing font,
    no failed request and no console error.
- **Board checks hook.** The suite has a named per-theme case for the board
  module's conformance, marked to-do with the reason that its checks are
  defined by `themed-board-art-and-motion`; that feature's task turns it on.
- **Proves it bites.** A test runs the checks against deliberately broken
  fixture themes (an unscoped rule, a missing token, a missing part state, a
  remote font URL, an uncatalogued slot) and asserts each is caught.
- **Gallery per theme.** `dev/components.html` takes a theme from the
  registry through a picker and a `?theme=<id>` query parameter, applies it
  with the applier, and renders every catalogued component in every state
  (the `data-force` previews) and every decoration slot shown. An unknown id
  falls back to the default.
- *Joyful tiles* passes every check.

## Decisions
- **Board checks deferred by a to-do case**, not a dependency: the
  theme-system tasks do not wait on `themed-board-art-and-motion`, which
  enables the case when its board checks exist.
- **The required token set is declared as data** beside the kit catalogue,
  so the conformance suite and the theme skill read one list.
- **Settled design detail** (`.claude/domain/features/theme-system.md`
  § Architecture, *Conformance tests*, *Component gallery*): the to-do board
  case and the required-token list's home. The feature document is not
  edited here; task 162 records what holds at ship time.
