# Task 214 — Full test runs reliable again: the stale counter test, the random first click, the theme-switch flakes and the slow components file

Target: claude

## Goal
These tests fail on `main` for reasons outside the code the recent steps
touched, so every full run (`.claude/external/run-full-tests.sh`) and every
slow-tier run (`.claude/external/run-slow-tests.sh`) needs a re-run or a
by-hand excuse, which hides real regressions. Each is fixed at its cause so
the fast, browser and slow tiers pass reliably under load, with the suite's
existing means — the timing helpers in `tests/helpers/` (`patience()`,
`timed()`, `MS_TIME_SLACK`), waits that poll for a state, and fixed boards
where randomness is the cause. No test is retried, skipped, quarantined or
weakened to make it pass.

## Acceptance criteria
- `tests/render-3d-flag-flash.test.mjs` (`[slow]`): the mines counter
  assertion expects the counter readout's current zero-padded form (`-03`
  for three below zero), taken from the counter readout's own formatting
  rather than restated where a helper exposes it; the rest of the test is
  unchanged and it passes in the slow tier.
- `tests/classic2d-mode.test.mjs`, "in a browser, a few moves on a board
  with a best": the game is played on a fixed board (fixed mine positions,
  seed or board code) whose first click on the chosen cell opens an area,
  so every assertion holds on every run; the board's best and its figures
  in the test still agree with that board.
- The theme-switch browser tests in `tests/classic2d-view.test.mjs` ("a
  theme switch and a large scrolled custom board…" and "switching between
  Joyful tiles and a fixture theme mid-game…") and `tests/theme.test.mjs`
  ("a switch between Joyful tiles and the fixture theme never shows two
  themes or no stylesheet") are root-caused, with the cause named in the
  task's closing report, and fixed. A cause in the product (a race in the
  theme applier, the board art hand-off or a redraw) is fixed in the
  product with its own test, never hidden by the test.
- `tests/components.test.mjs` finishes with clear headroom under the full
  run's timeout at the full run's concurrency: its browser tests are split
  by area into further `components-*.test.mjs` files (the
  `components-game3d` pattern), or its browser work is shared or trimmed
  without dropping a check. Every check it holds today is still held
  somewhere; the affected-tests mapping and the shell smoke set
  (`SHELL_SMOKE`) still select the moved tests for the changes that select
  them today.
- No retry loop around a test or an assertion, no `skip`/`todo`, no raised
  `--test-timeout` and no lowered concurrency as the fix. A hard-coded wait
  timeout in a touched test becomes `patience(ms)`; a fixed sleep stays
  only where it proves something does not happen.
- Evidence: the touched test files pass in several consecutive full-suite
  runs, the flag-flash file passes in a slow-tier run, and each touched
  file passes alone under raised load (for example `MS_TIME_SLACK=1` beside
  a parallel browser-tier run); the run counts and `components`' wall
  times before and after go in the closing report.
- `.claude/context/testing.md` names any new `components-*` file in its
  table; `.claude/context/testing-conventions.md` records any new
  convention the fixes establish. Nothing else in the context layer
  changes unless a fix makes a passage stale.

## Decisions
- **One task for all four**: they share the cause class (tests behind the
  product, randomness and load) and the means of fixing them, and together
  they are what keeps full runs from being trusted.
- **Theme-switch flakes and the Chromium font unload**: the font unload
  has its own task. If a theme-switch flake's cause turns out to be that
  unload, this task fixes it in the product with its own test (the rule
  above), and the font task's closing report says it was covered here.
