# Task 202 — Records Averages table stays inside its panel on a phone

Target: claude

## Goal
On the Records screen, the Averages panel's table (`#records-averages-table`,
rows Time, 3BV/s and Efficiency built by `showAverages` in
`js/records/screen.js` into `#records-averages-body`; columns Last 10,
Last 50, All) grows wider than its panel on a narrow screen when a time has
three digits before the decimal point (e.g. "502.426 s"), so the whole page
scrolls sideways. Its cells already keep one line (`white-space: nowrap`),
which is what pushes the table out. The other Records tables (recent games,
Top 10, replays) stack each row's cells under their `data-label` inside a
container query on their panels (`css/style.css`); the Averages table sits
in a panel outside that container and was left out. Make it fit its panel
at phone widths, in both themes, with figures still on one line.

## Acceptance criteria
- At 390 × 844 and 360 × 800, in both themes and both modes' Records, with
  an averages time of three digits before the decimal point in every column
  (e.g. "502.426 s", and "Last 50 (12)" as a column label), the Averages
  table's border box lies inside `#records-averages`'s content box, the page
  does not scroll sideways (`document.documentElement.scrollWidth` equals
  the viewport width), and every figure cell is one line high.
- At phone widths the table reuses the stacked layout the other Records
  tables use where it fits — each row's cells under their column's name
  (`data-label`, which `cells()` already sets), the row's label as the
  card's heading — triggered by a container query on `#records-averages`;
  a narrower variant is acceptable only if the stacked form does not fit.
- At 1024 px and wider the Averages table keeps its current table layout.
- **Tests first**: a browser test in tests/records-screen.test.mjs seeds a
  board whose won games average over 500 s, opens Records at 390 × 844 in
  both themes, and asserts the containment, no sideways scroll and one-line
  figures above. It fails on the current build.

## Decisions
- **Reuse task 193's stacked cards**, not a smaller font or a scrolling
  wrapper: the user asked for the other tables' layout where it fits, and it
  keeps the figures legible and on one line.
- Settled without conflict: `.claude/domain/features/records-screen.md`
  § Architecture, "Averages" describes a small table of means and does not
  fix its layout at narrow widths; the document does not change.
