# Task 65 — Replay format: header, streams, encoder and decoder

Target: claude

## Goal
Define the replay format of feature `replay-recording`: a versioned binary
blob with a header describing the board, its mines and the rules it was
played under, a delta-encoded action stream and movement stream, and check
values — with the encoder and the decoder `replay-playback` shares.

## Acceptance criteria
- The header holds format version, replay id (the summary's id), mode and
  graph description (square: width, height; box: X, Y, Z), board identity,
  mine set as cell indices, rule profile and rules version, seed and
  generator version, end date, and where movement ended when it was capped.
- Actions encode time (ms on the game clock), kind (reveal, toggle flag,
  chord) and cell index; movement encodes time and the mode's sample values
  plus the 2D cursor-cell and 3D view-mode change events; both are
  delta-encoded.
- Check values hold outcome, elapsed time, 3BV, 3BV solved, click counts by
  kind and a digest of the final per-cell state (revealed, flagged, hidden).
- The decoder reads every known format version through a per-version
  upgrade path, refuses a newer version with a distinct error, and reports
  an unreadable blob as unreadable.
- Encode → decode round-trips exactly; Node tests cover 2D and 3D headers,
  an empty movement stream, a capped one, a newer version and a corrupt
  blob.
