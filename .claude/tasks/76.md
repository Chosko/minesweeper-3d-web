# Task 76 — Replay simulator and verifier

Target: claude

## Goal
Build the headless core of feature `replay-playback`: a DOM-free simulator
that replays a decoded replay on the engine under its recorded profile and
rules version to any point in time, with snapshots for quick seeking on
large boards, and a verifier that checks every replay against its check
values before it is played.

## Acceptance criteria
- `simulate(replay, upTo)` builds the graph from the header, creates the
  game from the header's mine set under the recorded profile and rules
  version, applies the action stream up to `upTo`, and returns the game
  state and the cells changed; it is pure and deterministic in the browser
  and in Node.
- Seeking backwards replays from the nearest snapshot; on large boards the
  simulator keeps periodic engine-state snapshots.
- `verify(replay)` runs to the end without drawing and returns "reproduces"
  or the first check value that differs.
- A replay from a newer format version, or naming a rules version this
  build does not have, is refused with a "made by a newer version" reason;
  an unreadable one with its own reason.
- The snapshot interval is set by measuring seek time and memory on the
  largest 3D boards, and `.claude/domain/features/replay-playback.md` records
  it in place of that open question. Nothing else in the document changes.
- Node tests cover simulate at several times, backward seeks, verify on the
  recorded fixtures from task 69, a tampered replay and each refusal.

## Decisions
- Settled here: the feature document's open question on the snapshot
  interval, by measurement. `.claude/domain/features/replay-playback.md` is
  normally `/architect`'s; this task updates it for exactly this and for
  nothing else. The questions on a free 3D camera and on sound stay open;
  the viewer follows the recorded camera and is silent.
