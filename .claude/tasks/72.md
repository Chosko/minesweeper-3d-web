# Task 72 — Replay library: index, retention, pinning and recovery

Target: claude

## Goal
Build the library of feature `replay-library`: the only writer of the
replay store and of a versioned library index document, with add, the
newest-100 retention across both modes, best and hand pinning, start-up
reconciliation, change notification and the failure rules.

## Acceptance criteria
- The library index is a document registered with `platform-storage`, with
  its own format version, listing each kept replay's id, board key, mode,
  outcome, time, 3BV/s, efficiency, end date, size and pin reasons (best, by
  hand).
- `add(replay, listing fields, setBest)` writes the blob, then the index
  entry, then applies retention; adding the same id twice is a no-op; a game
  that set a best is pinned with the reason "best".
- Retention keeps every pinned replay and the newest 100 unpinned by end
  date, deleting the oldest first, after each add and unpin; pinned replays
  are never deleted by retention or a storage failure.
- Pin sets the hand-pin reason; unpin clears every reason and applies
  retention.
- Queries: the replays kept for a board key, whether a summary id has a kept
  replay, a replay's bytes by id. Subscribers are told after each add, pin,
  unpin and removal.
- At start-up the index is loaded once and reconciled with the store: a blob
  with no entry is deleted, an entry with no blob is dropped.
- When the store or the index cannot persist, the library works in memory
  and reports it; a failed blob write leaves no entry, is reported once and
  keeps the replay in memory for the session; a refused newer index version
  leaves stored data untouched and saves nothing.
- Node tests cover every rule above on the in-memory store.
