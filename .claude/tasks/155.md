# Task 155 — Load-robust timing tests and one shared Chromium per test file

Target: claude

## Goal
Make the timing-sensitive tests pass reliably under load, and give every
browser test file one shared Chromium. On the 4-core cloud box with no GPU,
WebGL is software-rendered by SwiftShader and each browser test's GPU process
pins a core. Under that contention several timing assertions fail
intermittently in a full run and pass when run alone, and every
implementation step of runbook 5 has reported one or more of them as flaky.
This task gives those assertions slack so they measure what they mean to
measure, replaces the fixed sleeps that wait for a state with polling, and
replaces the copy-pasted static server, Playwright loader and per-test
`chromium.launch` in the 36 browser test files with one shared helper. Every
part of this scope was approved by the owner.

## Acceptance criteria
- **Timing assertions tolerate contention.** Each of these keeps its intent
  and no longer fails under load:
  - `tests/engine-3d-profile.test.mjs`: the 100 × 100 × 100 build-and-open
    check under 2 s (around line 163);
  - `tests/engine-graph.test.mjs`: the 1000 × 1000 grid build under 1 s
    (around line 154);
  - `tests/generation-solver.test.mjs`: the slowest Expert solve under
    500 ms (around line 262);
  - `tests/records-history.test.mjs`: "paging a long history stays fast",
    under 500 ms (around line 237);
  - `tests/render-3d-flag-flash.test.mjs`: the flash's upper bound of
    `FLASH_S` + 2 frame gaps + 50 ms (around line 181);
  - `tests/mode3d-end.test.mjs`: the frame-gap condition around line 516 and
    its waits for the results screen across `END_DELAY_MS`;
  - `tests/replay-viewer-3d.test.mjs`: the waits behind "a seek leaves no
    pulsing cube" and "a recorded 3D replay plays from its fixture through
    to the end".
  For each, the implementer chooses a multiplier on the budget, a load-aware
  budget (for example scaled by a measured baseline operation), or polling
  with a generous timeout in place of a fixed window. A lower bound such as
  "not before the flash has played" stays exact.
- **The performance assertions still catch a real regression.** None is
  deleted, and each still fails when its work grows several times over its
  budget; the closing report shows one such failure, produced by temporarily
  inflating the work and then reverting it.
- **A shared browser helper** at `tests/helpers/browser.mjs` (or a similarly
  named module under `tests/helpers/`) provides:
  - the Playwright loader: `import('playwright')`, falling back to the
    global install next to the Node binary, the caller skipping its tests
    when neither exists. The fallback looks in both global-module layouts:
    the Windows one, `node_modules` in the Node binary's own directory (for
    example `C:/Program Files/nodejs/node_modules`), and the POSIX one,
    `../lib/node_modules` relative to the binary's directory. The copied
    loaders look only in the POSIX one, so every browser test skips on
    Windows;
  - the launch flags `--use-gl=angle --use-angle=swiftshader
    --enable-unsafe-swiftshader` as one constant;
  - one Chromium per test file, launched once and closed once (for example
    from `before` / `after` hooks), with a fresh browser context for every
    test;
  - one static server per file serving the repository root, replacing the
    `createServer` block each browser file carries.
- **All 36 browser test files use the helper**, and no `chromium.launch` or
  `createServer` call remains in any test file outside `tests/helpers/`.
  Each converted file keeps its tests' intent and passes.
- **Browser tests run on Windows with a global Playwright.** On a Windows
  machine where Playwright is installed only globally, the browser test
  files load it through the helper and none of their tests skips.
- **Chromium launches per full run drop** from about 60 to one per browser
  test file; the closing report states how this was counted.
- **Fixed sleeps that wait for a state become polls**, at least
  `tests/classic2d-mode.test.mjs` around line 1150 (1200 ms, the clock
  advancing while paused) and `tests/shell-mode-3d.test.mjs` around line 450
  (1100 ms). A wait that proves something never appears may stay a fixed
  window.
- **Three consecutive full runs pass** of `.claude/external/run-full-tests.sh`
  on the 4-core cloud box with no intermittent failure, each run's wall time
  recorded in the closing report.
- `.claude/context/testing.md` describes the helper, the rule that browser
  test files go through it, and how the timing assertions get their slack
  (and any environment variable that tunes it); `README.md` § Tests names that
  variable when one exists.

## Decisions
- **One task, after task 154.** Task 154 edits the page setup of 18 of the
  same browser files (the backdrop mechanism, the opt-in screenshots in
  `tests/components.test.mjs`) and the full runner's timeout. Doing this
  conversion second avoids conflicting edits to the same setup code and lets
  the helper absorb whichever backdrop mechanism 154 settles on.
- **Launch flags per file.** A file whose tests all launch bare today may
  keep a bare launch through the helper; a file that mixes bare and flagged
  launches (`components`, `replay-viewer`, `shell-menu`, `shell-returning`)
  uses the SwiftShader flags for its one browser. Its no-WebGL-2 tests get
  that condition from the WebGL-2-refusing init script on their own context,
  which the flags do not affect.
- **The investigation's report lives outside the repo**, so the facts this
  task needs (the timing sites, the sleeps, the launch counts) are carried
  in this body; the implementer re-checks them rather than trusting the
  line numbers.
