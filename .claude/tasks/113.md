# Task 113 — Rebinding controls on the Settings page

Target: claude+human

## Goal
Turn the framed Settings page's read-only bindings list into the rebinding
controls of feature `input-rebinding`: one panel per mode with a tab per
device, each action's inputs as slots, capture of the next input, clashes,
reserved inputs and last-binding refusals reported in place, and Reset to
defaults per mode and device — composed from catalogued kit components only.

## Acceptance criteria
- The Controls section of the framed Settings page shows a Classic 2D and a
  3D panel, each under its section label with Keyboard, Mouse and
  Controller tabs; each action is a list row whose slots are key hints
  labelled from the current bindings (key names from the keyboard layout
  where the browser provides it, else from the code; controller buttons
  with the connected pad's glyphs).
- The panels are composed from their supplied artboard using catalogued kit
  components only, with no styling of their own beyond placement and no
  rule added to any theme stylesheet; contrast checks pass under *Joyful
  tiles*, and no horizontal scroll at 1024 px wide.
- Choosing a slot opens capture; the next key, mouse button or controller
  button of that tab's device fills it through `bind`; the shell's Back
  input cancels capture and nothing else leaves it.
- A swap names the action that took the replaced input; a reserved input or
  a refused clear says why, and the binding is unchanged.
- Reset to defaults restores the panel's mode and device.
- The page stays fully operable by mouse, keyboard and controller, with a
  declared default focus; the Settings page's element ids, route and
  controller navigation targets survive.
- `.claude/domain/features/input-rebinding.md` drops the artboard from its
  open questions once supplied. Nothing else in it changes.
- Node tests cover capture state and messages with fakes; Playwright
  rebinds a 3D move key and a Classic 2D reveal key, reloads, finds them
  kept, and resets them.
