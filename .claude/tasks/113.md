# Task 113 — Rebinding controls on the Settings page

Target: claude

## Goal
Turn the Settings page's read-only bindings list into the rebinding
controls of feature `input-rebinding`: one panel per mode with a tab per
device, each action's inputs as slots, capture of the next input, clashes,
reserved inputs and last-binding refusals reported in place, and Reset to
defaults per mode and device.

## Acceptance criteria
- The Controls section shows a Classic 2D and a 3D panel, each with
  Keyboard, Mouse and Controller tabs, built from the screen kit; each
  action shows its slots labelled from the current bindings (key names from
  the keyboard layout where the browser provides it, else from the code;
  controller buttons with the connected pad's glyphs).
- Choosing a slot opens capture; the next key, mouse button or controller
  button of that tab's device fills it through `bind`; the shell's Back
  input cancels capture and nothing else leaves it.
- A swap names the action that took the replaced input; a reserved input or
  a refused clear says why, and the binding is unchanged.
- Reset to defaults restores the panel's mode and device.
- The page stays fully operable by mouse, keyboard and controller, with a
  declared default focus.
- Node tests cover capture state and messages with fakes; Playwright
  rebinds a 3D move key and a Classic 2D reveal key, reloads, finds them
  kept, and resets them.
