# Task 162 — Update documentation for feature `theme-system`

Target: claude

## Goal
Feature `theme-system` replaced the light and dark looks with a theme
catalogue: a registry, a kit catalogue as data, a base stylesheet plus a
per-theme stylesheet, self-hosted fonts, a registry-driven applier, the
Settings theme list and conformance tests. The documentation describing that area
still describes tokens with a light and a dark value, the light/dark applier
and the gallery's theme switch, and needs to reflect the shipped behaviour.

## Acceptance criteria
- `.claude/context/app-shell-kit.md` describes the theme registry, the kit
  catalogue, the base and theme stylesheets and the head order, the applier
  and its board module hand-off, the token reader, the failure contract and
  the per-theme gallery; nothing in it names a light or dark theme.
- `.claude/context/settings.md` describes the theme setting as a registry id,
  the format step's `light` / `dark` carry-over, the theme list, and the
  absence of any reduced-motion setting until `m7-after-launch` — the base
  stylesheet's shipped `prefers-reduced-motion` rule is the one
  reduced-motion behaviour, and cell motion ignores the preference.
- `.claude/context/testing.md` lists the registry and conformance tests and
  the rewritten token, theme, components and settings tests.
- `.claude/context/rendering.md` says where the sky stops come from now.
- `.claude/context/INDEX.md` rows for the touched files say what they cover
  now, with `Last updated` advanced.
- `README.md` changes only where it names the light and dark themes or the
  theme files.
- `.claude/domain/features/theme-system.md` records the details tasks
  157–161 settled that hold at ship time (theme folder and module paths, the
  pre-paint mirrored table, the required-token
  list beside the kit catalogue); the board module placeholder and the
  to-do board check are recorded only if `themed-board-art-and-motion` has
  not replaced them. Nothing else in it changes.
- `.claude/domain/features/design-tokens-and-themes.md` and
  `.claude/domain/features/settings.md` state the agreed design change — the
  light and dark themes are removed and the visual values, the theme applier
  and the theme setting are now `theme-system`'s — in every passage that
  stated the old design, by citing `theme-system.md` there rather than
  restating it. Nothing else in those documents changes.

## Decisions
- **Design change agreed (user decision, 2026-10-13, by the runbook's
  standing answer to take the draft's recommendation):** in
  `design-tokens-and-themes.md` and `settings.md`, every passage stating a light and a dark theme, light/dark token values, the
  light/dark applier or the light/dark theme setting now cites
  `theme-system.md` as the design that replaced it. These documents are
  normally `/architect`'s; this task updates them for exactly this and for
  nothing else. A further design decision met at implementation time is not
  covered: leave that passage untouched and name it under *Follow-ups* as a
  precise follow-up.
- **`technical-direction.md` is not edited**: self-hosted per-theme fonts and
  per-theme drawing belong there on the next `/product-design` pass, as
  `theme-system.md` § Architecture says; that document is `/product-design`'s.
- **`screen-components.md` is not edited**: it already speaks of every
  theme and cites `theme-system` wherever a theme's look is concerned, and
  it stays `/architect`'s.
