# Task 44 — Records store: persistence, recovery and the abandoned-game hook

Target: claude

## Goal
Persist feature `personal-records` through platform storage: a records store
that loads the records and history documents once at start-up, is the only
writer, records each summary in memory then saves, notifies subscribers,
recovers bests and counters from the history, and handles unavailable
storage and a newer records format — and attach it to the game shell's
abandoned-game hook.

## Acceptance criteria
- Records and history documents are registered with `platform-storage` under
  their own names at version 1 and loaded once at start-up.
- `record(summary)` → comparison updates memory first, then saves both
  documents; a failed save keeps the session's records correct and is
  reported once.
- When the records document is missing or corrupt and the history is
  intact, bests and counters are rebuilt from the history.
- `onChange(listener)` fires after each recorded game.
- When storage reports nothing will persist, records work for the session
  and `available()` says so.
- A refused newer records version leaves the stored documents untouched and
  runs the session with empty, unsaved records.
- The game shell's abandoned-game hook records the summary.
- A game ended by closing the window or tab is not recorded (the feature
  document's open question stays open).
- Node tests cover all of the above on the in-memory backend.
