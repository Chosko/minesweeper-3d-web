# Task 290 — Natural screen sizes

Target: claude

## Goal
For feature `shared-screen-layout`: give each non-game screen its
**natural size** — the size its desktop artboard on the canvas draws — so
the frame no longer fills the window. The frame takes its natural size
within the available area (task 289), centred on the backdrop, and its
content shrinks to fit when the natural size does not, never growing past
it. This is what the desktop window is later sized to (task 86), and on the
web the screens appear at that size on the dotted background.

## Acceptance criteria
- The main menu, the board choice screens (Classic 2D, Hexagon, Triangle,
  3D), Daily, Records, Settings, the results screen, the replay viewer, the
  pause card, the 3D ready card, the message and status cards, the
  confirmations, the placeholder screen and the 404 page each take the
  frame size their desktop artboard draws at the desktop step, and at the
  compact step the compact artboard's, read from the canvas
  https://claude.ai/artifact/LeP32jxNxEnHLUtRwJ3FNC.
- A screen whose natural size exceeds the available area shrinks to fit,
  its body scrolling vertically when needed; none grows past its natural
  size on a larger area.
- A screen that grows with its content keeps doing so up to the available
  area — the board choice frame widening when its panel opens.
- The touch step keeps today's layout.
- Browser tests assert each listed screen's frame size at a desktop and a
  compact available area against the artboard values, and that the frame
  is centred on the backdrop.

## Decisions
- **Artboard sizes are the source**: the owner chose the canvas's desktop
  artboards over fixed widths chosen in the feature document.
- **The main menu stops filling the window** on the web too; that is the
  intended visible change.
