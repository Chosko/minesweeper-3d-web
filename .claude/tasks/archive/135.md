# Task 135 — 2D sound

Status: [DONE]
Files: js/classic2d/mode.js, js/main.js, tests/classic2d-mode.test.mjs, .claude/domain/features/classic-2d-square-play.md

Target: claude

## Goal
Give Classic 2D the sound 3D already has. This is row W-09 of
`docs/UX_REVIEW.md` § Approved scope and work plan (Area: Classic 2D, Size:
Small, Phase 2). It closes one row of that document, P-62 (Major, every
Classic 2D player): Classic 2D has no sound at all; reveal, flag, chord,
no-op, explosion and win are silent, while 3D has a synthesized cue for each.
The approved solution, verbatim: "Play the same synthesized cues as 3D for
the same actions, driven by the same volume and mute settings." Classic 2D
therefore plays the existing cues of `js/audio.js` (`reveal`, `flag`,
`chord`, `noop`, `explode`, `win`) for the same actions and outcomes the 3D
game plays them for, from mouse, keyboard and controller input alike, at the
master volume and mute the settings store already applies. No cue is added
or retuned and 3D sound is unchanged.

## Acceptance criteria
- **The same cue for the same outcome** (P-62). Every action the Classic 2D
  session takes, from the pointer input or the cursor input (keyboard and
  controller), plays the cue 3D's `actionSounds` / `endGame` in `js/main.js`
  plays for that outcome:
  - a reveal that opens cells: `reveal(count)`, `count` the cells it opened;
  - a flag placed or removed: `flag(on, count)`, `on` true when it placed
    one, including a flag placed before the first reveal;
  - a chord that opens cells: `chord(count)`, `count` the cells it opened;
  - an action the session takes while playing that changes no cell (a
    wasted reveal or chord): `noop()`;
  - a reveal or chord that loses: `explode()`, and no reveal or chord cue
    for that action;
  - a win: `win()` once, when the session finishes won, after the cue of
    the winning action.
- **The first reveal is heard.** The first reveal's result arrives with
  its board (a Promise); its cue plays when the board arrives, unless the
  game was restarted or left meanwhile. Browsers start audio only after a
  user gesture, and the first click or key press on the board is one: the
  audio context is unlocked by that gesture (the sound module's existing
  `pointerdown` / `keydown` unlock and the 2D board choice's
  `sfx.unlock()` on Start), so the first reveal after a mouse click or a
  key press is audible.
- **Silence where nothing was done.** No cue plays for a press cancelled by
  moving off the cell before release, for an input the session refuses
  (`null`: generating, failed, paused, hidden, ended or left), or for a
  right press on a revealed cell that the pointer input never sends.
- **Same volume and mute** (P-62). The cues go through the one `sfx`
  instance `applyAudio` drives, so the `volume` and `muted` settings apply
  to 2D exactly as to 3D, with no new setting: muted, Classic 2D is silent;
  a volume change applies to the next cue.
- **Replay viewer stays silent.** Watching a 2D replay plays no cue.
- **Sound never touches play** (`.claude/context/audio.md` § Domain
  dependencies): a cue never changes, delays or gates an action, and a
  mode created without a sound sink (the tests' default) plays nothing and
  behaves exactly as before.
- **Tests first.** `tests/classic2d-mode.test.mjs` mounts the mode with a
  recording fake sound sink and pins each mapping above for both pointer
  and cursor actions: reveal with its count, flag on and off, chord with
  its count, the no-op, the loss (explode only), the win (the action's cue,
  then win once), the first reveal's cue after the board arrives and none
  after a restart before it arrives, and no cue for a cancelled press or a
  refused action. A browser check (Playwright through `__ms`, with the
  `sfx` methods spied) plays a 2D Beginner game with the mouse and with
  the keyboard and sees the cues called on that one instance, which
  reports muted while the `muted` setting is on.
- **What not to break** (`docs/UX_REVIEW.md` § Decisions taken, "What not
  to break"): release-to-act with drag-to-cancel, the reference input
  conventions, and 3BV, click and efficiency accounting are unchanged; the
  existing Classic 2D, replay and 3D tests pass unchanged.
- `.claude/domain/features/classic-2d-square-play.md` settles that Classic
  2D plays the 3D game's synthesized cues for its actions at the shared
  volume and mute (§ Scope and non-goals, the in-scope list) and names the
  sound module among its dependencies (§ Dependencies). Nothing else in the
  document changes.

## Decisions
- **Settled here, without conflict** (P-62 of `docs/UX_REVIEW.md`, row W-09
  of § Approved scope and work plan): `classic-2d-square-play.md` § Scope
  and non-goals leaves sound unstated; the in-scope list gains the 2D
  sound cues. § Dependencies gains the sound module (`js/audio.js`).
  `.claude/domain/features/classic-2d-square-play.md` is normally
  `/architect`'s; this task updates it for exactly this and for nothing
  else. A further design decision met at implementation time is not
  covered: leave that passage untouched and name it under *Follow-ups* as
  a precise follow-up.
- **Where the cues are chosen**: in the Classic 2D mode, at the gate both
  inputs already act through (`act` in `js/classic2d/mode.js`), from the
  engine's result (`changed`, the changed cells' new states, the game's
  phase) and the session's `finished`. The mode stays DOM-free: it takes
  the sound sink as an injected option and `js/main.js` passes the shared
  `sfx`. The 2D engine result carries no `revealed` / `flagged` counts as
  the 3D session's does, so the mode derives them from the changed cells.
- **No-op follows 3D's rule**: it plays only for an action taken while
  playing that changed no cell, as 3D's `version` check does. Actions the
  session refuses, and a flag or chord before the first reveal that changes
  nothing, are silent.
- **Cues only**: 3D's loss flash and controller rumble are not part of
  P-62. The 2D end-of-game moment is W-11 (P-64) and haptics W-25 (I-18).
- **Out of scope**: M toggling sound in Classic 2D is task 119's (W-01,
  P-01), which already states it; this task supplies the cues it toggles.
  The 2D replay viewer stays silent (`replay-playback.md` keeps "the viewer
  is silent"); sound in the viewer would be W-32's (P-52, P-66, I-10) if it
  is ever added. Sound wording on the Settings page is W-07 (P-10). The
  count-scaled right-click-on-a-number sound is 3D's, W-20 (task 127).
