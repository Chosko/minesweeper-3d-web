# Task 21 — Tile and number colour tokens

Archived: 2026-10-10
Status: [DONE]
Files: css/tokens.css, tests/tokens.test.mjs
Preconditions: 1
Feature: square-tile-skin

Target: claude

## Goal
Define the palette of feature `square-tile-skin` as design tokens: the
square tile's colours in every state (closed, pressed, revealed, flagged,
mine, exploded mine, wrong flag, board frame and gap) and the number colours
1–8, each with a light and a dark value, checked against the contrast
contract.

## Acceptance criteria
- `css/tokens.css` gains tile tokens for every state and the board frame and
  gap, and number tokens 1–8, each with a light and a dark value; names are
  semantic (`tile-closed`, `number-3`, …).
- Values are low-fidelity: the light number set starts from the current 3D
  number hues (blue, green, red, navy, maroon, teal, near-black, grey); the
  dark tile colours and the dark number set are simple placeholder values
  chosen against the dark revealed tile. No value is taken from the
  high-fidelity designs.
- Every number colour reaches at least 4.5:1 against its theme's revealed
  tile; the token contrast test asserts it for both themes.
- The 3D palette in `js/textures.js` is untouched.

## Decisions
- Low-fidelity pass: every tile state and number colour exists in both
  themes, with plain placeholder values wherever a value is a visual-design
  judgement; the high-fidelity values come from the approved designs in a
  later pass, and those designs are not an input to this task.
