## Goal
Give the player a way to wipe everything the game keeps in this browser and
start over as a new player. This is row W-35 of `docs/UX_REVIEW.md`
§ Approved scope and work plan (Area: Settings, Size: Small, Phase 1). It
closes P-70 of that document (Minor): today records, history, replays,
settings and the last board choices can only be cleared through the
browser's own site-data controls. P-70's approved solution is a "Reset all
data" action at the bottom of the Settings page, behind a confirmation that
names what goes. The work serves players who share a browser and anyone
who wants a fresh start. The export P-70 offers first belongs to row W-31
(I-09, CSV or JSON export, Phase 5). This task leaves room for it and does
not build it.

## Acceptance criteria
- **The action** (P-70): the Settings page ends, below the Bindings panel,
  with a "Data" `ui-panel` holding one line saying what the action does
  and a "Reset all data…" kit button. It is reachable and operable by
  mouse, keyboard and controller like the page's other controls. No new
  component variant and no new token: it uses the kit's existing buttons.
- **The confirmation names what goes** (P-70): the button opens a
  confirmation panel in the Data panel, in the style of the pause card's
  `#pause-confirm`: a message, a confirm button labelled with the action
  ("Reset all data") and Cancel. The message names every kind of data that
  goes: records, game history, replays, settings, the last board choices
  (Classic 2D and 3D) and the first-use hints. It says the data is deleted
  from this browser and cannot be undone, for example "Delete your
  records, game history, replays, settings, last board choices and
  first-use hints from this browser? This cannot be undone." When the
  panel opens, focus moves to Cancel. Cancel, Esc, the browser or
  controller Back, and leaving the page all close the panel and change
  nothing, and closing it returns focus to "Reset all data…". While the
  panel shows, Back closes the panel first and does not leave the page.
- **Every platform document is cleared** (P-70): confirming removes every
  document the storage backend holds, whether or not it is registered this
  session: `settings`, `records`, `records.history`, `records.inProgress`,
  `replays.library`, `shell.lastMode`, `classic2d.lastChoice`,
  `mode3d.lastChoice`, the first-use document task 119 adds if it has
  landed, and any document added later. It also removes every kept-aside
  copy, and a document stored at a newer version than this build knows.
  The storage interface gains this as one operation, for example
  `clear()` → Promise of `{ ok: true }` or `{ ok: false, reason:
  'write-failed', error? }`, which never rejects. The backend contract
  gains the matching method, implemented by the browser backend (every
  `ms3d:doc:` and `ms3d:aside:` key and no other key) and by the memory
  backend (both Maps). `js/platform/index.js` re-exports it like the other
  storage methods.
- **Every replay blob is cleared** (P-70): every blob the blob store lists
  is deleted through the existing `list()` / `delete()`. The reset waits
  for the replay library's start-up load to settle before it clears, so
  the library's reconciliation cannot save an index back afterwards. After
  the reset no store saves a document that was cleared.
- **Legacy keys are cleared**: the four legacy `localStorage` keys the
  settings store carries over (`LEGACY_KEYS` in `js/settings/store.js`:
  `ms3d.lookSens`, `ms3d.invertY`, `ms3d.volume`, `ms3d.muted`) are
  removed, so the next start finds no settings document and nothing to
  carry over, and every setting takes its default. The first-use key
  `ms3d.hintH.done` in `js/ui.js` is removed too, or whatever first-use key
  task 119 leaves in its place. A key removal that throws counts as a
  failure (below). The unread keys `ms3d.custom`, `ms3d.best.*` and
  `ms3d.lastPreset` are left alone (Decisions).
- **Fresh profile through a reload**: once everything is cleared, the page
  reloads (`location.reload()`, with the leave-page guard's `reloading`
  flag set as the context-lost reload already does). The game then starts
  exactly as a new player's does: Light theme before first paint, every
  setting at its default, empty Records (2D and 3D) with their honest
  empty states, an empty replay library, no "Last played" mark on the
  menu, both board choices at their fallbacks, and the first-use hints
  showing again. The reload is injected into the reset module, so tests
  can observe it without reloading.
- **Failure is said, not hidden**: if clearing the documents, listing or
  deleting a blob, or removing a legacy key fails, the page does not
  reload. The confirmation panel is replaced by a warning line
  (`ui-text--warning`) saying which data could not be deleted (for example
  "Replays could not be deleted.") and that the rest was. The action stays
  available so the player can try again. With storage unavailable for the
  session (`available()` false), the reset still clears what exists and
  reloads.
- **Room for export (W-31)**: the Data panel is where W-31's export action
  (I-09) will sit, before "Reset all data…". This task adds no export
  control, no placeholder button and no export wording in the
  confirmation.
- **Tests first**: `tests/platform-storage.test.mjs` pins `clear()` over
  the memory backend: registered, unregistered, kept-aside and newer-version
  documents gone; `load` afterwards returns nothing; a backend that throws
  gives `{ ok: false }` and never rejects. `tests/platform-browser.test.mjs`
  pins the browser backend removing every `ms3d:doc:` / `ms3d:aside:` key
  and leaving every other key (the legacy `ms3d.*` keys, unrelated keys)
  in place. A new `tests/settings-reset.test.mjs` pins the reset module
  over the memory backend, the memory blob store and a fake legacy store:
  everything cleared, then reload called once; each failure path reports
  what failed and does not reload; it waits for the library's load.
  `tests/settings-page.test.mjs` pins the Data panel after Bindings, the
  confirmation's message naming each kind of data, Cancel changing
  nothing, and focus moving to Cancel and back. A Playwright run through
  `__ms` (or a unit over the page wiring) checks that a profile with
  records, replays, a dark theme and last choices is back to a fresh
  profile after confirming.
- **What not to break** (`docs/UX_REVIEW.md` § Decisions taken): the
  confirmations that say "It will count as a loss" (the pause card's are
  untouched); the last-choice memory and the honest empty states and
  storage notices outside a reset; the settings store's one-time
  carry-over on a first start; the platform rule that the browser backend
  touches only its own keys.
- `README.md`'s Settings line mentions "Reset all data" on the Settings
  page.
- The owned documents state the agreed design change, in every passage
  that stated the old one: the Settings page ends with a Data panel whose
  "Reset all data" action, behind a confirmation naming what goes, clears
  every document, kept-aside copy and replay blob and the carried-over
  legacy keys, then reloads into a fresh profile; the storage interface
  gains `clear()`; the replay library and the records can be reset this
  way. They also settle the points listed under Decisions. The documents
  are `.claude/domain/features/settings.md`,
  `.claude/domain/features/platform-storage.md`,
  `.claude/domain/features/replay-library.md` and
  `.claude/domain/features/personal-records.md`. Nothing else in those
  documents changes.

## Decisions
- **Design change agreed (user decision, 2026-10-12):** settled by prior
  instruction. P-70's proposed solution in `docs/UX_REVIEW.md` is a "Reset
  all data" action at the bottom of Settings, behind a confirmation that
  names what goes, with an export offered first (I-09). It is approved
  without condition under § Approved scope and work plan (row W-35), and
  the export is assigned to row W-31.
  - `settings.md` § Architecture, "Settings page" ("sections for controls,
    graphics, theme and audio"): the page ends with a Data panel and the
    reset action. § Data and state, "Carried-over values": a reset removes
    the legacy keys, so the next start carries nothing over.
  - `platform-storage.md` § Interfaces and contracts (register, load,
    save, availability): gains a clear-all operation that removes every
    document and kept-aside copy. § Data and state, "Legacy keys" ("left
    in place"): the settings feature removes its four keys on a reset.
  - `replay-library.md` § Scope and non-goals ("Deleting a replay by hand,
    and resetting the library — in no milestone's slice") and the rule
    that pinned replays are never removed: a player-confirmed Reset all
    data deletes every replay, pinned ones included. Retention and storage
    failures still never delete a pinned replay.
  - `personal-records.md` § Scope and non-goals ("Resetting or deleting
    records — no milestone's slice includes it") and § Interfaces,
    "Failure" ("a newer build's records are never overwritten by an older
    one"): a player-confirmed reset deletes the records, the history, the
    in-progress marker and a newer-version document alike. "All data"
    means all.

  Settled here, without conflict: a fresh profile is reached through a
  page reload; the old per-size 3D best times (`ms3d.best.*`) and the
  other unread `ms3d.*` keys stay where they are
  (`personal-records.md` § Scope and non-goals). These documents are
  normally `/architect`'s; this task updates them for exactly this and for
  nothing else. A further design decision met at implementation time is
  not covered: leave that passage untouched and name it under *Follow-ups*
  as a precise follow-up.
- **Reload rather than in-place reset**: every owner (settings, records,
  replay library, last mode, both last board choices, the first-use state,
  the theme script before first paint) loads its document at start-up, and
  each keeps an in-memory copy as the source of truth. Reloading after the
  clear reaches a true fresh profile with no reset method on each store.
  Resetting in place would need a reset on every store and would risk a
  stale copy saving itself back. The reset is offered only from the
  Settings page, where no game is in progress, so the reload loses nothing.
- **Only the carried-over legacy keys and the first-use key go**: the
  launch scope names the four keys the settings store carries over, which
  would otherwise re-import old settings at the next start. The first-use
  key brings the hints back. `ms3d.custom`, `ms3d.best.*` and
  `ms3d.lastPreset` are read by nothing, so they cannot change the fresh
  profile, and `personal-records.md` keeps the old best times untouched.
- **Clearing is the storage layer's job, and only in its own namespace**:
  the documents and kept-aside copies go through a storage `clear()`, so a
  later Steam backend implements the same operation. The legacy keys are
  removed by the reset module, which belongs to the settings feature, the
  way the settings store reads them today. The browser backend still
  touches no key outside `ms3d:doc:` / `ms3d:aside:`.
- **Out of scope**: the export offered first (W-31, I-09); deleting single
  replays or records; any new setting (decision 17 drops the accessibility
  panel); changing the pause card's confirmations.
