## Goal
Build the navigation core of feature `game-shell`: a screen router that owns
the current screen and a back stack, shows one screen at a time, hands focus
to each screen's default target and resolves Back; and shell navigation that
makes every shell screen operable by mouse, keyboard and controller on the
existing controller reader and spatial focus search.

## Acceptance criteria
- A router module owns the current screen (menu, mode board choice, playing,
  paused, results, records, settings) and a back stack; every screen change
  goes through it and no screen shows another directly.
- On each change it shows exactly one screen, focuses that screen's declared
  default target, and Back returns to the screen it came from.
- Esc and the controller's back button always mean Back (or Pause while
  playing), never a game action.
- The topmost visible layer takes input; a button held across a screen
  change is ignored until released.
- Router and focus logic are DOM-free where possible and covered by Node
  tests (route, back stack, default focus, held-button suppression); a
  Playwright check walks menu → screen → Back by keyboard.
- The existing 3D flow and `window.__ms` keep working.
