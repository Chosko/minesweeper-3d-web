## Goal
Take the wait out of the first click. This is row W-13 of
`docs/UX_REVIEW.md` § Approved scope and work plan (Area: Generation, Size:
Medium, Phase 2). It closes P-17, P-34 and I-11 of that document, under
decision 18 ("Cube Expert no-guess budget: no measurement; no-guess is the
default — P-34's background generation and reliable status card still
proceed"). The first click opens late. The board comes back from the
generation worker 50 to 300 ms after the release, 500 ms on the first game of
a page load and 200 to 350 ms on no-guess Expert. The wait is off the clock,
but the opening visibly lags the click a speed player feels most (P-17,
Minor, speed players). A no-guess Cube Expert first click waited 19 s in the
browser with no "Generating" card visible at 300 ms. The same generation took
128 ms median and 849 ms worst from the centre cell in Node. Twenty seconds
of nothing between Play again and the first opening would end a grind session
(P-34, Major if it reproduces on a laptop, 3D enthusiasts with no-guess on).
I-11 fixes both at the root with a warm worker and background generation.
The approved fix has four parts:
- Standard boards are placed synchronously on the main thread, and the worker
  is kept for no-guess.
- The worker is spawned and warmed when a board choice opens.
- The next no-guess board is pre-generated for a marked start cell while the
  results screen shows.
- The "Generating the board…" card becomes reliable, with a progress line and
  a way out to a standard board.

The task serves speed players, 3D enthusiasts with no-guess on, and anyone
who meets a long no-guess wait.

## Acceptance criteria
- **Standard boards placed synchronously** (P-17, I-11): with no-guess off,
  the first click (in 3D the first reveal) places the board on the main
  thread, in both modes. The placement takes the same request, the same seed
  and the same code path the worker runs for a standard request
  (`generate()` with `noGuess: false`, or the placer behind it). The mines,
  seed and `generatorVersion` therefore equal what the worker would have
  returned. No request goes to the worker, the session never enters
  `generating`, no status card shows, and the first reveal is applied in the
  same call. The worker is used for no-guess requests only. The client
  contract that generation never runs on the main thread is replaced by that
  rule.
- **Warm worker, shared across games** (P-17, I-11):
  - Each mode keeps one generation client for the page instead of creating one
    per game. Today `createClassic2DMode` creates one per `open`.
  - Its worker is spawned and warmed when that mode's board choice screen
    opens, Classic 2D's (`classic-2d-choice`) and 3D's (`board-choice`).
    Warmed means the module is loaded and has answered a no-op warm-up
    message, so the first no-guess request of a page load pays no worker
    start-up.
  - Warming twice is harmless. A cancelled request still terminates the
    worker, as today, and the next warm-up or request starts a fresh one.
  - The warm-up is not a board request and never delivers a board.
- **Marked start cell** (I-11; decision 15, which W-33's daily board and
  challenge links will reuse):
  - Every board has exactly one marked start cell, a pure function of its
    graph description, defined once in the generation layer, DOM-free and
    exported for the sessions and for W-33.
  - Square `{width, height}`: the cell at column `floor(width / 2)`, row
    `floor(height / 2)`. Box `{X, Y, Z}`: the cell at `floor(X / 2)`,
    `floor(Y / 2)`, `floor(Z / 2)`. Each is converted to a cell index by the
    graph's own coordinate order.
  - It is a request input like any first click. It changes nothing in the
    placer, solver or no-guess loop, so the first click stays safe-cell-only
    (decision 1) and `GENERATOR_VERSION` does not change.
- **Background pre-generation for Play again** (P-34, I-11):
  - *When it starts.* When a mode reports a finished game (won or lost) whose
    board was no-guess, the mode requests the next board of the same board
    choice through its warm worker. The request uses a fresh seed from the
    session's seed source and `firstClick` = that board's marked start cell.
    It runs while the results screen shows. Standard boards are never
    pre-generated, since they are placed synchronously. An abandoned game
    pre-generates nothing.
  - *Who uses it.* The pre-generation belongs to the mode, from its finished
    report until its next start or its leave. The next start with the same
    board choice takes it over: Play again, or Restart from the pause card of
    the finished game. A start with any other choice, or the mode being left,
    cancels and discards it. This keeps the shell's mode contract unchanged.
  - *The mark.* A game that took over a pre-generation opens closed with its
    marked start cell visibly marked. In 2D the board view draws the mark
    over the tile, in the cursor-ring style, from existing tokens. In 3D the
    renderer tints that cube's instance. The mark shows only while a
    pre-generated board waits for that cell and goes when the first click
    lands anywhere. A game with no pre-generation shows no mark.
  - *First click on the mark.* If the first click (3D: the first reveal;
    flags placed before it do not count) lands on the marked start cell, the
    pre-generated board is the game's board. If it has already arrived, the
    board is applied in the same call with no generating state. If it is
    still in flight, the session enters `generating` and waits for that same
    request, with the status card's normal rules. A failed pre-generation
    (budget exhausted) leads to a fresh request at the click, exactly as
    today.
  - *First click anywhere else.* If the first click lands on any other cell,
    the pre-generated board is discarded, or its in-flight request cancelled.
    Generation then runs exactly as today around the clicked cell with a
    fresh seed. The player keeps a free first click.
- **Reliable status card** (P-34):
  - While a no-guess board has not arrived, `#c2d-status` (2D) and
    `#m3d-status` (3D) are visible no later than `GENERATING_DELAY_MS`
    (200 ms, unchanged) after the first click.
  - This holds in every path: the first game, a game started by Play again or
    Restart, a first click on the marked start cell whose pre-generation is
    still in flight, and pointer-locked 3D play.
  - The task finds why the review saw no card 300 ms after the click, fixes
    that cause, and pins it with a test. Places to look: the 3D card's
    `S.mode === 'playing'` gate in `showStatus3D`, the session's show timer
    on its clock, and stacking against the canvas or overlays.
- **Progress line** (P-34):
  - While the card shows "Generating the board…", a `ui-text--muted` line
    under its title reads `candidate <n> · <s> s`, for example
    "candidate 14 · 6 s". `<n>` is the number of candidates the worker has
    tried so far. `<s>` is the whole seconds since the first click.
  - The line updates at least once a second while shown and is cleared when
    the card hides.
  - The worker protocol gains a progress message, `{ id, progress: {
    candidates } }`, posted during a no-guess request at most every 250 ms of
    worker time, before the request's single result. `generate()` takes an
    optional progress callback that never changes its result, so determinism
    holds.
  - The client exposes progress per request. A progress message for a
    superseded or cancelled id is dropped like a late reply.
- **Play a standard board from the generating card** (P-34, "Cancel to a
  standard board"):
  - The generating card gains a "Play a standard board" button. It cancels
    the no-guess request through the client and places a standard board of
    the same size around the same first click, synchronously. The game starts
    at once and is played and recorded as a standard board (no-guess off).
  - The mode's board choice switches no-guess off for later restarts, as the
    failure offer's Play a standard board already does.
  - The button is reachable by keyboard and controller. The contrast test
    covers it in both themes.
- **Timer unchanged** (P-34): the wait stays off the clock. In both modes
  the timer starts when the board arrives, so a ready pre-generated or
  synchronous board starts the clock at the first click itself.
- **Deterministic replays and records**:
  - The recorded seed and `generatorVersion` reproduce every board exactly.
    For a pre-generated board, `generate({graph, mineCount, firstClick:
    <marked start cell>, noGuess: true, seed})` returns the recorded mines.
    For a synchronous standard board, the worker's answer to the same request
    equals the main-thread placement. Tests pin both.
  - A pre-generated game's summary and replay header carry the seed the
    pre-generation used.
  - No `GENERATOR_VERSION` bump.
- **Tests first**:
  - Generation tests pin the marked start cell for square and box
    descriptions (odd and even sides, sides of 1), the progress callback and
    message (the result unchanged with or without it), and the client's
    progress, warm-up and dropped stale progress.
  - Session tests in both modes pin:
    - a standard first click that never touches the client and never enters
      `generating`;
    - a pre-generated board used on a click on the mark, both ready and in
      flight;
    - discard and fresh generation on a click elsewhere;
    - a failed pre-generation falling back to a fresh request;
    - Play a standard board from `generating`;
    - the timer starting at the board's arrival.
  - Mode and shell tests pin:
    - one client per mode across games;
    - warm-up on opening each board choice;
    - pre-generation started at a finished no-guess game and not at a standard
      or abandoned one;
    - discard on leave and on a different choice;
    - the 3D card shown by the delay in pointer-locked play.
  - The 2D view test pins the start-cell mark.
- **Coordination with task 121** (row W-04, P-05 and P-11), which lands in
  either order. Task 121 owns:
  - the generating card's spinner and its Cancel back to the closed board;
  - Esc and the controller's back button cancelling generation to the closed
    board;
  - the failure offer's buttons (Retry, Play a standard board, Back to menu)
    and their stacking and focus.

  This task leaves all of those as it finds them. Its "Play a standard board"
  button sits beside task 121's Cancel on the same card, and its progress
  line sits under the same title. If task 121 has landed, cancelling while
  waiting on an in-flight pre-generation also discards it.
- **What not to break** (`docs/UX_REVIEW.md` § Decisions taken): no-guess
  boards stay separate records; release-to-act with drag-to-cancel; 3BV,
  click and efficiency accounting; the last-choice memory; the confirmations
  that say "It will count as a loss"; the failure offer as it stands.
- `.claude/domain/features/board-generation.md` states the agreed design
  change in every passage that stated the old one, and nothing else in it
  changes. The change:
  - the worker is used for no-guess boards only, and standard boards are
    placed synchronously on the main thread;
  - the worker is warmed when a board choice opens;
  - the next no-guess board is pre-generated for a marked start cell while
    the results screen shows, and a first click elsewhere discards it;
  - the worker posts progress messages before its single result;
  - the generating card carries a progress line and Play a standard board.

  It also records the settled points: the marked start cell's definition (the
  centre cell of each side, a request input that changes no generator
  behaviour), and a pre-generated board's seed recorded and reproducing it
  exactly.
- `.claude/domain/features/classic-2d-square-play.md` and
  `.claude/domain/features/3d-play-flow.md` state the agreed design change in
  every passage that stated the old one, and nothing else in them changes.
  The change: the game session places a standard board synchronously at the
  first click, asks the worker only for a no-guess board, and takes over a
  pre-generated board when the first click lands on the marked start cell.
  They also settle that Play again opens with the marked start cell shown
  while a pre-generated board waits for it.

## Decisions
- **Design change agreed (user decision, 2026-10-12):** settled by prior
  instruction. Source: `docs/UX_REVIEW.md` P-17, P-34 and I-11, approved
  under § Approved scope and work plan (row W-13), with decisions 15 ("with a
  marked start cell") and 18.
  - `board-generation.md` § Scope and non-goals says the worker is "used for
    every board, not only no-guess ones". The worker becomes no-guess only,
    and standard boards are placed synchronously on the main thread.
  - `board-generation.md` § Scope and non-goals lists "Pre-generating a
    no-guess board with a forced starting cell" as a non-goal. The next
    no-guess board is pre-generated for a marked start cell while the results
    screen shows. The start cell is not forced: a first click elsewhere
    discards the pre-generated board and generates at the click.
  - `board-generation.md` § Architecture, "Generation worker", hosts the
    placer off the main thread. The placer also runs on the main thread for
    standard boards, and the worker is warmed when a board choice opens.
  - `board-generation.md` § Interfaces and contracts, "Generate" and
    "Timing". The worker posts progress messages before its one result, and
    the caller's generating state shows a progress line and Play a standard
    board.
  - `classic-2d-square-play.md` § Architecture ("Game session") and §
    Dependencies, and `3d-play-flow.md` § Architecture ("3D game session"),
    say the session asks the worker for the board at the first click. The
    session places standard boards itself, asks the worker for no-guess ones
    only, and takes over a pre-generated board on its marked start cell.

  Settled here, without conflict:
  - the marked start cell's definition (`board-generation.md` § Data and
    state);
  - the pre-generated seed recorded so the board rebuilds exactly (same
    section);
  - Play a standard board on the generating card, which extends the standard
    board option of `board-generation.md` § Failure offer to the wait itself.

  Those three documents are normally `/architect`'s. This task updates them
  for exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- **The centre cell is the marked start cell.** It needs no stored state. It
  is the same for every board of a size, which W-33's daily board and
  challenge links need. It is also the cell the review measured Cube Expert
  no-guess timing from.
- **The mark exists only to save the wait.** Free first click is the
  project's chosen difference from the reference, which marks a
  server-chosen start cell (`board-generation.md`'s non-goal). Clicking
  elsewhere therefore costs exactly today's behaviour and never a forced
  start. W-33 (daily board, challenge links) decides for itself whether its
  boards force the start cell.
- **The mode owns the pre-generation, not the shell.** It is held from the
  finished report until the next start or leave. "While the results screen
  shows" then needs no new mode-contract method in `game-shell.md`. Play
  again and Restart of a finished game, both a start with the same choice,
  pick it up.
- **One client per mode, kept warm.** The 500 ms first-game cost of P-17 is
  the worker's start-up. Today 2D starts a fresh worker for every game, so
  warming is only worth it with a client that outlives the game.
- **"Cancel to a standard board" is a button labelled Play a standard
  board.** Task 121's Cancel back to the closed board takes "Cancel", so this
  action keeps the failure offer's label for the same result. Both coexist
  on the card.
- **Progress line copy.** The copy is "candidate 14 · 6 s", exactly as
  approved. The count comes from the worker and the seconds are page-side
  wall time from the first click. No estimate of the remaining time is shown.
- **Boundaries.** Out of scope:
  - any Cube Expert budget measurement or `ATTEMPT_BUDGET` change
    (decision 18);
  - the no-guess default, switch copy, spinner, Cancel, Esc and the failure
    offer (W-04, task 121);
  - the daily board, board codes, challenge links and any start-cell use
    outside Play again (W-33, which reuses the marked start cell);
  - one-key restart (W-29);
  - P-19's opening first click, dropped by decision 1.
- **Target is claude.** The browser checks (card visible by 200 ms,
  pointer-locked 3D) run through Playwright and the `__ms` debug hook, per
  `.claude/context/testing.md`.
