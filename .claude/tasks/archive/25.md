## Goal
Add the mode host of feature `game-shell`: a registry of mode front-ends
behind one contract — open board choice, start, pause, resume, restart,
leave, the game's summary so far, and the started / finished / abandoned /
can-pause reports — and an
adapter that puts the existing 3D game behind it without changing its rules,
look or controls.

## Acceptance criteria
- A mode-host module registers modes by id and is the only way the shell
  reaches a mode; the contract is documented in the module.
- `pause()` stops the mode's timer and board input; `leave()` discards the
  game and releases everything the mode holds (pointer lock, canvas, worker
  requests); `restart()` and `leave()` on a started, unfinished game first
  report `game abandoned` with the game's summary; `summary()` returns that
  same summary, outcome abandoned, for a started, unfinished game at any
  moment, and nothing before the first click.
- The 3D adapter wraps the existing start, pause, pointer-lock and
  end-of-game flow in `js/main.js`: resume re-acquires pointer lock, or enters
  lockless play when resumed from a controller, as today.
- A mode that fails to start (lost graphics context in 3D) reports it; the
  shell shows the mode's failure screen with back to menu.
- Node tests cover the registry and contract with a fake mode; Playwright
  drives the 3D game through the adapter (start, pause, resume, leave) via
  `window.__ms`.

## Decisions
- Until `game-summary` lands, the 3D adapter reports `game finished` /
  `game abandoned` with the summary fields the existing game already has
  (outcome, dimensions, mines, time), and answers `summary()` with the same
  fields; `game-summary` and the 3D slice of m2 complete it.
