## Goal
Build the game session of feature `classic-2d-square-play`: turn a board
choice into a board request, own one game from closed board to result —
first-click request to the generation worker, a "generating" state when the
answer is slow, the timer from the moment the board is ready, actions
applied to the engine, the summary built and handed on at the end — and
remember the player's last board choice.

## Acceptance criteria
- Board setup maps Beginner (9 × 9, 10), Intermediate (16 × 16, 40), Expert
  (30 × 16, 99) and Custom (width, height, mines) plus the no-guess switch to
  the square graph and generation options; custom boards are validated
  against `CUSTOM_LIMITS` on the reference profile: width and height 1 to
  100 each, and a mine count up to the smaller of Minesweeper Online's
  size-dependent cap and the cell count minus one.
- The session opens a closed board; the first reveal goes to the generation
  client with that cell; a "generating" state shows only when the answer
  takes longer than a short threshold; the timer starts once the board is
  ready and the reveal is applied.
- The timer measures from board-ready, pauses while paused, stops at win or
  loss, and exposes whole seconds for display and milliseconds for the
  result.
- On a no-guess generation failure the session shows the failure and offers
  *Retry* (a new seed) and *Play a standard board* (same size, no-guess off);
  the timer never starts on a failed board.
- Win or loss stops the timer and emits `game finished` with a summary built
  by `buildSummary`; restart or leave after the first click emits
  `game abandoned` with its summary first; before the first click nothing is
  reported. Restart cancels any pending generation.
- The last board choice (size, custom dimensions, no-guess) is a
  `classic2d.lastChoice` document in `platform-storage`, read when the mode
  opens.
- The session is DOM-free and covered by Node tests with a fake generation
  client and a fake clock.
- `.claude/domain/features/board-generation.md` records the failure offer
  and the no-up-front-refusal as settled in place of that open question, and
  `.claude/domain/features/classic-2d-square-play.md`'s generation-failure
  contract names the offer. Nothing else in either document changes.

## Decisions
- `CUSTOM_LIMITS` takes the site's mine cap from the measured boards in
  `tests/fidelity/minesweeper-online.md` (largest custom board), by cell
  count, interpolated between measured points as the file says, and never
  above the cell count minus one: the site allows a mine in every cell on
  boards of up to 36 cells, and this game keeps one cell free so the first
  click is always safe — the deliberate difference
  `classic-2d-square-play.md` § Architecture records. Task 37 pins it with
  fidelity tests.
- Settled here: board generation's open question on what the player is
  offered when a no-guess request fails — *Retry* or *Play a standard
  board* — and high-density custom boards do not refuse the no-guess switch
  up front; the failure offer covers them.
  `.claude/domain/features/board-generation.md` and
  `.claude/domain/features/classic-2d-square-play.md` are normally
  `/architect`'s; this task updates them for exactly this and for nothing
  else.
