## Goal
Add the no-guess loop of feature `board-generation`: draw candidate boards
from the seeded source one after another and accept the first the solver
clears from the first-click cell, within an attempt budget fixed by
measurement. The candidate sequence is part of the deterministic output.

## Acceptance criteria
- A `generate(request)` function takes the request the feature document
  defines (graph description, mine count, first-click cell, no-guess on or
  off, seed) and returns the result (mine set, seed,
  generator version, and for no-guess boards the number of candidates tried).
- With no-guess on, the same seed always yields the same accepted board; a
  test pins one for a fixed seed.
- Every accepted no-guess board clears with the solver from its first-click
  cell (checked over many seeds at Beginner, Intermediate and Expert).
- An exhausted budget returns a failure with a reason, never a board that
  needs a guess.
- The attempt budget constant is set from a measurement of Expert no-guess
  generation in Node (median and worst over a fixed seed set), recorded in
  the module beside the constant.
- `.claude/domain/features/board-generation.md` records the measured budget
  and timing as settled in place of that open question. Nothing else in the
  document changes.

## Decisions
- Settled here: the feature document's open question on the attempt budget
  and Expert no-guess timing, fixed by measurement as the document asks.
  `.claude/domain/features/board-generation.md` is normally `/architect`'s;
  this task updates it for exactly this and for nothing else. The other
  open question (what the player is offered on failure) is task 32's.
