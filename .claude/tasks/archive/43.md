## Goal
Build the DOM-free, storage-free logic of feature `personal-records`: given
the current records and a new summary, update the board's three bests, the
per-board and Classic 2D counters and the history, and return the comparison
against the bests that stood before the game.

## Acceptance criteria
- Three bests per board key — fastest time, best 3BV/s, best efficiency —
  from best-eligible won games only (`isBestEligible`); a best is replaced
  only when strictly better, a tie keeps the earlier holder; each best keeps
  the holding summary's id, value and date.
- Counters per board and for Classic 2D overall: games, wins, current and
  longest streak; a win extends the current streak, a loss or an abandoned
  game ends it; win rate is derived, never stored.
- History holds every summary in play order in compact form (id, board key,
  outcome, time, 3BV, 3BV solved, clicks, end date).
- The comparison gives, per stat, the standing best before this game, the
  difference, and whether this game set a new best.
- Recording the same summary id twice is a no-op returning the original
  comparison.
- Bests and counters can be rebuilt from the history alone and equal the
  incrementally maintained ones (tested over a generated sequence of games).
- Queries: boards played (standard boards first, then custom boards by last
  played), a board's bests, counters, win rate and history, the overall
  counters.
- Node tests cover every rule above.
