# Task 100 — Achievement catalogue and evaluator

Target: claude

## Goal
Add the DOM-free core of feature `steam-achievements`: the m3 catalogue —
each achievement's stable API name and its rule as a predicate over one
summary — and the pure evaluator `earned(summary)`.

## Acceptance criteria
- The catalogue holds the m3 set: Classic 2D firsts (Beginner,
  Intermediate, Expert), Expert the hard way (no-guess off), Expert speed
  at three 3BV/s thresholds, Efficiency at two thresholds on Intermediate
  or Expert, No flags on Intermediate or Expert, the six 3D preset wins and
  3D cube Expert speed — 17 achievements, each on won games on standard
  boards only. API names are pinned by a test.
- Threshold values are constants in one place, provisional until task 102
  calibrates them.
- `earned(summary)` is pure and deterministic; 3BV/s and efficiency come
  from `game-summary`'s derivations; "no flags" means no flag action at all
  during the game.
- Custom boards earn nothing.
- The evaluator states whether it can judge "no flags" from a compact
  history summary: if the history keeps only a click total, catch-up skips
  that rule and it is judged at game end only, as the feature document
  provides.
- Node tests cover every rule at and around each threshold, custom boards,
  losses and the no-flags case where a flag was placed and removed.

## Decisions
- Settled here: whether `personal-records`' compact history keeps clicks by
  kind, read from the shipped history format, with the feature document's
  own fallback applied when it keeps only a total.
  `.claude/domain/features/steam-achievements.md` records the answer in
  place of that open question; it is normally `/architect`'s, and this task
  updates it for exactly this and for nothing else.
