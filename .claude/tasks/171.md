# Task 171 — Settings page in the shared layout

Target: claude

## Goal
Recompose the Settings page, for feature `shared-screen-layout`, inside the
screen frame from catalogued components — section labels over the Controls,
Graphics, Theme, Audio and Data sections, the theme list of
task 160 included — keeping every setting's behaviour as `settings` and
`theme-system` define it, as J-Settings-xl/-l/-m/-p and J-Settings-states
draw it.

## Acceptance criteria
- The page is composed from its artboards using catalogued components
  only; the page is still generated from the schema.
- On a phone (J-Settings-p) the bindings device selector (Keyboard and mouse
  / Controller / Touch) spans the full width, "Keyboard and mouse" wrapping
  onto two lines inside its option; nothing overflows the screen.
- Every control, the theme list, the bindings list, Reset all data and its
  confirmation behave as before.
- Every element id, route, default focus and controller navigation target
  survives; existing settings tests pass, updated only where they assert the
  old arrangement.
- No horizontal scroll at any supported window size; the frame body scrolls vertically;
  contrast checks pass under *Joyful tiles*.

## Decisions
- **No Accessibility section** (2026-10-13): the Settings page carries no
  reduced-motion setting; the setting is `m7-after-launch` scope
  (`theme-system.md` § Scope and non-goals).
- **Its artboards exist** — J-Settings-* on the canvas — so the manual
  intervention this task carried while the artboard was undrawn is gone and
  the task is `claude`. The phone selector's wrapping is the owner's change
  (DESIGN-CHANGES §4.8).
