# Task 298 — Machine prefs directory, document delete and list, and the pre-paint theme on the Steam build

Target: claude

## Goal
Bring the Steam build's storage in line with feature `steam-cloud-saves` as
amended: the machine settings document (task 296) lives in a machine prefs
directory under the user-data directory, outside `saves/`, so Steam
Auto-Cloud never syncs it; the file service and the page bridge gain
document delete and list over both directories, so Steam document storage's
`clear()` removes every document and kept-aside copy and Reset all data
removes everything; the main process reads the theme id from the settings
document's file before the window loads and the preload hands it to the
page, which `js/theme.js` prefers; and nothing on the Steam build touches
browser storage.

## Acceptance criteria
- The file service serves a machine prefs directory beside the save
  directory, outside it, with the same safe-write, name-check and
  set-aside rules; the machine settings document's file lives there and
  every other document's in the save directory.
- The file service and the bridge offer document delete and list, mirroring
  `blobs.delete` / `blobs.list`, for both directories; no request reaches
  outside the two directories.
- Steam document storage's `clear()` lists and deletes every document file
  and kept-aside copy in both directories and resolves `{ ok: true }`; it
  fails only when an existing file cannot be deleted.
- Before the window loads, the main process reads the theme id from the
  settings document's file in the save directory (nothing when absent or
  unreadable); the preload exposes it to the page before any page script
  runs; `js/theme.js` applies it when present and on the Steam build reads
  no browser storage.
- With task 296's wiring, no code path on the Steam build reads or writes
  `localStorage`.
- Node tests cover the prefs directory, document delete and list, `clear()`
  over both directories, the theme id read and hand-off, and `js/theme.js`
  preferring the handed-over id.

## Decisions
- One task for the feature's amended runtime work: the prefs directory,
  delete and list, `clear()` and the pre-paint theme each touch the same
  host and bridge files and are small; kept as one to keep the backlog
  simple.
- Waits on task 296, which introduces the machine settings document this
  task routes to the prefs directory.
- How a request names its directory (an argument, or the file service
  knowing the machine-local name) is left to the implementer within the
  fixed-pattern name check; `.claude/domain/features/steam-cloud-saves.md`
  § Architecture does not fix it.
