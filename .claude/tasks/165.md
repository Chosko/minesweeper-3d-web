# Task 165 — Main menu in the shared layout

Target: claude

## Goal
Recompose the main menu, for feature `shared-screen-layout`, as the
J-Menu-xl/-l/-m/-p artboards, J-Menu-states and J-Menu-extra draw it: the
game's title in one line at the top; on the left nine entries — Classic 2D,
Hexagon, Triangle, Surface, 3D; Daily, Records, Settings; Quit — the selected
one taller, the blocks as tall as the preview; on the right the preview of
the selected entry; under them the key hints and the build label. With it go
the menu's behaviour changes `game-shell` now states: Hexagon, Triangle and
Surface open the *Coming soon* page, Leaderboards leaves the menu, Play again
and the session strip are removed, and the menu opens on the last mode
played.

## Acceptance criteria
- The menu is built from catalogued components only, with no styling of its
  own beyond placement.
- **Title** in one line at the top, centred, sized per artboard at each
  desktop size and on the phone.
- **Entries**, in this order, in three blocks with a gap between them and no
  group labels: Classic 2D, Hexagon, Triangle, Surface, 3D; Daily, Records,
  Settings; Quit. All enabled except 3D without WebGL 2 (disabled, reason
  line *Needs WebGL 2 — not available in this browser*, a lock) and Quit on
  the web (locked grey). Accents per J-Tokens: modes coloured, Records and
  Settings neutral cream, Quit cream on a desktop build. No Leaderboards
  entry.
- **Sizes.** Every entry has the same height but the selected one, which is
  taller with a bigger icon and label (the state model of task 163); the
  entries together take exactly the preview's height.
- **Routes.** Classic 2D and 3D open their board choices; Hexagon, Triangle
  and Surface each open the placeholder screen (`#coming-soon`) titled with
  that mode, Back returning to the menu with that entry selected; Daily,
  Records and Settings as before; Quit opens nothing on the web.
- **Preview** of the selected entry, as J-Menu-extra draws each case: a real
  Classic 2D board drawn by its board view; the real cube for 3D through
  task 164's target rectangle (a static themed background without WebGL 2);
  today's daily Expert board, closed, with its marked start cell, for Daily;
  the mode's colour badge and *Coming soon* for Hexagon, Triangle and
  Surface; a cream badge for Records and Settings; *Desktop build only* for
  Quit on the web. Nothing is a picture built for the menu alone.
- **Opening selection.** The menu opens with the last mode played selected,
  its entry carrying the Last played chip (the first entry when nothing was
  played; the first enabled one when the last mode is 3D without WebGL 2);
  that mode's board choice opens on its last board, so Enter then Play
  replays it.
- **Removed:** Play again, the session strip (`js/shell/returning.js`'s
  menu surfaces and their tests), the bests row, the menu's Controls
  button, Sound toggle and Volume slider; the Settings page gains a
  *Controls* action opening the same controls reference, and its audio
  section keeps sound and volume. Pause card quick access is unchanged.
- **Key hints:** ↑ ↓ Move · Enter Select for the active input device, no
  Back hint; the build label shows the game's real version.
- **Phone** (J-Menu-p): no preview — the title, the nine entries filling the
  screen, the touch note and the build label, fitting the phone's height.
- Every surviving element id, route, the default focus target and controller
  navigation order survive or move with their owners; menu, returning,
  settings and router tests are updated first to the new entries, routes,
  opening selection and removals, and pass.
- No horizontal scroll at any supported window size; contrast checks pass
  under *Joyful tiles*.

## Decisions
- **Owner decisions** (DESIGN-CHANGES §2.1–2.3, §4.1): Hexagon, Triangle
  and Surface enabled, opening *Coming soon*; Leaderboards moved to a
  Records tab (task 170); Play again and the session strip removed, the
  last-played mode selected instead. These reverse the locked entries,
  Leaderboards entry and kept Play again this task first carried.
- **The canvas is the source** (owner, DESIGN-CHANGES §1): built from the
  J-Menu artboards, not the earlier S3D-Menu.
- **Behaviour folded in.** The menu's routing and opening-selection changes
  are `game-shell`'s rules, built here because they live in the menu's own
  code (`js/shell/menu.js`, `js/shell/returning.js`).
- **Placeholder screen's look** is task 168's; this task only routes to it
  with the mode's name.
- **Settled design detail** (`.claude/domain/features/shared-screen-layout.md`
  § Scope, *Main menu*): how the entries share the preview's height. The
  feature document is not edited here; task 173 records what holds at ship
  time.
