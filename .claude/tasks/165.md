# Task 165 — Main menu in the shared layout

Target: claude

## Goal
Recompose the main menu, for feature `shared-screen-layout`, from the S3D-Menu
artboard as the feature document amends it: inside the screen frame on the
page backdrop, the title block with the game's name only; the mode entries in
the order Classic 2D, 3D, then the locked entries Hexagon, Triangle, Surface
and Leaderboards, then Daily, Records and Settings, with a locked Quit as the
final control after Settings, set apart from the list; a scene panel, as tall
as the column allows, showing a live preview of the focused mode drawn by that
mode's own renderer — the real cube for 3D, a real board for Classic 2D; the
key hints for the active input device, the build label, and the existing Play
again and last-played detail placed in the layout. The menu's Controls, Sound
and Volume controls leave the menu; the controls reference opens from the
Settings page.

## Acceptance criteria
- The menu is built from catalogued components only, with no styling of its
  own beyond placement.
- No tagline or page subtitle, no per-entry subtitle, no bests column and no
  credit line.
- Entry order: Classic 2D, 3D, Hexagon (locked), Triangle (locked), Surface
  (locked), Leaderboards (locked), Daily, Records, Settings; Quit (locked)
  after Settings, set apart from the list. Locked entries use task 163's
  locked state, open nothing and stay in focus order so the player can read
  them. Adding or unlocking an entry needs no change to the menu's
  composition; when the entries are taller than their column, the column
  scrolls on its own with the scene panel and key hints in place (a test adds
  dummy entries to prove it).
- The scene panel previews the focused mode live, drawn by that mode's own
  renderer — no picture or scene built for the menu alone — and takes the
  height the column frees: 3D focused shows the real cube through task 164's
  target rectangle; Classic 2D focused shows a real Classic 2D board drawn by
  its board view. While a locked entry or a non-mode entry (Daily, Records,
  Settings, Leaderboards, Quit) has focus, the panel keeps the last mode
  previewed; on opening, it previews the menu's default focus. With no WebGL
  2 the 3D preview shows the backdrop and the 3D entry keeps its current
  fallback and reason line; the Classic 2D preview still shows.
- The menu's Controls button, Sound toggle and Volume slider are removed; the
  Settings page gains a *Controls* action opening the same controls
  reference, and its existing audio section keeps sound and volume. Pause
  card quick access is unchanged.
- Play again and the last-played detail line (`js/shell/returning.js`) keep
  their behaviour and sit where the artboard places them.
- The build label shows the game's real version, not the artboard's
  placeholder.
- Every menu element id, route, the default focus target and controller
  navigation order survive, except the removed controls; existing menu,
  returning, settings and router tests pass, updated only where they assert
  the old arrangement.
- No horizontal scroll at 1024 px wide; contrast checks pass under *Joyful
  tiles*.

## Decisions
- **Quit placement** — the owner asked for Quit to be shown; placing it
  locked as the final control after Settings, set apart from the list, is the
  coordinator's reading, recorded in the feature document.
- **Preview on a locked or non-mode entry** — the panel keeps the last mode
  previewed (the feature document's rule), so focus moving down the list
  never blanks it; a locked mode's preview arrives with the mode.
- **Locked entries focusable** — kept in focus order and announced as
  unavailable, so a keyboard or controller player meets the same menu a mouse
  player sees.
- **Feature document over artboard.** Where the S3D-Menu artboard draws a
  tagline, subtitles, a bests column, a credit line or menu sound/volume
  controls, the feature document's owner decisions win.
- **Settled design detail** (`.claude/domain/features/shared-screen-layout.md`
  § Scope, *Main menu*): the no-WebGL2 panel. The feature document is not
  edited here; task 173 records what holds at ship time.
