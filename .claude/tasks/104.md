# Task 104 — Leaderboard screen: board picker, scope tabs, entries and states

Target: claude+human

## Goal
Build the leaderboard screen of feature `leaderboard-screen` as a
game-shell route inside the shared layout's screen frame: the board picker,
the Global, Friends and Around me tabs, the entry list with the player's own
row highlighted, the own standing, paging through Global, and the loading,
empty, offline, unavailable and web-build local-only states — all reading
`steam-leaderboards`, and composed from catalogued kit components only.
Everything under the board picker is one rankings part for a given board,
which the Records screen's Leaderboards tab (task 107) also shows.

## Acceptance criteria
- The route opens with an optional board identity: that board, else the
  board last viewed this session, else Classic 2D Expert with no-guess off;
  Back returns to the caller.
- The screen sits in the screen frame: Back with its key hint and the title
  in the head, the content in the scrolling body, the status line in the
  foot. It is composed from its supplied artboard using catalogued kit
  components only (board option, switch, section label, tabs, stat tile,
  list row, button, key hint, empty and error states), with no styling of
  its own beyond placement and no rule added to any theme stylesheet; it
  passes the contrast checks under *Joyful tiles*.
- **Rankings part** (`leaderboard-screen.md` § Architecture, *Rankings*):
  the scope tabs, own standing, entry list and states below are one part,
  exported from `js/leaderboards/screen.js`, that takes a board identity
  and a host element and keeps its scope and position; the screen composes
  it under its board picker, and nothing in it assumes the leaderboard
  screen is its host. A Node test mounts it on its own for a given board.
- Board picker: 2D | 3D switch, the mode's catalogue boards as board
  options (Beginner, Intermediate and Expert in Classic 2D; the three cube
  presets, Beginner, Intermediate and Expert, in 3D) and a no-guess switch;
  only catalogue boards are offered.
- Tabs Global (default), Friends and Around me, with key hints for the
  scope-switching inputs that follow the active input device; each list row
  shows rank, player name, time to the thousandth (`47.380 s`), 3BV/s and
  efficiency from the entry's details, and a *Watch replay* button disabled
  without a replay (wired in task 105). The player's own row is highlighted
  in every scope.
- Global loads one page at a time with *More*; Friends shows the whole
  list; Around me shows a range either side of the player. The page size and
  range are set at real list heights.
- Own standing: stat tiles for the time, in the same format as the rows,
  and the global and friends rank, or "no time yet".
- Every time on the screen is truncated to the thousandth, never rounded
  (an entry of 47 380 ms shows as `47.380 s`), through the results screen's
  time formatter (task 46) rather than a second copy; the Node tests check
  a row's and the own standing's time.
- States: loading; empty; offline with a retry; Steam unavailable; and in
  the web build a "local only" label in the frame's foot with Friends and
  Around me hidden. A failed fetch never leaves the screen unusable; Back
  always works.
- Every control is reachable by keyboard and controller; shoulder buttons
  switch scope; Esc and the back button mean Back. No horizontal scroll at
  1024 px wide.
- `.claude/domain/features/leaderboard-screen.md` and
  `.claude/domain/features/steam-leaderboards.md` record the page size and
  the Around me range in place of their open questions, and
  `leaderboard-screen.md` drops the artboard from its open questions once
  supplied. Nothing else in either document changes.
- Node tests drive the screen's state with a fake leaderboards module;
  Playwright checks the web build's local-only screen.

## Decisions
- Settled here: the global page size and the Around me range
  (`.claude/domain/features/leaderboard-screen.md` § Open questions and
  `.claude/domain/features/steam-leaderboards.md` § Open questions), and the
  artboard open question in `leaderboard-screen.md`, dropped once the
  artboard is supplied. Both
  are normally `/architect`'s; this task updates them for exactly this and
  for nothing else.
- The screen's time format is `results-screen`'s, per
  `leaderboard-screen.md` § Architecture (Entry list).
- **Times to the thousandth (director decision, 2026-10-12;
  `docs/UX_REVIEW.md` P-46):** task 128 makes `formatTime` the one time
  format outside the live bar, to the thousandth, and this screen shows its
  times through it. `leaderboard-screen.md` § Architecture ("Entry list")
  states tenths (47.3 s) until task 128, which agreed that change, updates
  the passage; this task does not edit it.
- **Shared layout (2026-10-13):** the screen is composed in the screen frame
  from catalogued components (`leaderboard-screen.md` § Architecture,
  *Composition*), so it waits on task 163, which adds them. A component the
  artboard seems to need beyond the catalogue is not added here: compose
  from the catalogued ones and name the gap under *Follow-ups*.
- **Waits on its artboard**, per `shared-screen-layout.md` § Architecture,
  *Design status per screen*.
- **Rankings as one part** (owner's answer: the Records Leaderboards tab
  shows the rankings in place, inside Records): built here so task 107
  places the same part in the tab rather than a second copy.
