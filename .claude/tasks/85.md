# Task 85 — Steamworks capability adapter, unavailable implementation and the page bridge

Target: claude

## Goal
Add the boundary of feature `steam-desktop-host`: the Steamworks capability
adapter interface the main process uses for every Steam call, its
unavailable implementation, and the page bridge — a preload script exposing
one frozen object with a fixed list of promise requests and events, every
request validated in the main process before it reaches the adapter or the
disk.

## Acceptance criteria
- The adapter interface exposes the capabilities identity, presence,
  achievements, leaderboards, shared files and overlay, each reporting
  available or not, with the operations the feature document lists.
- The unavailable implementation reports every capability unavailable and
  rejects every call with `unavailable` ("Steam unavailable").
- The preload exposes one frozen object with exactly the document's request
  list (Steam state; achievements set, store, read; leaderboards find,
  upload, download, attach; shared files write-and-share, download; storage
  and blob operations as registered slots; quit hand-shake; quit) and its
  events (Steam state changed, overlay activated, flush requested).
- The main process validates operation name, argument types and sizes;
  every request resolves or rejects with a typed error — `unavailable`,
  `offline`, `not-found`, `invalid`, `failed` — and never throws into the
  page. The bridge carries no general file or process access.
- The main process selects the unavailable adapter until the Steam
  implementation exists; quit over the bridge runs the closing sequence
  from task 84.
- Node tests cover validation, typed errors, the unavailable adapter and
  the event fan-out with a fake IPC.
