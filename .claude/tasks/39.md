# Task 39 — Settings schema and store

Target: claude

## Goal
Build the settings core of feature `settings`: one schema declaring every
setting (key, type, range or values, default), and the store that loads the
versioned settings document through platform storage before the first
screen, validates every read and write, notifies subscribers, survives
storage failure, and carries over the values players already have.

## Acceptance criteria
- The schema declares look sensitivity (0.25–3, default 1), invert Y (off),
  fullscreen (off), render resolution (Auto / Sharp / Fast, default Auto),
  theme (light / dark, default light), volume (0–1, default 0.7) and mute
  (off).
- `get(key)` always returns a valid value; `set(key, value)` validates,
  saves the whole document through `platform-storage` and notifies; an
  invalid value is rejected and the old value kept, never saved.
- `onChange(key, listener)` fires after a change and once at start-up with
  the loaded value.
- A `load()` the shell awaits before its first screen fills missing or
  invalid values with defaults.
- With no settings document, the store reads `ms3d.lookSens`,
  `ms3d.invertY`, `ms3d.volume` and `ms3d.muted` once, writes them into the
  new document, and from then on reads only the document.
- Unreadable storage gives every default; a failed save keeps the change for
  the session and reports once that settings will not be kept.
- Node tests cover all of the above on the in-memory storage backend.
