# Task 195 — Learn 3D guided board: the chord prompt moves on when a chord can no longer teach

Target: claude

## Goal
On the Learn 3D guided board (task 153), prompt 4 — "Press left and right
together on the number to chord" — is done only when a chord on the lesson
number L opens at least one cube. If the player flags the lesson mine M and
then opens L's other closed neighbours one at a time, a later chord on L opens
nothing, so the prompt line stays on the chord step until the box is cleared
(the board can still be won). Found in task 153's review and deferred there.
The prompt must not get stuck: once every neighbour of L is open or flagged,
the chord can no longer teach anything and the chord step is skipped, the way
a prompt already done when its turn comes is skipped, and the line moves on
to "Clear the rest of the box".

## Acceptance criteria
- The prompt sequence (`createLearnPrompts` in `js/mode3d/learn.js`) treats
  the chord step as done once L has no closed, unflagged neighbour, whenever
  that becomes true after the first reveal — through left-click reveals, a
  chord elsewhere, auto-opened cascades or flags. It stays DOM-free: the
  shell hands it what it needs (for example a predicate or L's closed,
  unflagged neighbour count from the game view) rather than the module
  reading the game.
- A chord on L that opens at least one cube still completes the step, as
  today; a chord on L that opens nothing while L still has a closed,
  unflagged neighbour (a chord before the flag) still does not.
- The skip follows the sequence's existing rule: when the chord step is
  done before its turn (prompts 1–3 still pending), it is skipped when its
  turn comes; when it is the current prompt, the line moves straight to
  "Clear the rest of the box" and L loses the start-cell tint.
- The shell (`learnAction` in `js/main.js`) feeds the condition after every
  board action of the guided game, left-click reveals included, and
  refreshes the hint strip and tint when the prompt changes.
- No other prompt, the end card, the records/replay exclusions or the
  completion rule change.
- Tests first (full TDD): in `tests/mode3d-learn.test.mjs`, the unit cases —
  chord step skipped when L's closed neighbours are all opened after M is
  flagged; skipped when its turn comes if that happened earlier; a chord
  that opens cubes still advances; a chord before the flag still does not —
  plus, through `create3DGame` on `LEARN_BOARD`, the stuck sequence from the
  review (first reveal, flag M, open L's other closed neighbours one by one)
  ending on 'rest'. The existing Playwright lesson stays green.
- `.claude/context/mode3d.md` (the `createLearnPrompts` signature and the
  Learn 3D pattern) and `.claude/context/app-shell-3d.md` (`learnAction`)
  describe the skip.

## Decisions
- **Skip, not a fallback line.** The feature document
  (`.claude/domain/features/3d-play-flow.md`, Learn 3D) names the four
  prompts but not their completion conditions, so it prescribes neither
  option; skipping reuses task 153's own rule ("a prompt already done when
  its turn comes is skipped") and adds no new text, so it is the simpler
  behaviour. The feature document needs no edit.
- **The condition is "no closed, unflagged neighbour of L"**, not "M
  flagged and the rest open": with every neighbour open or flagged a chord
  on L can open nothing whatever the flags are, which is exactly when the
  prompt can no longer be satisfied.
