# Task 191 — Classic 2D touch help: touch binding rows and a touch clipped-board hint

Target: claude

## Goal
Document Classic 2D's touch controls in the game and stop telling touch
players to use a mouse wheel. The UX review drift audit
(`docs/UX_REVIEW_DRIFT.md` § Defects outside the numbered items) found two
defects with one cause — the bindings source `js/settings/bindings.js` has
no touch entries for Classic 2D:

1. **Classic 2D lists no touch bindings.** `BINDINGS['classic-2d']` has no
   `touch` device, so on a phone the 2D pause card, the H panel and
   Settings › Bindings show mouse and keyboard rows. Long-press, the
   Reveal / Flag switch, the tap chord, pan and pinch (task 142, P-37 and
   P-38 of `docs/UX_REVIEW.md`) are documented nowhere in the game.
2. **The clipped-board hint names the mouse wheel on touch.** On a
   390 × 844 touch phone, Classic 2D Expert shows "Wheel scrolls ·
   Shift+wheel sideways", because `HINT_TEXT.scrollHint` has only keyboard
   and controller texts.

Decision 11 of `docs/UX_REVIEW.md` ("Touch a target? Yes") and P-01's
approved solution (one bindings component fed by the active mode and device)
make touch a device the help must follow in Classic 2D as it already does in
3D.

Steps to reproduce (from the audit): 390 × 844 touch emulation → Classic 2D
→ Expert → the clipped-board hint strip reads "Wheel scrolls · Shift+wheel
sideways"; tap Pause → the pause card's bindings show mouse / keyboard rows
and no touch rows; Settings › Bindings › Classic 2D lists no Touch device.

## Acceptance criteria
- `BINDINGS['classic-2d']` gains a `touch` device whose rows state Classic
  2D's touch controls as built: tap reveals a closed cell (or flags it while
  the switch is on Flag); a 400 ms long-press flags or unflags; tap on a
  revealed number chords; the *Tap: Reveal / Flag* switch sets what a tap
  does; one finger pans a board that scrolls; two fingers pan and pinch to
  zoom; Pause at the top. `bindingDevices('classic-2d')` then lists Touch,
  and every surface drawn from the bindings source (the 2D pause card, the
  H panel, the Controls panel's Classic 2D tab, Settings › Bindings) shows
  the touch rows where it shows 3D's.
- On a coarse-only device the 2D help surfaces pick the touch rows as the
  3D ones do (`_bindDevice` / `setDevice`); any per-device table that the
  2D surfaces read for that device (the help foot, the HUD strip, the hint
  strip) has a touch entry, so no lookup throws.
- `HINT_TEXT.scrollHint` gains a touch text, "Drag to pan · pinch to zoom",
  and the clipped-board hint shows it on a coarse-only device. Keyboard and
  controller texts are unchanged. It stays one-time: dismissing it, or a
  touch pan of a clipped board, retires it as a wheel scroll does.
- On a mouse and keyboard desktop every help surface and the hint read
  exactly as before.
- **Tests first**: the bindings tests (tests/settings-page.test.mjs,
  tests/shell-help.test.mjs, tests/classic2d-mode.test.mjs or the file that
  pins `bindingDevices` and `HINT_TEXT`) pin the 2D touch rows, Touch in
  `bindingDevices('classic-2d')` and the touch scroll hint;
  tests/shell-first-use.test.mjs pins the touch text on a coarse-only
  device; the phone run in tests/classic2d-touch.test.mjs asserts the pause
  card shows the touch rows and the Expert hint strip reads "Drag to pan ·
  pinch to zoom".
- `.claude/domain/features/settings.md` (§ Scope, Controls: "touch
  included for 3D") and `.claude/domain/features/classic-2d-square-play.md`
  (§ Architecture, "Board view": the hint "Wheel scrolls · Shift+wheel
  sideways") state the agreed design change — the bindings list touch for
  Classic 2D too, and on a coarse-only device the clipped-board hint reads
  "Drag to pan · pinch to zoom" — in every passage that stated the old one.
  Nothing else in those documents changes.

## Decisions
- **Design change agreed (user decision, 2026-10-15)**, by prior
  instruction: the user approved turning the audit's findings into tasks,
  and the audit prescribes both fixes ("Add 2D touch rows to the bindings
  source"; "Add a touch text ("Drag to pan · pinch to zoom") and pick it on
  coarse-only devices").
  - `settings.md` § Scope lists bindings for "each mode and input device,
    touch included for 3D"; touch is listed for Classic 2D as well.
  - `classic-2d-square-play.md` § Architecture, "Board view" names the hint
    "Wheel scrolls · Shift+wheel sideways"; on a coarse-only device it reads
    "Drag to pan · pinch to zoom".
  Settled here, without conflict: a touch pan of a clipped board retires
  the hint as a scroll does (the document says it goes "once the player
  scrolls"). These documents are normally `/architect`'s; this task updates
  them for exactly this and for nothing else. A further design decision met
  at implementation time is not covered: leave that passage untouched and
  name it under *Follow-ups* as a precise follow-up.
- **One task for both defects**: they share the bindings source, the device
  selection and the help tests, and have one cause.
- **Row wording is the implementer's**, matched to the 3D touch rows'
  style, as long as it names each gesture task 142 built.
