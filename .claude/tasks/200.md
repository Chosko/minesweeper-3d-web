# Task 200 — Touch wording on a coarse-only device for the help foot, HUD strip and hint strip

Target: claude

## Goal
On a coarse-only (touch-only) device the help surfaces drawn from the
bindings source `js/settings/bindings.js` should all speak touch, in both
Classic 2D and 3D. The bindings lists — the pause card, the H panel's list,
the main menu's Controls tab — and the clipped-board scroll hint already
follow the touch device through `UI._bindDevice` (the touch rows on a
coarse-only device unless a controller is in use). Three surfaces do not:
the H panel's foot line (`helpFootHtml`), the HUD strip `#hud-tools`
(`hudStripHtml`) and the first-use hint strip (`hintStripHtml`) are drawn
for `this._device`, keyboard or controller, so a phone or tablet player sees
key names they cannot press ("[H] hides this panel", "Esc menu",
"Left reveal · Right flag", "Arrows move · Space reveal"). Found while
implementing task 191. This task brings those three surfaces onto the same
active-device rule, with touch wording where a surface names an input.

## Acceptance criteria
- `HELP_FOOT`, `HUD_STRIP` and `HINT_STRIP` each gain a `touch` entry for
  both modes, and `js/ui.js` draws the help foot, the HUD strip and the
  mode's hint strip for `_bindDevice(mode)` — the device the bindings lists
  already use — so on a coarse-only device with no controller in use all
  three read touch wording, and a controller in use on that device still
  gets the controller wording.
- Touch wording names only gestures and on-screen controls a touch player
  has, matched to each mode's touch rows in `BINDINGS`:
  - **Hint strip** — Classic 2D: tap reveal, long-press flag, tap a number
    chord; 3D: tap reveal, long-press flag, the Space button aims through,
    the Shift button shows neighbours.
  - **Help foot** — names no key: 3D states the release rule for a finger
    (an action fires when the finger lifts); Classic 2D carries no input
    instruction (empty, or a line that names no key).
  - **HUD strip** — lists only what a touch player can use: 3D keeps its
    spacing readout, labelled for pinch; an entry with no touch input (H,
    M, F, Esc) is not listed. A strip left with no entries hides its panel
    rather than showing an empty box.
- When each surface shows is unchanged: the hint strip's eligibility and
  dismissal (`stripShown`, `used2D`, `refreshHints`), the HUD strip's
  existing layout rules and the H panel's openers are not touched.
- On a mouse-and-keyboard desktop and with a controller, every one of the
  three surfaces reads exactly as before.
- **Tests first**: the bindings tests (tests/shell-help.test.mjs, or the
  file that pins `HUD_STRIP`, `HINT_STRIP` and `HELP_FOOT`) pin the touch
  entries for both modes and that no touch entry renders a `<kbd>` key or
  pad glyph; tests/shell-first-use.test.mjs pins the touch hint strip on a
  coarse-only device in each mode; the phone run in
  tests/classic2d-touch.test.mjs and the touch run in
  tests/shell-mode-3d.test.mjs assert the shown hint strip and HUD strip
  name no key, and a desktop run still shows the keyboard wording.
- `.claude/context/settings-bindings.md` and
  `.claude/context/app-shell-help.md` state that the help foot, the HUD
  strip and the hint strip follow the touch device like the bindings lists,
  in every passage that says otherwise.

## Decisions
- **The rule is `_bindDevice`, not a new one**: the three surfaces adopt the
  device rule the bindings lists already follow, so every help surface on a
  coarse-only device picks the same device.
- **Wording is the implementer's** within the constraints above, matched to
  the touch rows' style; the touch rows in `BINDINGS` are the source of
  truth for which gestures exist.
- **Not covered**: the one-time toasts (`autoHide`, `aimHint`) and the Learn
  3D prompts, which are drawn through `hintText` for `this._device` /
  `DEVICE.current`, keep their keyboard or controller wording. If they show
  key names on a coarse-only device, name that under *Follow-ups* as a
  precise follow-up rather than widening this task.
