# Task 260 — Triangle boards, limits, identity and board-code token

Target: claude

## Goal
Part of feature `triangle-grid`: set the Triangle mode's standard boards and
custom limits, how a triangle board is identified in the records, and how it
is spelled in a board code, so a mode can play one (`flat-grid-modes`).

## Acceptance criteria
- Standard boards, as drawn on the Triangle board sheet: Beginner 13 × 7
  with 8 mines, Intermediate 25 × 13 with 36, Expert 41 × 17 with 103.
- Custom boards: 1 to 100 a side; mines from 1 to Classic 2D's cap for the
  same cell count, at most cells − 1. A 1 × 1 board is refused on the mines
  field. Validation gives Classic 2D's refusal shape; no-guess is never
  refused up front.
- The board identity's triangle form: mode `triangle`, grid `tri`, width,
  height, mines, no-guess, with the standard names recognised on the `tri`
  grid. The board-key format version does not change.
- Board codes: a triangle board encodes as `T` before the 2D token (`TB`,
  `TI`, `TE`, `T<w>X<h>M<mines>`, then `N` when no-guess). Parsing checks
  the size against these limits and builds the `tri` graph. Every existing
  code, the hexagon `H` codes included, keeps its meaning.
- A triangle code checked against another mode's board choice is refused as
  another mode's code.

## Decisions
- **The values live in a new `js/triangle/board-setup.js`**, the same way
  task 256 puts Hexagon's in `js/hexagon/board-setup.js`.
