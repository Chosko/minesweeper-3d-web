# Task 153 — Learn 3D guided board

Target: claude

## Goal
Teach a first-time 3D player the two things 3D adds before they meet a real
board: a number counts the mines among up to 26 cubes in three layers, and
solved cubes disappear. This is row W-21 of `docs/UX_REVIEW.md` § Approved
scope and work plan (Area: 3D, Size: Medium, Phase 3, "after W-01 and
W-17"). It closes I-01 of that document (Medium effort; player: the
first-time 3D player), under decision 16 ("3D tutorial before the campaign?
Yes — I-01, I-02 proceed"). I-01: the design routes 3D newcomers through a
campaign that does not exist, and the web build drops them on Cube
Beginner. Its approved solution: a "Learn 3D" entry on the 3D board choice
that starts a fixed no-guess board with a fixed seed and start cell, four
HUD prompts in sequence (hold Shift to see what this number counts; hold
Ctrl to see the cleared cubes; flag the one cube that must be a mine;
left + right on the number to chord), no records, no timer, repeatable. The
entry builds on task 119 (W-01: the help and hint component, the toasts and
the first-use state) and task 152 (W-17: the First box presets and the
per-board start spacing). Task 152 keeps the default 3D choice on Cube
Beginner and steers newcomers to the First box presets only through this
entry: the guided board is the one route from "new to 3D" to First box 1.

## Acceptance criteria
- **The guided board** (I-01): one DOM-free module (for example
  `js/mode3d/learn.js`) defines it as a frozen constant: 4 × 4 × 3 with
  First box 1's mine count (task 152's measured count), the seed and
  generator version it came from, its start cell — the box's centre cell
  (`floor(X / 2)`, `floor(Y / 2)`, `floor(Z / 2)`, task 138's marked start
  cell, computed directly when task 138's helper is not in the tree) — its
  mine positions, the lesson number and the lesson mine.
- **The board is found by a dev script** (for example
  `dev/find-learn-3d.mjs`, in the style of `dev/measure-noguess-3d.mjs`). It
  runs `generate` for the 4 × 4 × 3 box with First box 1's count,
  `firstClick` the start cell, `noGuess: true`, over seeds from 1 upwards,
  and takes the first seed whose board, after the first reveal on the start
  cell, meets all of these:
  - the first reveal does not win the board;
  - at least one cube is hidden by auto-hide;
  - a revealed number P has exactly one closed neighbour, the lesson mine M,
    and P's value is 1, so M must be a mine;
  - a revealed 1, the lesson number L (not P), has M and at least one other
    closed cube among its neighbours, all of the others safe, so a chord on
    L after M is flagged opens cubes; among candidates, L is the one nearest
    the start cell.

  The script prints the seed, mine positions, L and M, and the module's head
  comment names them. If no seed up to 10,000 qualifies at First box 1's
  count, the script tries the next count up to 6, and the count it takes is
  recorded in the module's comment and named under Follow-ups.
- **The entry** (I-01): `#board-choice` shows a "Learn 3D" item first, above
  the First box group, with a detail line saying it is a guided
  4 × 4 × 3 box with no timer and no records. `bindBoardChoice` reports it
  through its own callback (for example `onLearn`). Starting it does not
  save `mode3d.lastChoice`, does not move the board choice's "Last played"
  mark and is never the board Play again, the menu's "Last played" line or
  task 133's quick play names. It can be started any number of times.
- **The ready-card hint** (I-01; task 119's first-use state): while the
  player has no finished 3D game and has not completed Learn 3D, the 3D
  ready card of every other 3D board carries one line, "New to 3D? Learn 3D
  walks you through a small box.", with a "Learn 3D" action that starts the
  guided board. The card's own click still starts the chosen board. Once
  either condition holds, the line is gone.
- **Start** (I-01): the guided board is played through the 3D mode as a
  fixed board (the session's `minePositions` path), so the scene, camera,
  controls, pause and end delay are the 3D game's own, and no generation
  request is made. Its start spacing and spawn pose are those every 3D
  start uses for its size and mine count: task 152's start-spacing helper
  (1.5, First box 1's) and task 125's pose where it is in the tree. The
  overlay's board readout and the pause card's board line read "Learn 3D".
- **Forced, marked start cell** (I-01: a fixed start cell): the game opens
  closed with the start cell marked by task 138's 3D tint (the renderer
  tints that cube's instance; built here the same way when task 138 is not
  in the tree). Before the first reveal, a reveal anywhere else changes
  nothing, and the hint "Start on the marked cube" shows with the mark
  pulsing: task 151's forced-start behaviour, reused when it is in the
  tree. Flags before the first reveal behave as in any 3D game. Until the
  first reveal, the prompt line reads "Click the marked cube to start".
- **Four prompts in sequence** (I-01), each shown in task 119's hint strip
  component at the bottom of the play area, with no close button, drawing
  key and button names from the bindings source so a controller player
  sees the controller's inputs:
  1. "Hold Shift to see what this number counts" — done when Shift is held
     while the crosshair is on L;
  2. "Hold Ctrl to see the cubes you cleared" — done when Ctrl is held;
  3. "Flag the one cube that must be a mine" — done when M is flagged; a
     flag on any other cube does not complete it;
  4. "Press left and right together on the number to chord" — done when a
     chord on L opens at least one cube.

  The prompts start after the first reveal and show in this order. Each is
  done by its action at any time after the first reveal; a prompt already
  done when its turn comes is skipped. While prompt 1 or 4 shows, L carries
  the start-cell tint; while prompt 3 shows, M does. After the fourth, the
  line reads "Clear the rest of the box". Task 141's neighbourhood
  wireframe shows on L as task 141 defines it, where it is in the tree;
  otherwise the Shift neighbour view is as it is today.
- **Nothing else teaches at the same time**: during the guided game the 3D
  first-use hint strip, the "How 3D works" block and task 119's one-time
  auto-hide toast do not show, and the guided game counts toward none of
  task 119's three-game windows. When prompt 2 is done, the auto-hide toast
  is marked shown.
- **No timer** (I-01): the overlay shows no timer during the guided game,
  and the pause card and end card show no time.
- **No records** (I-01; `.claude/context/records.md`): the guided game has
  no summary (the fixed board's null), so it writes nothing to `records`,
  `records.history` or `records.inProgress`, at a win, a loss, a restart, a
  leave or `pagehide`. No best, counter, streak, history entry or
  game-in-progress marker changes.
- **No replay** (`.claude/context/replay.md`): the guided game is not
  recorded and nothing reaches the replay library; no Watch replay is
  offered.
- **The end** (I-01): the end effect and `END_DELAY_MS` run as in any 3D
  game, with input ignored during the delay. Then, in place of the results
  screen, a Learn 3D end card shows over the stopped scene, built from the
  component kit:
  - on a win: "You've got the basics of 3D." with "Play First box 1", which
    starts First box 1 as an ordinary board pick (the presets' no-guess
    switch as the remembered choice holds it, saved as the last choice), and
    "Back to board choice";
  - on a loss: "That cube was a mine." with "Try again", which restarts the
    guided board, and "Back to board choice".

  Back on the end card goes to the board choice. Pointer lock is released
  for the card as for the results screen.
- **Restart and Back to menu** on a guided game proceed at once with no
  confirmation, since nothing counts as a loss. Restart starts the guided
  board again from the closed box and the first prompt. The confirmations
  of every recorded game are unchanged.
- **Completion** (I-01; task 119): a guided win marks the 3D rules block as
  seen in the first-use document: the "How 3D works" block and the
  ready-card Learn 3D line stop showing, as after a finished 3D game. A
  loss, a restart or a leave marks nothing. Storage failure never blocks
  the guided game, as task 119's rule for the first-use state says.
- **What not to break** (`docs/UX_REVIEW.md` § Decisions taken):
  release-to-act with drag-to-cancel; the reference input conventions; 3BV,
  click and efficiency accounting; no-guess boards as separate records; the
  confirmations that say "It will count as a loss" on recorded games; the
  last-choice memory; the honest empty states and storage notices. The
  default and fallback 3D choice stays Cube Beginner.
- **Tests first** (full TDD):
  - the guided board constant: `generate` with its seed, start cell, count
    and `noGuess: true` gives its mine positions while `GENERATOR_VERSION`
    equals the recorded version; on its mines, through `create3DGame`, the
    first reveal on the start cell meets every board condition above, and
    the solver clears it from the start cell;
  - the prompt sequence: order, each completion condition, a wrong flag and
    a chord before the flag not advancing, a prompt done early being
    skipped, the closing line, the controller's input names;
  - the board choice: the entry and its callback, `mode3d.lastChoice` and
    the "Last played" mark untouched;
  - the forced start: a reveal off the start cell before the first reveal
    changes nothing and shows the hint;
  - the adapter: a guided game reports no summary and no replay at a win, a
    loss, a restart and a leave; the records documents and the replay
    library are unchanged;
  - the first-use state: a guided win marks the rules block seen, a loss
    does not, the guided game counts toward no window, prompt 2 marks the
    toast shown;
  - the pause controller: no confirmation on a guided game;
  - a Playwright run with SwiftShader through a `__ms` hook: open the 3D
    board choice, start Learn 3D, see the marked cube, reveal it, walk the
    four prompts, clear the box, see the win end card, and check that the
    records documents are unchanged.

  The existing suite stays green.
- **The owned documents state the agreed design change** in every passage
  that stated the old one:
  - `.claude/domain/product-design.md`: the 3D on-ramp starts with the
    Learn 3D guided board on the 3D board choice, then the First box
    presets, ahead of the campaign;
  - `.claude/domain/features/3d-play-flow.md`: the 3D board choice offers
    Learn 3D; the guided board is a fixed board from a fixed seed with a
    forced, marked start cell, shows no timer, has no summary, reports no
    finished or abandoned game to records or replays, and ends on its own
    end card, not the results screen;
  - `.claude/domain/features/game-shell.md`: Restart and Back to menu on the
    guided game proceed at once, and its end goes to the Learn 3D end card,
    not the results screen.

  They also settle the points listed under Decisions. Nothing else in those
  documents changes.
- The context files describing the changed surfaces state the new state,
  per `CLAUDE.md` § Editing Discipline: `mode3d.md` (the guided board, the
  entry, the forced start), `app-shell.md` (the ready-card line, the end
  card, the confirmations, the `__ms` hook), `testing.md` (new test files
  and the dev script). README.md's "3D: how to play" names Learn 3D.

## Decisions
- **Design change agreed (user decision, 2026-10-12):** settled by prior
  instruction: I-01 of `docs/UX_REVIEW.md` under decision 16 ("3D tutorial
  before the campaign? Yes — I-01, I-02 proceed"), row W-21; the
  no-confirmation and end-card points follow from I-01's "No records, no
  timer".
  - `product-design.md` § User experience and key flows, "The 3D on-ramp"
    ("A player curious about 3D starts the 3D campaign rather than free
    play"), and § High-level features, 3D mode ("once the campaign has
    taught the player to read numbers in depth"): the on-ramp starts with
    the Learn 3D guided board, then the First box presets, before the
    campaign.
  - `3d-play-flow.md` § Scope and non-goals ("Board choice: … presets …
    plus Custom and the Random fill, and the no-guess switch"): the board
    choice also offers Learn 3D.
  - `3d-play-flow.md` § Interfaces and contracts, "First-click guarantee"
    (the board is generated around the first click): the guided board is
    fixed in advance and its first reveal is forced onto the marked start
    cell.
  - `3d-play-flow.md` § Interfaces and contracts, "Timer", "Mode contract"
    and "Summary" (the timer shows in the overlay; every finished or
    abandoned game reports a summary and replay): the guided game shows no
    timer, has no summary and no replay, and ends on its own end card.
  - `game-shell.md` § Interfaces and contracts, "Restart" and "Back to
    menu" (a started, unfinished game asks for confirmation, saying it will
    count as a loss): on the guided game they proceed at once.
  - `game-shell.md` § Interfaces and contracts, "Game finished" (the shell
    hands the summary to `results-screen`): the guided game has no summary
    and shows the Learn 3D end card.

  Settled here, without conflict: the guided board never becomes the last
  3D board choice (`3d-play-flow.md` § Data and state and `game-shell.md`
  § Data and state, "Last mode played", which do not cover a board outside
  the choice); the guided board is not a campaign level, so the campaign
  non-goal in `3d-play-flow.md` stays. These documents are normally
  `/architect`'s and `/product-design`'s; this task updates them for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and
  name it under *Follow-ups* as a precise follow-up.
- **4 × 4 × 3, not the review's 4 × 4 × 4 · 3**: three layers is the fewest
  that teaches depth on a no-guess box (a side of 2 can never be no-guess,
  `docs/UX_REVIEW.md` § Approved scope and work plan, last paragraph, and
  task 152's Decisions), and it is First box 1's size, so the lesson and
  the first preset are the same box.
- **Its own fixed board, at First box 1's size and mine count**, not First
  box 1 itself: a preset is generated afresh each game, while the lesson
  needs a board where L, M and the chord exist. Sharing the size and count
  gives it First box 1's start spacing and spawn through task 152's helper
  with no new value, and makes "Play First box 1" the same box at the same
  density.
- **The mine positions are committed, derived from a recorded seed**: the
  lesson then never changes with a later `GENERATOR_VERSION`, and the fixed
  board path makes no worker request. The seed, start cell and generator
  version stay recorded, as I-01's "fixed seed and start cell" asks.
- **No replay**: a fixed board already has no summary to seal a replay with
  (`.claude/context/mode3d.md`, Recording), and a lesson has nothing to
  watch or compare.
- **Completion is a win**: the rules block is "seen" once the player has
  cleared the box; a loss offers Try again.
- **The fixed board's pause-card end is replaced** by the Learn 3D end card
  for the guided board only; the debug hook's fixed board keeps its
  pause-card end.
- **The ready-card line, not the default choice, steers newcomers**: task
  152 keeps Cube Beginner as the default; this entry and the ready-card line
  are the only steering to the First box presets.
- **Out of scope**: the campaign; the First box presets, the preset re-tune
  and the start spacing (W-17, task 152); the neighbourhood wireframe and
  readability work (W-18, task 141); the help component, hint strips, toasts
  and the first-use document themselves (W-01, task 119); the spawn pose
  (task 125); the marked start cell's definition (task 138); daily boards
  and challenge links (W-33, task 151); touch controls (W-23, task 147);
  accessibility settings (decision 17, not now). The overviews of
  `personal-records.md`, `replay-recording.md` and
  `3d-results-records-screens.md` describe recorded games and stay as they
  are.
