# Task 96 — Leaderboard outbox, verifier gate and submission state

Target: claude

## Goal
Add the submission path of feature `steam-leaderboards`: `submit(summary,
replay)` called from the end-of-game hand-off, the verifier gate that
re-runs the replay before anything is queued, the outbox keeping at most one
pending submission per leaderboard across sessions, and the submission
state with change notification that screens read.

## Acceptance criteria
- `submit(summary, replay)` returns at once with eligible or not; verifying
  and queueing run in the background; a second call for the same summary id
  is a no-op.
- The verifier gate uses `replay-playback`'s verifier: the submission goes
  ahead only when the replay reproduces, its outcome is a win, its board
  matches the leaderboard and its elapsed time equals the summary's;
  otherwise the state is rejected by verification.
- The outbox document is registered with `platform-storage` under its own
  name and version; per leaderboard it holds the pending summary id, score,
  details and replay reference; a better pending game replaces a worse one.
  Pending replays live in a blob store opened under the outbox's own name,
  deleted when their entry is submitted or dropped.
- The outbox flushes through a submitter interface at start-up and on each
  logged-on event; the Steam submitter is task 97's, and with none present
  entries wait.
- Submission state per summary id — not eligible, pending, submitted (with
  global rank before and after), rejected by verification — with change
  notification.
- The end-of-game hand-off calls `submit` for a finished game after the
  summary is recorded and the replay added to the library; nothing here
  interrupts play or the results flow.
- Node tests use in-memory storage, an in-memory blob store, recorded
  fixture replays and a fake submitter: tampered replays, replacement,
  restart persistence and duplicate submits.
