# Task 157 — Theme registry, kit catalogue and the Joyful tiles theme folder

Target: claude

## Goal
Lay the data foundation of feature `theme-system`: one registry module that
is the only place a theme is registered, one machine-readable declaration of
the component kit (components, parts, states, decoration slots) that the
conformance tests, the gallery and the theme skill read, and the *Joyful
tiles* theme folder with its registry entry, its self-hosted Rubik and
JetBrains Mono font files and their licence. Nothing renders differently yet:
the stylesheet, the applier and the settings list build on this in the tasks
that follow.

## Acceptance criteria
- **Registry module** `js/themes/registry.js` (plain ES module, DOM-free)
  exports the entries in catalogue order, the default id `joyful-tiles`, and a
  lookup by id that returns the default entry for an unknown or absent id
  rather than failing. Each entry carries: `id` (stable kebab-case), display
  name, stylesheet path, board module path, font files with their licence
  file, catalogue order, and a demo field (whether the demo offers the
  theme) that nothing reads yet. Entries are frozen.
- **Joyful tiles entry** — id `joyful-tiles`, name "Joyful tiles", stylesheet
  `themes/joyful-tiles/theme.css`, board module
  `themes/joyful-tiles/board.js`, demo field `true`.
- **Theme folder** `themes/joyful-tiles/` holds `fonts/` with the Rubik and
  JetBrains Mono `woff2` files for only the weights the *Joyful tiles*
  artboards use (J-Tokens names them: Rubik 500–900 and JetBrains Mono), and
  the SIL Open Font License text for both beside them.
  The files are fetched once at authoring time from each font's published
  package (e.g. the `@fontsource` npm packages); no file in the folder
  references a remote URL.
- **Board module placeholder** `themes/joyful-tiles/board.js` exists as a
  valid ES module exporting an empty, frozen board description with a header
  comment saying its shape and values are `themed-board-art-and-motion`'s.
  No renderer reads it yet.
- **Kit catalogue** `js/ui/kit-catalogue.js` (DOM-free) declares every
  component currently documented in the head comment of `css/components.css`:
  its catalogued name, its CSS class, its named parts (each with its
  selector, and an `optional` flag where a theme may hide it), the states of
  each interactive part (default, hover, pressed, focused, disabled, and
  selected where it applies), and the decoration slots (none exist yet; the
  structure supports them). Each part and state maps to the selector a theme
  stylesheet styles, so a test can check a rule exists for it.
- **Tests** `tests/theme-registry.test.mjs`: entry shape and freezing,
  default lookup for unknown/absent ids, catalogue order, ids unique and
  kebab-case; the kit catalogue lists every `ui-*` component class used in
  `css/components.css` and every catalogued class exists there; every font
  file and licence the registry names exists on disk.
- The new modules have no runtime consumer yet and change no screen;
  the full suite stays green.

## Decisions
- **Theme files live at `themes/<id>/`** (repo root, served as static files
  beside `js/` and `css/`), the registry at `js/themes/registry.js` and the
  catalogue at `js/ui/kit-catalogue.js`. The feature document fixes the
  pieces, not their paths.
- **Board module placeholder.** The registry entry names a board module from
  the start, so the applier (task 159) loads and hands on a real file;
  `themed-board-art-and-motion` writes its shape and values. This keeps the
  theme-system tasks free of a dependency on that feature.
- **Settled design detail** (`.claude/domain/features/theme-system.md`
  § Architecture, *Theme registry*, *Kit catalogue*, *Theme fonts*): the
  paths above and the board module placeholder. The feature document is not
  edited here; task 162 records what holds at ship time.
