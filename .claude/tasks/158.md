# Task 158 — Base stylesheet and the Joyful tiles theme stylesheet; retire light and dark

Target: claude

## Goal
Split the game's styling, for feature `theme-system`, into a base stylesheet
that carries structure only and a theme stylesheet that carries every visual
value, and write *Joyful tiles*' stylesheet as the game's one look. Today's
light and dark looks are removed, not migrated: their token values, the dark
overrides, the gallery's light/dark switch and the tests that pinned them go.
After this task every screen paints in *Joyful tiles*, with its self-hosted
fonts, and no stylesheet outside the theme's own carries a colour, font,
border, radius, shadow or motion value.

## Acceptance criteria
- **Base stylesheet.** `css/components.css` and `css/style.css` keep only
  structure: layout, display, the sizes the layout depends on, z-layers,
  the hidden default of every decoration slot, and the rule that every
  focusable part shows a focused state, with no separate focus ring
  (`theme-system.md` § Architecture, *Base stylesheet*). No colour, font family, border style or colour, radius, shadow,
  transition or animation value of any theme remains in them. The
  `@media (prefers-reduced-motion: reduce)` rule in `css/style.css`, which
  stops every animation and transition, stays in the base unchanged, and no
  theme stylesheet overrides it.
  `css/tokens.css`
  keeps only structural tokens (spacing, z-layers, sizes) or is removed with
  those moved into the base; nothing in it is per-theme.
- **Joyful tiles stylesheet** `themes/joyful-tiles/theme.css`: every rule is
  scoped to `:root[data-theme="joyful-tiles"]`. It declares the theme's
  tokens (every colour, font, radius, shadow and motion token the base and
  the screens read, including the `--color-scene-*` sky stops the scene
  palette reads today), styles every part and state in
  `js/ui/kit-catalogue.js` with a visible focus style on every interactive
  part — on buttons, menu entries and board options the selected state of
  the kit's state model (`screen-components.md` § Scope and non-goals),
  drawn on focus only: raised by default, level with the surface when
  selected (no outline, no halo), sunk below it with an inset shadow when
  pressed, flat when disabled, and no rule styling their hover; switches,
  fields, segmented choices and tabs keep their own states — declares Rubik and JetBrains Mono with `@font-face` from the files in
  `themes/joyful-tiles/fonts/` only, and carries its DOM component animation
  as plain CSS.
- **One selected control** (`theme-system.md` § Architecture, *One
  selected control*). On buttons, menu entries and board options, moving
  the mouse over an enabled one focuses it (without scrolling the page), so
  the selected control is always the focused one and at most one control
  shows the selected state; keys and controller buttons move focus as
  today; after a key or controller press, a control under a resting pointer
  is not selected, and the next mouse move over a control focuses it again.
  One delegated listener in `js/ui/components.js` does this for every such
  control, present and future; no screen wires it itself.
- **Values from the canvas.** The theme's tokens are J-Tokens' token block,
  every one — the green, orange and ink-edge tokens and the per-entry
  accents among them (Classic 2D blue, Hexagon teal, Triangle green, Surface
  orange, 3D coral, Daily violet; Records, Settings and a desktop Quit the
  neutral raised surface) — with its measured contrast pairs; every existing
  kit component's parts and states are styled as J-Components draws them.
  J-Tokens and J-Components are the source of the theme's tokens and kit
  CSS; nothing is styled by analogy.
- **Interim loading.** `index.html` loads the base stylesheets and
  `themes/joyful-tiles/theme.css`, and `js/theme.js` sets
  `data-theme="joyful-tiles"` on the root before first paint whatever is
  stored. Task 159 replaces this with the registry-driven applier.
- **Light and dark removed.** No `:root[data-theme="dark"]` or
  `data-theme="light"` rule remains anywhere; the gallery's light/dark
  segmented switch and its `?theme=dark` handling are removed; the theme
  setting's stored value no longer changes the look (the setting itself is
  task 160's).
- **Tests.** `tests/tokens.test.mjs`, `tests/theme.test.mjs` and the
  contrast checks in `tests/components.test.mjs` stop pinning the light and
  dark values and instead check *Joyful tiles*: body text on each surface
  token at least 4.5:1, large text and essential glyphs at least 3:1; a test
  parses the base stylesheets and fails on any colour, font family, radius,
  shadow, transition or animation value in them outside that reduced-motion
  rule; a test fails on any rule of `theme.css` not scoped to the theme id,
  and on any `prefers-reduced-motion` rule or `!important` animation or
  transition in it. A browser test checks, on two buttons, that moving the
  mouse over one focuses it and gives it the selected look, that pressing
  Tab or an arrow then moves the selected look to the other while the
  pointer still rests on the first — the first no longer looking selected —
  that moving the mouse again re-selects the control under it, that pressed
  differs from selected, and that no outline is drawn. Existing behaviour
  tests pass.
- **Screens unchanged in arrangement.** Every element id, route, default
  focus target and controller navigation target is as before; this task
  restyles, it does not move anything (that is `shared-screen-layout`).
- The menu screens' backdrop and the context-lost card read *Joyful tiles*
  tokens, so no hard-coded light tint survives in `css/style.css`.

## Decisions
- **Interim static link and fixed root attribute** until task 159 lands: the
  task stays shippable on its own without the applier.
- **Sky tokens stay in the theme stylesheet** (`--color-scene-*`), read by
  `js/shell/scene-palette.js` as today, until `themed-board-art-and-motion`
  moves the sky into the board module. The 2D tile skin and the 3D atlas keep
  their current palettes until that feature lands.
- **No component styled by analogy** — reversed: J-Components now draws
  every kit component in every state, so the theme follows it throughout.
- **Selected state, not a focus ring** (owner decision, DESIGN-CHANGES
  §3.1): on buttons, menu entries and board options the flush selected
  state is the focus cue; no ring, halo or outline is added.
- **One selected control** (owner's answer to the focus-visibility
  question, DESIGN-CHANGES §8, reversing the accepted consequence that two
  controls could look selected at once): only one control is selected,
  depending on the input method in use — the mouse's hover moves focus, and
  after a key or controller press hover counts for nothing until the mouse
  moves again. Built here, once, for the kit; task 163's components follow
  it.
- **Task 156 is superseded** by this task: it themes the dark look this task
  removes. Its fixes (no light haze behind menu screens, a readable
  context-lost card) hold here through *Joyful tiles*' tokens.
- **The shipped reduced-motion rule stays** (2026-10-13): the reduced-motion
  feature is `m7-after-launch`, and until then the shipped game is kept as it
  is (`theme-system.md` § Architecture, *Base stylesheet*), reversing the
  reading that removed the base `prefers-reduced-motion` rule. It is exempt
  from the no-animation-values test and no theme may override it.
- **Settled design detail** (`.claude/domain/features/theme-system.md`
  § Architecture, *Base stylesheet*, *Theme stylesheet*): the interim loading
  and the sky tokens' interim home. The feature document is not edited here;
  task 162 records what holds at ship time.
