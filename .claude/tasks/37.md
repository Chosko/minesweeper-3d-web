# Task 37 — Classic 2D input fidelity tests

Target: claude+human

## Goal
Pin the reference behaviours feature `classic-2d-square-play` owns — which
inputs chord, press feedback, release-off-cell cancelling and the largest
custom board — by fidelity tests written from recorded observations of
Minesweeper Online with its default options.

## Acceptance criteria
- `tests/fidelity/minesweeper-online.md` gains one dated observation each
  for: which mouse inputs chord (both buttons, middle button, left on a
  satisfied number); what shows pressed while a button is held, alone and
  for a chord; what releasing off the pressed cell does; the largest custom
  width, height and mine count the site accepts.
- Node tests on the pointer state machine and the board setup cite each
  observation and assert it; a Playwright check covers press feedback and
  release-off-cell on the real board.
- The reference profile's input rules and `CUSTOM_LIMITS` match the
  observations; any mismatch is corrected in rules version 1 (task 5's
  decision) and the full suite passes.

## Manual interventions

⚠ REQUIRES MANUAL INTERVENTION — pause implementation at these points and
walk the user through them on the live Minesweeper Online site; wait for
their confirmation and verify the outcome before continuing:

1. Before any test is written: the user opens Minesweeper Online with its
   default options and, for each of the four behaviours in the acceptance
   criteria, performs the described input (or tries the largest custom
   board) and reports what the site did. Claude writes each report, dated,
   into `tests/fidelity/minesweeper-online.md`. Verify the file holds one
   entry per behaviour, each stating a single observed behaviour.
2. After the tests run: if any test fails because the game differs from an
   observation, show the user the behaviour and the observation before
   correcting it. Verify the corrected build passes the full suite.
