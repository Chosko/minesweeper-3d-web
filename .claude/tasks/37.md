# Task 37 — Classic 2D input fidelity tests

Target: claude

## Goal
Pin the reference behaviours feature `classic-2d-square-play` owns — which
inputs chord, when a flag toggles, press feedback, release-off-cell
cancelling and the largest custom board — by fidelity tests that read the
recorded behaviour of Minesweeper Online with its default options from
`tests/fidelity/minesweeper-online.md`.

## Acceptance criteria
- Node tests on the pointer state machine and the board setup cite each of
  the file's Classic 2D entries by heading and assert it: which mouse inputs
  chord (left or middle on a number, left + right through the left release,
  nothing on a right press on a number); flag timing (on the right press,
  also while left is held on a closed cell); pressed feedback alone and for
  a chord; releasing off the pressed cell; and the largest custom board
  (width and height 1 to 100, larger refused; the mine cap at the file's
  measured boards).
- The custom-board test asserts the one recorded deliberate difference: on a
  board of up to 36 cells the mine cap is the cell count minus one, not the
  site's every cell (`classic-2d-square-play.md` § Architecture, Board
  setup).
- A Playwright check covers press feedback and release-off-cell on the real
  board.
- The tests use `tests/fidelity/minesweeper-online.md` as it stands and add
  nothing to it, unless a test finds a contradiction in it.
- The reference profile's input rules and `CUSTOM_LIMITS` match the file;
  any mismatch is corrected in the game against the file, in rules version 1
  (task 5's decision), and the full suite passes.

## Decisions
- The file's entries were settled from the site's client code, help pages
  and live play, so no step of this task needs a person. The file is the
  oracle: a fidelity-test failure is resolved by correcting the game, never
  by re-observing the site.
