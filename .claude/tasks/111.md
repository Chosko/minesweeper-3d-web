# Task 111 — Action catalogue, bindings resolver and the bindings setting

Target: claude

## Goal
Build the DOM-free core of feature `input-rebinding`: two action
catalogues — one for the flat modes, shared by Classic 2D, Hexagon and
Triangle, and one for 3D — with each action's default keyboard, mouse and
controller inputs, the player's overrides stored as one setting in the
settings document, and the resolver that joins the two into the current
bindings and enforces the clash, reserved-input and last-binding rules. It
replaces the fixed bindings source every help surface reads — the Settings
page's bindings list, the shared layout's key hints, the in-game controls
reminder, the 3D HUD key strip and first-use hints, and the in-game help.

## Acceptance criteria
- The 3D catalogue holds the six move directions, the three held view modes
  (Shift, Space, Ctrl by default), reveal and flag; the flat modes'
  catalogue holds reveal, flag, chord and the four cursor moves. Each action declares
  its label, whether it fires on press, on release or while held, and up to
  two default inputs per device. The defaults equal today's bindings (README
  Controls tables and task 35's Classic 2D mapping).
- Keys are identified by `KeyboardEvent.code`, mouse buttons by button
  number, controller buttons by standard-mapping index.
- The overrides are one schema entry in the settings document, keyed by
  catalogue, device and action, holding only the actions the player changed; it
  loads, saves and notifies through the settings store like any setting.
- `actionFor(mode, device, input)` and `inputsFor(mode, device, action)`
  answer from the current bindings of the mode's catalogue and follow
  override changes without a restart; `classic-2d`, `hexagon` and
  `triangle` give the same answers, so a rebinding made for one applies to
  all three.
- `bind` refuses reserved inputs; an input already bound to another action
  of the same catalogue and device is swapped (that action takes the
  replaced input) and the swap is reported to the caller. `clear` refuses an action's
  last input on keyboard and mouse together, or on the controller.
  `reset(mode, device)` restores the defaults of that mode's catalogue.
- Reserved inputs are those of the feature document, and `bind` refuses
  each of them in every catalogue: Esc, the controller's Start and home buttons,
  the restart key F2, the results screen's play-again key R, Tab, Meta and
  the browser's function keys; plus each mode's non-catalogue inputs
  (the flat modes: controller B and the shell's Back; 3D: help, sound,
  fullscreen keys and buttons, the d-pad spacing buttons, and every other
  input its play gives to something outside the catalogue). Controller Y
  stays bindable in both catalogues — only its chord with the held Start is
  reserved, and that chord is kept away from the bindings by the input
  layers (task 112), not by the resolver.
- Invalid saved overrides (unknown action or input, clash, reserved input,
  F2 and R included) are discarded for that catalogue and device, which
  fall back to defaults; the rest are kept.
- Every help surface reads the resolver's current bindings and shows an
  override change from its next update: the Settings page's read-only
  bindings list, the key hint component (task 163) wherever a screen shows
  one, the Classic 2D controls reminder (task 176), the 3D overlay's HUD key
  strip and first-use hints (task 177), and the in-game help. No help
  surface keeps a fixed copy of a binding.
- Node tests cover defaults, resolve both ways (Hexagon and Triangle
  resolving through the flat modes' catalogue as Classic 2D does), bind with swap, reserved
  refusal (F2 and R in each mode among them, Y accepted), last-binding
  refusal, reset, invalid-override fallback and change notification on the
  in-memory storage backend, and a key hint and the controls reminder
  showing a rebound input after an override change.

## Decisions
- Classic 2D, Hexagon and Triangle share one catalogue and one set of
  overrides (`input-rebinding.md` § Scope and non-goals): the resolver maps
  each flat mode id to the flat catalogue rather than keeping a set per mode.
- Settled here, against `.claude/domain/features/input-rebinding.md`
  § Interfaces and contracts → Reserved inputs: the resolver keys on mode
  and device, not screen, so R — reserved "on the results screen" — is
  refused in both modes' catalogues; in 3D it is already taken by the
  camera return (`Home` / `R`), and in Classic 2D refusing it keeps the
  play-again key from ever carrying a play action. The Start + Y chord is
  not representable as one input in the resolver, which only refuses Start
  itself; task 112 enforces the chord.
- **Help surfaces of the shared layout (2026-10-13):** the key hints and the
  controls reminder that tasks 163, 176 and 177 build read the bindings
  source this task replaces (`input-rebinding.md` § Architecture, *Help and
  glyphs*), so this task waits on them and switches each to the resolver.
