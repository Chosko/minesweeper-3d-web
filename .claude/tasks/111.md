# Task 111 — Action catalogue, bindings resolver and the bindings setting

Target: claude

## Goal
Build the DOM-free core of feature `input-rebinding`: one action catalogue
per mode (Classic 2D, 3D) with each action's default keyboard, mouse and
controller inputs, the player's overrides stored as one setting in the
settings document, and the resolver that joins the two into the current
bindings and enforces the clash, reserved-input and last-binding rules. It
replaces the fixed bindings source the read-only bindings list and the
in-game help read.

## Acceptance criteria
- The 3D catalogue holds the six move directions, the three held view modes
  (Shift, Space, Ctrl by default), reveal and flag; the Classic 2D catalogue
  holds reveal, flag, chord and the four cursor moves. Each action declares
  its label, whether it fires on press, on release or while held, and up to
  two default inputs per device. The defaults equal today's bindings (README
  Controls tables and task 35's Classic 2D mapping).
- Keys are identified by `KeyboardEvent.code`, mouse buttons by button
  number, controller buttons by standard-mapping index.
- The overrides are one schema entry in the settings document, keyed by
  mode, device and action, holding only the actions the player changed; it
  loads, saves and notifies through the settings store like any setting.
- `actionFor(mode, device, input)` and `inputsFor(mode, device, action)`
  answer from the current bindings and follow override changes without a
  restart.
- `bind` refuses reserved inputs; an input already bound to another action
  of the same mode and device is swapped (that action takes the replaced
  input) and the swap is reported to the caller. `clear` refuses an action's
  last input on keyboard and mouse together, or on the controller.
  `reset(mode, device)` restores the defaults.
- Reserved inputs are those of the feature document: Esc, Start, home,
  Tab, Meta and the browser's function keys in every mode, plus each mode's
  non-catalogue inputs (Classic 2D: controller B; 3D: help, sound,
  fullscreen keys and buttons and the d-pad spacing buttons).
- Invalid saved overrides (unknown action or input, clash, reserved input)
  are discarded for that mode and device, which fall back to defaults; the
  rest are kept.
- The read-only bindings list and the in-game help read the resolver's
  current bindings.
- Node tests cover defaults, resolve both ways, bind with swap, reserved
  refusal, last-binding refusal, reset, invalid-override fallback and change
  notification on the in-memory storage backend.
