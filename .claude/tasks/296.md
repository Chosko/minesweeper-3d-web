# Task 296 — Machine settings document and browser-only carry-over of the loose keys

Target: claude

## Goal
Feature `settings` splits the saved settings into two versioned documents:
a machine settings document holding look sensitivity and render resolution,
and the settings document holding everything else. The store loads and
saves both and stays the one source of truth; with no machine settings
document it takes those two values from a settings document saved with
them, once. The carry-over of the loose `ms3d.*` keys, and Reset all data's
removal of them, apply to the browser build only, so the Steam build reads
and removes nothing from browser storage.

## Acceptance criteria
- The store registers a second document through `platform-storage` for look
  sensitivity and render resolution; `set` of either saves that document,
  `set` of any other setting saves the settings document, and the settings
  document no longer holds the two machine values.
- With no machine settings document, the store takes sensitivity and render
  resolution from the loaded settings document when it holds valid ones,
  saves the machine settings document, and from then on reads only it; a
  machine settings document that is present always wins.
- On a first start with no settings document on the browser build, the
  loose keys carry over into the two documents as before (field of view at
  45° when any carried over).
- On the Steam build (`capabilities.desktopHost`) the store reads no loose
  key and Reset all data removes none; Reset still clears every document and
  every replay blob.
- `get`, `set`, `onChange`, validation, the save-failure notice and the
  load-trouble rules behave as before for every setting.
- Node tests cover the split saves, the one-time carry-over from an old
  settings document, a present machine document winning, and the Steam
  build skipping the loose keys in the store and in Reset.

## Decisions
- One task for the split and the browser-only carry-over: both are the
  store's and Reset's wiring, and the Steam storage work
  (`steam-cloud-saves`) builds on the machine settings document existing.
- The Steam build skips the loose keys by the shell handing the store and
  Reset no legacy reader or remover there; the store and Reset stay
  DOM-free. Settled here (`.claude/domain/features/settings.md` § Data and
  state leaves the mechanism open).
- No format step strips the two machine values from a stored settings
  document before the store's carry-over reads them. Settled here, same
  passage.
