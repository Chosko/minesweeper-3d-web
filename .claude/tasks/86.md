# Task 86 — Page platform selection, capability flags, overlay pause and the quit flush

Target: claude

## Goal
Make the game page aware of the host, for feature `steam-desktop-host`: at
start-up the platform layer looks for the bridge and selects the Steam or the
browser implementations, publishes capability flags the rest of the game
reads, keeps the latest Steam state, turns overlay activation into the
shell's existing automatic pause, and answers the host's flush request
before quit.

## Acceptance criteria
- `js/platform/index.js` selects once at start-up: bridge present → Steam
  implementation slots (storage, replay store, leaderboards, achievements)
  that later features fill; absent → the browser implementations and local
  stand-ins. No module outside `js/platform/` tests for Electron or the
  bridge.
- Capability flags — desktop host, Steam present, achievements,
  leaderboards, shared files, cloud — are derived at start-up and updated
  from Steam state events; callers subscribe to changes.
- An overlay-activated event pauses a started, unfinished game through the
  same path a window blur takes in the pause controller.
- A flush-requested event awaits every registered flush hook (pending
  saves) and answers the host; the host waits for that answer bounded by a
  short timeout before shutting down.
- The web build behaves exactly as before: no bridge, browser
  implementations, every capability flag off.
- Node tests cover selection both ways with a fake bridge, flag updates,
  the overlay pause and the flush answer; a desktop run shows the overlay
  signal pausing a game.
