# Task 12 — Generation worker and message protocol

Target: claude

## Goal
Host generation off the main thread, as feature `board-generation` requires:
a Web Worker running `generate`, and a page-side client that sends a request
as a plain message, receives the result or failure, and can cancel a request
when the player leaves or restarts. Every board, not only no-guess ones, goes
through it, so the start-of-game flow is one flow.

## Acceptance criteria
- A module worker wraps `generate`; request and result are plain
  structured-clone messages matching the feature document's shapes.
- A page-side client offers `request(req)` → a promise of the result or
  failure, and `cancel()`; a cancelled request never delivers a result, and
  only one request is in flight per game.
- The worker holds no state between requests.
- Determinism: the worker returns the same mine set as `generate` in Node for
  the same request; a Node test covers the client with a fake worker, and a
  Playwright check confirms a real worker round-trip in Chromium.
- No generation code runs on the main thread in the game.
