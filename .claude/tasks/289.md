# Task 289 — Size steps from the available area

Target: claude

## Goal
For feature `shared-screen-layout`: make every screen's layout read the
**available area** — the browser window on the web, the work area (the
monitor less the taskbar) of the display the window is on at the desktop
host — instead of the window's own size, so the desktop window can be sized
to its frame without the layout feeding back on itself (the main menu
stepping down to the phone layout, a frame never able to grow). On the web
the available area is the browser window, so the web build looks exactly as
before.

## Acceptance criteria
- One root area is sized to the available area: the viewport on the web; on
  the desktop host (the platform layer's desktop-host capability flag) the
  display's work area as `screen.availWidth` / `screen.availHeight` report
  it, updated when it changes (the window moved to another display, the
  taskbar resized).
- The desktop and compact size steps, and every rule sized from the window
  (viewport units, window-width and window-height breakpoints), resolve
  against that root area in the base stylesheet, `css/components.css` and
  the theme stylesheet. A frame's height cap and its body's vertical scroll
  follow the available area.
- The touch step (phone sizes, upright or sideways) keeps today's layout;
  no phone artboard's rendering changes.
- On the desktop host nothing in the layout reads the window's own size: a
  test that lays a screen out against a work area larger than the window
  gets the work area's step and frame size.
- The web build's screens render as before at the canvas's window sizes:
  the existing component and screen browser tests pass unchanged.
- The theme conformance tests pass, and the theme contract
  (`theme-system`) states how a theme stylesheet writes a step-dependent
  value, if the way it does changes.

## Decisions
- **Container queries on a root container.** The step and window-sized
  rules move from `@media` window queries and viewport units to container
  queries and container units on one root container sized to the available
  area; the alternative — a full-work-area transparent window with
  click-through outside the frame — was rejected because the OS window
  would no longer be the frame (dragging, the taskbar, Alt+Tab).
- **The touch step stays on its media queries** on the web: mobile formats
  keep today's behaviour, with no root-area measurement. The desktop host
  never takes the touch step, whatever its window's size.
