# Task 160 — Settings theme list and light/dark carry-over

Target: claude

## Goal
Turn the Settings page's Theme section, for feature `theme-system`, into a
list of the registry's themes — each with its name and a small swatch, the
active one selected, picking one applying it at once — and carry a stored
`light` or `dark` value over to *Joyful tiles*.

## Acceptance criteria
- **Schema.** The `theme` setting is a choice among the registry's ids,
  default `joyful-tiles`. A stored id the registry does not know is kept as
  stored (never overwritten) while the default theme is applied, until the
  player picks.
- **Carry-over.** The settings document's format step (its version raised
  by one, through `platform-storage`'s versioning) maps a stored `light` or
  `dark` to `joyful-tiles`; a version-1 document loads with that mapping and
  everything else intact.
- **Theme list.** The Settings page's Theme section shows the registry's
  themes in catalogue order, each a selectable row with its display name and
  a swatch drawn from that theme's tokens, the active one selected and named
  to assistive technology; keyboard and controller reach every row. Picking a
  row calls the applier's `setTheme` and the setting is saved once the switch
  resolves; a failed switch leaves the selection on the current theme. The
  list reads the registry, so a theme added later appears with no change to
  the page.
- **Tests.** `tests/settings-store.test.mjs` (the carry-over, the unknown id
  kept), `tests/settings-page.test.mjs` (the list's rows from the registry,
  selection, keyboard and controller reach, a pick applying the theme) and
  `tests/settings-appliers.test.mjs` (the theme setting applied through the
  applier).
- Reset all data still returns every setting to its default.

## Decisions
- **The swatch is drawn from the theme's own tokens**, read from its
  stylesheet without applying it (a scoped preview element carrying the
  theme's id is one way); a theme not yet loaded shows its swatch once its
  stylesheet is fetched. The implementer picks the mechanism.
- **Settled design detail** (`.claude/domain/features/theme-system.md`
  § Data and state, *The theme preference*): the format step's version
  raise. The feature document is not edited here; task 162 records what
  holds at ship time.
- **No reduced-motion setting** (2026-10-13): the setting, its first value
  from the operating system's preference, is `m7-after-launch` scope
  (`theme-system.md` § Scope and non-goals); until then the base
  stylesheet's shipped `prefers-reduced-motion` rule, which task 158 keeps,
  is the one reduced-motion behaviour. This task adds no settings field,
  root marker, accessibility section or preference read.
